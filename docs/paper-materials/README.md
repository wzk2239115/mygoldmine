## 建议的叙述顺序

先介绍系统如何把候选发现转化为可核验结果，再介绍这些结果如何反馈到下一轮探索。Workflow 提供跨阶段协作和证据基础，RSI 在此基础上改变后续任务选择与分析方法。

论文可以围绕三个方向组织方法描述：

1. 将代码读取观测与任务级审计意图关联，支持有目的的重复检查。
2. 结合过程反馈与经过验证审核的成果，引导探索优先级和投入。
3. 通过有版本记录的项目限定技能试用，在自然审计任务中观察方法收益。

这些是贡献组织方向，原创性仍需结合相关工作论证，效果仍需实验支持。

## 写作边界

本文依据截至 2026-11-07 已实现的机制整理。反馈引导探索与技能试用的主要实现快照为 [98ee899](https://github.com/wzk2239115/mygoldmine/commit/98ee899)。Workflow 的交付、恢复与验证机制还在持续完善，复现实验应额外固定完整代码版本。

目前可以描述机制及其运行方式，但不能据此声称：

- 系统已经证明持续提高漏洞发现能力；
- 读取覆盖等同于全仓库安全审计覆盖；
- 技能试用产生的报告具有已确认的因果归属；
- 所有内部验证报告均已获得 CVE 编号；
- 项目限定试用等同于通用技能稳定发布。

RSI 在本文中指技能和探索策略层面的迭代，不涉及模型权重训练。文件内提到的实验均是建议设计，除非另有实验数据支持，不应写成已完成结果。
