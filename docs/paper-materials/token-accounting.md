# 词元统计与持续审计曲线

截至 2026-11-07，系统已有部分原始用量记录，尚未实现覆盖全部阶段与全部模型调用的统一累计统计，也没有验证后的持续审计曲线。

## 已有记录

Claude Code 会话原始日志的 result 事件提供输入、输出、缓存写入、缓存读取词元及会话耗时。Jev 初筛界面可显示输入和输出用量。audit_rsi/adapters/raw_trace.py 保留部分动作和会话的消耗字段，供轨迹解释使用。

这些字段不能直接求和当作全系统消耗：逐步事件与会话总量可能重叠，同一会话还可能出现在镜像日志、重放和恢复目录。红队直接调用模型的路径尚未持久化 response.usage。缺失用量必须标为未知，不能当成零。

## 待实现的统一口径

每笔用量绑定项目、轮次、阶段、智能体、会话或请求编号、模型、时间戳和原始来源。按来源去重：有逐请求完整记录时使用逐请求记录；只有会话总量时作为会话级累计，不再叠加其逐步用量。重试是新的实际消耗，重复导入日志不是新的消耗。

输入、输出、缓存写入与缓存读取分别累计并明确提供方语义。不能在没有核对语义时跨提供方直接相加。缺失数据与统计覆盖范围同时展示。日志里的费用字段也不能未经核对就当作实际账单。

## 建议的论文曲线

横轴为实际时间，纵轴为所选统一口径下的累计词元消耗。标记经验证与独立审核通过的漏洞事件，同时标记技能候选生成、评估、试用、发布及回滚等不同 RSI 事件；不能把任意节点完成都算作一次成功进化。

同一漏洞跨轮出现应按稳定身份去重；首次候选时间与最终验证时间分开。词元消耗增加代表投入增加，不自动代表能力提升。论文还应报告新增有效漏洞、检查视角与证据缺口变化、每个有效结果的消耗，并保留缺失数据说明。

本节中的统一汇总与曲线属于待实现设计，不是已有实验结果。
