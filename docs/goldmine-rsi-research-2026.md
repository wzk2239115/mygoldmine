# 2026 年 RSI 研究调研与 Goldmine 映射

调研时间：2026-11-02。以下结论均来自论文原文或作者官方页面。RSI 指递归自我改进（recursive self-improvement），即系统依据自身运行证据持续改进；本文不把普通多轮反思都包装成 RSI。为便于阅读，harness 统一称为“执行框架”，即模型外部负责组织工具、环境和验证的执行逻辑。

## 1. 总体判断

2026 年较有工程价值的路线不是无约束地让模型重写自己，而是：**固定安全边界，围绕操作记录、验证器、执行框架、候选版本和发布门禁形成可审计闭环**。Goldmine 最适合走这条路线。

| 论文 | 核心机制 | 对 Goldmine 的直接启示 |
|---|---|---|
| [Self-Harness: Harnesses That Improve Themselves](https://arxiv.org/abs/2606.09498) | 归纳共性弱点 → 最小执行框架修改 → 在参与和未参与调参的项目上检查非回归 | 从红队和验证失败记录中归纳可复用弱点；每轮只修改事先声明的范围，候选不过门禁就不发布。例：`model_timeout` 聚为运行时控制弱点，对应 `audit_rsi/weakness.py`、`audit_rsi/harness.py` |
| [AgentDevel: Reframing Self-Evolving LLM Agents as Release Engineering](https://arxiv.org/abs/2601.04620) | 单一版本线、可执行诊断、逐项检查“通过→失败”（P→F）和“失败→通过”（F→P） | 不只看平均收益；必须记录每个候选问题和项目的回归，保留不可变候选和回滚能力 |
| [Recursive Self-Improvement through Multi-Agent Self-Supervision](https://arxiv.org/abs/2610.12176) | 多角色工作流搜索与自评估交替，优质团队操作记录回流训练 | 红队攻击者、目标服务执行框架和独立评判器的记录应按角色保留；可研究团队轨迹，但自评不能替代独立证据 |
| [Model–Harness Co-evolution for Recursive Self-Improvement](https://arxiv.org/abs/2608.13951) | 构建、更新、重建执行框架，保留同一问题的不同验证结果和完整证据 | 同一候选问题的执行框架应保留成功、回归和近失样本；未来模型更新后要重建匹配的执行框架 |
| [DiscoveryRSI: Recursively Learning to Discover Valuable Hypotheses](https://arxiv.org/abs/2610.23839) | 假设树、贡献评估、执行回放和再次发现 | 候选问题不只是一个标签，还应记录根因、调查决策、替代解释和可证伪性；可研究如何评估每个假设的贡献 |
| [Recursive Self-Improvement in AI: From Bounded Self-Refinement to Autonomous Research Loops](https://arxiv.org/abs/2607.07663) | 汇总 1,250 篇论文，比较验证方式、闭环程度与崩溃风险 | 验证器强度决定 RSI 上限；形式化检查和实际运行验证强于模型自评，“决定什么值得验证”仍需要人类判断 |

## 2. 关键证据

### Self-Harness

- 固定基座模型和评估器，只从执行记录中归纳模型特定弱点。
- 候选修改必须最小、针对具体失败机制，并在参与和未参与调参的项目上通过非回归检查。
- Terminal-Bench-2.0 上，三个模型在未参与调参的留出项目中的通过率分别由 40.5%→61.9%、23.8%→38.1%、42.9%→57.1%。这些是论文设定内的结果，不能直接外推到 Goldmine。

### AgentDevel

- 把智能体当作可发布制品，每轮只产生一个发布候选（RC），保留清晰的版本线。
- 强调“通过→失败”（P→F）的回归和“失败→通过”（F→P）的修复，而不是只看平均分。
- WebArena 消融实验中，完整方案的 P→F 为 3.1%，移除修复/回归门禁后为 14.8%，并出现 4 次不应发布的版本。这支持 Goldmine 采用逐候选问题、逐项目的回归门禁。

### MASS

- 同一基座模型扮演多个角色，搜索工作流，再把优质团队操作记录用于模型训练。
- 两轮后，在四个开放研究基准上，每输出一个 token 的得分为基座的 1.2–1.6 倍。
- 论文同时提醒：模型自评可能强化共同盲点。Goldmine 的独立评判器与 flag 来源核验必须保持独立。

### HELIX / Model–Harness Co-evolution

- 执行框架不仅决定今天如何运行，也决定明天能学到什么操作记录。
- 证据层保留操作轨迹、测试、策略决定和来源信息；同一问题的成对验证记录包含成功、回归、近失和替代方案。
- 论文报告的 200 组配对样本产出 438 条用于监督训练、评价、过滤和偏好学习的记录，说明丰富操作记录比单一“成功/失败”标记更有学习价值。

### DiscoveryRSI

- 将假设贡献评估、工作流回放和再次发现连接起来。
- 两轮后假设质量从 4.86 提升到 5.39，并有初步专家评估；但其生命科学领域结果不能直接视为安全漏洞发现效果。

### 2026 综述

- 验证方式从形式化检查到模型自评不等，实证改进强度与验证方式的可靠程度相关。
- 主要风险包括用自身判断反复强化自身结论、模型或多样性崩溃，以及计算预算限制。
- “选择什么值得评估”不能仅靠提高评判分数解决，还需要人类研究方向与安全先验。

## 3. Goldmine 当前差距

截至本轮代码与数据检查：

- 经验池有 986 条问题实例（occurrence）记录，可实际用于训练的验证动作支持从 0 修复为 6 条真实代码分析（static）样本。
- 高等级可信样本支持数 `trusted_support=0`，生产发布仍被拒绝；不能声称已实现生产 RSI 或因果提升。
- 验证报告（`verify-report.json`）和自动状态文件（`auto-state.json`）原先未完整进入经验池，已在本轮修复。
- 新增红队经验适配（`redteam-experience`）：运行级结果与攻击者逐步工具事件分层，只有来源可重算核验的实际运行或独立评判记录才自动获得可信标签；未捕获来源（`not_captured`）的记录保持未知（unknown）。
- 新增 `redteam-weakness`：按项目类型、攻击模型、失败类别和严重度对失败进行可重复分组，输出支持数量、成本和候选可修改范围；只归纳弱点，不自动修改执行框架。
- `verify-flips` 现在带候选非回归门禁：默认要求配对覆盖率 ≥0.8、至少一个“失败→通过”（F→P）、零“通过→失败”（P→F）；门禁接受后仍需候选复核，不自动发布。
- 新增标签补充计划（`label-plan`）：优先选择完全缺少可信标签的项目和动作，过滤无动作记录，保留抽样倾向和安全上下文，用于更高效地补充真实标签。
- 新增 `harness-propose / harness-validate`：弱点归纳结果可生成带稳定 ID、证据哈希和保留行为的最小候选，身份篡改会被拒绝；候选仅在修复/回归门禁接受时标记为已验证，仍不执行实际修改（`mutation=none`）。
- 自动路由可以提供按既定规则选择的动作及其选择概率，但不等于探索数据；同动作回放不能证明替代动作会更好。
- 红队 HTTP 实验环境、flag 来源核验和独立评判器是强证据来源，但当前覆盖和协议范围仍有限。

## 4. 建议的短期与中期路线

短期：

1. 持续增加真实验证、实际运行和独立评判标签，按问题实例与语义身份隔离训练和评估，防止同一问题泄漏到两侧。
2. 为每个动作保留动作前上下文、成本、结果和证据等级。
3. 增加逐候选问题的修复/回归检查与跨项目 holdout，不只汇报平均收益。**holdout 是留出验证项目，训练和调参时不看它，用来检验跨项目泛化。**
4. 保持影子模式（shadow-only）：**只给建议，不自动改变生产流程**，直到可信样本支持、留出验证和统计门禁真实满足。

中期：

1. 在明确允许修改的执行框架范围内归纳弱点并生成最小候选。
2. 建立攻击者、场景和独立评判器的多角色操作记录库，保留同一问题的不同验证结果。
3. 用基线对照和按项目重抽样评估真实提升及其稳定性，失败候选保留回滚。
4. 最后再研究模型参数更新；不要把开放式自我修改当作起点。
