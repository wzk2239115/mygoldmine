# 按阶段和仓库改进技能

目标是让环境构建、审计编排、场景设计、蓝队验证、红队场景构建、红队执行、独立审核、经验学习分别积累适用的规则。这里改变的是 Markdown 技能上下文，不修改模型权重，也不承诺每一轮必然更好。

## 两层技能与启动

每个阶段保留既有基础智能体与技能，再加载两层已验证的规则：

- 通用技能：`<stage>/general/shared`，跨仓库使用。
- 仓库专属技能：`<stage>/project/<project>`，只用于指定仓库和阶段。

现行版本指针在 `rsi/stage-skills/active.json`；候选与已发布版本分别保存 Markdown、来源摘要和适用条件。阶段启动时读取固定的版本内容，追加到原有技能上下文，将本次内容和版本编号写入输出目录的 `.stage-skills-loaded/`。本次运行继续使用启动时内容，发布不会中途改变其提示。可选条件为机器架构、Python 版本、源码提交号的精确匹配；无法确认条件时不加载对应规则。

原生 Claude 阶段通过系统提示加载；红队独立模型循环通过系统消息加载。审计容器中的公共技能库仍为只读，候选先写本轮输出目录，不给容器增加公共规则写权限。对照评估所需的版本参数会传入审计容器。

## 各阶段产生反馈

结构化提交工具除交付检查外，还提供 `propose_skill_update`。字段包括层级、候选 Markdown、证据路径、可选适用条件；学习节点可通过 `target_stage` 整理其他阶段的反馈，其他节点只能提炼本阶段。成功经历、失败诊断、无效尝试和错误判定都可成为证据；没有有效新经验时不要求凑候选。

证据必须位于指定输出目录，提炼时保存副本及摘要。候选请求写入 `.stage-skill-proposals/`，宿主机在终态和学习阶段统一入库。单节点重跑结束后也采集反馈与候选。历史候选不会因另一项目开始学习而被删除。

采集器输出 `rsi/stage-feedback/index.json` 和八份阶段反馈，包括实际产物路径及摘要、阶段状态、整轮状态、结论计数；没有产物就标记缺失。总体成功不能覆盖阶段受阻。恢复汇总复用原始环境构建的证据，单节点重跑使用新尝试的反馈。安全审计阶段还会采集 `.workspace/findings/` 复制到运行产物的覆盖记录、下一批任务计划和复审计划，作为技能候选证据；覆盖记录中的未检查风险、缺失证据、受阻原因和复审收益可用于调整下一轮任务顺序，但不能用候选条数或读取行数代替效果。

独立的 `stage-skill-learner` 读取 `stage-skill-learning` 技能，负责跨阶段整理与提出候选；失败轮次也可通过同一入口学习。日常更新只提交覆盖、假设追踪、复审和验证反馈形成的候选；周期性更新再由既有评估入口做固定预算的新旧对照和未参与提炼的仓库验证。每次提炼保留独立会话、输入摘要和候选数，界面可查看。第 08 阶段负责跨阶段整理与提出候选，不负责凭自身判断批准规则。结束时由宿主机调用独立评估入口：已有可信套件就进行对照并发布通过版本，未配置则记录原因并保留候选。评估子任务带专用标记，禁止递归触发下一轮评估。既有挖掘修复经验机制保留，新阶段技能库独立管理，不把旧机制的完成状态等同于八阶段技能已改善。

### 第 08 阶段调用 SkillOpt

第 08 阶段先读取 `rsi/stage-feedback/index.json`、覆盖记录、复审计划、验证结论和红队与独立审核结果，按“来源阶段 → 目标阶段”归因，选择最多两个证据最充分的目标。需要重写时通过 `request_skillopt_optimization` 提交问题、1—4 条修改建议、1—5 份证据、来源阶段、预期改善、可能退化和适用条件；请求写入 `rsi/skillopt-requests/`，不直接修改正式技能。

宿主机 `scripts/stages/learn_round.py` 读取请求，调用 `scripts/stages/skillopt_adapter.py`。适配层只使用本地固定检出的 SkillOpt 核心重写入口 `skillopt.optimizer.rewrite.rewrite_skill_from_suggestions`，把当前技能正文和建议交给优化模型，再把返回的完整技能正文转换为现有 `SkillBank` 候选。适配层不启用 SkillOpt-Sleep 的完整夜间循环，也不启用上游 WebUI、插件、hook 或自动采用；现有技能库仍是正式版本、评估、发布和回退的唯一入口。

每个请求最多尝试两次；只有第一次没有返回可解析结果时才重试。优化任务设置 `SKILLOPT_RUN=1`，学习入口检测到该标记后跳过，避免递归启动学习。SkillOpt 的版本、提交、模型和尝试次数写入候选来源说明；请求和重写结果保存在 `rsi/skillopt/`，作为文本轨迹显示。

候选不会绕过评估：存在 `config/stage-evals/<目标阶段>.json` 时走现有对照评估；没有可信套件时记录 `missing_evaluation_suite` 并保留候选。评估通过后才调用现有发布入口，发布保留前一版和回退记录。SkillOpt 的内部评分、重写理由或候选数量都不等于项目发布批准。

有界试验使用临时运行 `demo/one`：真实 `stage-skill-learner` 读取反馈后提交两个请求，适配层调用固定提交的 SkillOpt 核心入口，生成环境构建和蓝队验证两个候选。没有评估套件时，现有 `advance` 将本轮全部候选都记录为 `missing_evaluation_suite`，正式版本指针保持为空。另在临时仓库放入测试评估命令，候选进入现有评估后 accepted，随后 publish 写入指针、rollback 清空指针。该试验只证明调用、候选、拒绝和发布接线，不证明漏洞识别能力提高。

## 独立评估、发布与回退

候选不参与默认运行。维护者在 `config/stage-evals/<stage>.json` 配置可信的实际执行与独立验收命令，参见该目录的 README。评估器固定同一份现行指针，分别执行基线与候选；每个用例重复至少三次并交替顺序。每次必须通过独立验收，所有指标不退化且至少一项改善，才可发布。缺少指标、非有限数值、超时或未通过验收都拒绝发布。

审计的覆盖率和误报率需独立标签或已验证的样例支持，不能拿发现条数或模型评分代替；没有这种数据时维持候选状态。通用规则还须在至少两个未参与该规则及其祖先提炼的其他仓库通过验证。仓库规则只接受本仓库评估，不把它直接推广为通用规则。

发布与回退在文件锁内原子更新指针，并保留前一版、评估记录和发布记录。评估后若现行版本变化，拒绝沿用旧对照结果发布。候选内容摘要不匹配时拒绝加载。

```bash
python3 scripts/stages/skill_bank.py status
python3 scripts/stages/skill_bank.py collect --project verl --root runs/verl/<运行编号>
python3 scripts/stages/skill_bank.py evaluate --candidate <编号> --suite config/stage-evals/verify.json
python3 scripts/stages/skill_bank.py publish --evaluation <评估编号>
python3 scripts/stages/skill_bank.py rollback --publication <发布记录编号>
```

## 连续执行 01—08

```bash
python3 scripts/stages/learning_cycle.py --source /home/wzk/mygoldmine/targets/verl --project verl --rounds 3 --patience 2
```

控制器逐轮启动既有完整流程，等待监督进程结束，采集反馈和候选，执行已配置的阶段评估套件并发布通过的版本，再进入下一轮。模型配置读取现有设置。运行记录在 `rsi/stage-skills/cycles/<编号>/`，每轮保留独立产物和结果。

默认最多三轮；连续两轮没有新版本通过评估就停止。没有评估套件时候选继续保留，不声称改善，也不会强行发布。可以在循环目录创建 `stop` 文件，让当前轮结束后停止后续轮次；超出本轮时限时请求停止该轮。循环使用项目锁，避免与界面项目重跑或节点重跑并发。中断控制器不会删除历史产物；若进程被强杀留下锁，应先核对该项目运行情况再清理。

此入口尚未在页面提供启停按钮，默认不自动启动长时间循环。节点轨迹页显示下次运行可用的通用版本、仓库版本和待评估候选数。当前已用 verl 的真实反馈试运行候选提炼；未用模拟测试结果替真实候选发布，也未据此宣称漏洞识别准确率已提高。

多条执行会话的接口默认选择列表首项：原始完整审计优先，新阶段学习会话排在旧挖掘修复会话之前；显式指定不存在的会话编号仍返回不存在，不回退到其他记录。
