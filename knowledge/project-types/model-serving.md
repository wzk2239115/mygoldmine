# Model Serving 审计知识卡

## 适用项目

Triton Inference Server、OpenAI-compatible model server、自研 serving 层、模型网关。

## 核心信任边界

1. **HTTP/gRPC 推理 API**：认证、路由、请求体解析、超时/大小限制。
2. **模型仓库**：模型加载、版本切换、动态加载、路径/权限。
3. **管理面**：`/v2/repository`、`/metrics`、`/health`、`/config`、reload/shutdown。
4. **多租户**：模型隔离、队列隔离、配额、日志。
5. **后端运行时**：TensorRT/ONNX/PyTorch、自定义 backend、插件。

## 高价值问题

- 默认是否无认证？管理面与推理面是否同一认证域？
- 模型仓库路径是否可穿越/可写？能否加载未授权模型？
- 动态加载/插件是否执行任意代码？backend 是否可信？
- 请求体是否有大小/类型/嵌套深度限制？是否可 DoS？
- 指标/健康/配置端点是否泄露敏感信息？
- 多租户是否共享队列/缓存/工作目录？

## 常见 CWE

CWE-306、CWE-862、CWE-22、CWE-502、CWE-400、CWE-200、CWE-693。

## 误报排除

- 管理面只绑定回环/受信网络 → 降级。
- 模型仓库只读且由管理员维护 → 不算任意加载。
- 动态 backend 只在显式管理员操作下启用 → opt-in。

## 验证配方

- 起本地服务，检查默认认证与绑定地址。
- 用 benign 模型/路径验证仓库边界，不加载未知二进制。
- 对管理端点只做 `curl 127.0.0.1` 的认证检查。

## 输出要求

标注默认认证、网络暴露、管理面是否独立、模型来源是否可信。
