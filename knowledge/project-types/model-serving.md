# 模型服务（Model Serving）审计知识卡

## 适用项目

Triton Inference Server、兼容 OpenAI 接口的模型服务、自研模型服务层和模型网关。

## 核心信任边界

1. **HTTP 和 gRPC 推理 API**：认证、路由、请求体解析、超时与大小限制。
2. **模型仓库**：模型加载、版本切换、动态加载、路径与权限。
3. **管理面**：`/v2/repository`、`/metrics`、`/health`、`/config`、重新加载和关闭服务。
4. **多租户**：模型隔离、队列隔离、配额和日志。
5. **后端运行时**：TensorRT、ONNX、PyTorch、自定义后端和插件。

## 高价值问题

- 默认是否无认证？管理面与推理面是否同一认证域？
- 模型仓库路径是否可穿越或可写？能否加载未授权模型？
- 动态加载或插件是否执行任意代码？后端是否可信？
- 请求体是否有大小、类型和嵌套深度限制？是否可导致拒绝服务？
- 指标、健康和配置端点是否泄露敏感信息？
- 多租户是否共享队列、缓存或工作目录？

## 常见 CWE

CWE-306、CWE-862、CWE-22、CWE-502、CWE-400、CWE-200、CWE-693。

## 误报排除

- 管理面只绑定回环地址或受信网络：降级。
- 模型仓库只读且由管理员维护：不算任意加载。
- 动态后端只在显式管理员操作下启用：可达性为 `opt-in`。

## 验证配方

- 启动本地服务，检查默认认证与绑定地址。
- 用无害模型和路径验证仓库边界，不加载未知二进制。
- 对管理端点只做 `curl 127.0.0.1` 的认证检查。

## 输出要求

标注默认认证、网络暴露、管理面是否独立、模型来源是否可信。
