# PHP Doctrine MongoDB Query Injection

## Details

**漏洞成因**：Doctrine MongoDB ODM 为 PHP 应用提供对象-文档映射。当使用 Doctrine 的查询构造器或 `createQueryBuilder()` 时，若使用原生查询或参数未验证，攻击者可注入 MongoDB 操作符。

**代码审计焦点**：
- 是否使用了 `createQueryBuilder()` 进行查询构造
- 是否使用了 `where()`、`field()` 等方法
- 是否使用了原生查询方法（`find()` 直接传递数组）
- 查询条件的参数化情况

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `createQueryBuilder`、`.where(`、`.field(`、`$_GET` 等关键字
- **(L2: 跳读)** 检查查询条件是否来自用户输入
- **(L3: 逐行读)** 追踪参数从接收到查询执行的过程，确认是否进行了验证
- **(L4: 跨模块追踪)** 检查是否通过多个仓库或服务组合查询

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用了查询构造器而非原生查询
- **(L2: 跳读)** 验证参数是否通过 Doctrine 验证注解
- **(L3: 逐行读)** 确认是否使用了参数绑定
- **(L4: 跨模块追踪)** 检查是否使用了查询白名单

## Classify

**漏洞研判**：
1. 若原生查询直接接受用户输入构造的数组 → 漏洞
2. 若查询构造器未使用参数绑定 → 漏洞
3. 若字段名由用户输入直接使用 → 漏洞

**误报风险**：
1. 使用查询构造器且参数通过绑定 → 低风险
2. 字段名使用常量 → 低风险
3. 使用 Doctrine 的验证注解 → 低风险

## Low risk

- 仅使用 Doctrine 的查询构造器
- 参数通过绑定而非直接拼接
- 字段名使用常量或白名单映射
- 使用 Doctrine 验证注解
- 数据库连接启用认证
