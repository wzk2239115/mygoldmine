# Rust Custom NoSQL Query Builder

## Details

**漏洞成因**：Rust 应用使用自定义的 NoSQL 查询构造器时，若未进行类型安全验证，攻击者可通过字符串拼接或宏注入实现注入攻击。Rust 的类型系统可以防止编译期错误，但运行时的字符串操作仍可能导致注入。

**代码审计焦点**：
- 是否使用字符串拼接构造查询条件
- 宏是否接受用户输入参数（特别是 `format!`、`concat!` 等）
- 查询条件是否通过外部配置或环境变量构造
- 查询对象是否实现了 `FromStr` 或类似 trait，允许反序列化用户输入

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `format!`、`concat!`、`to_string()`、`FromStr` 等关键字
- **(L2: 跳读)** 检查字符串操作是否包含用户控制的变量
- **(L3: 逐行读)** 追踪查询对象的构造过程，确认是否存在类型验证
- **(L4: 跨模块追踪)** 检查多个模块如何组合构造查询

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用了参数化查询 builder 模式
- **(L2: 跳读)** 验证是否使用 `serde` 等库进行类型安全反序列化
- **(L3: 逐行读)** 确认是否使用了 Rust 的类型系统限制字段访问
- **(L4: 跨模块追踪)** 检查是否使用了 MongoDB 官方 Rust 驱动的安全接口

## Classify

**漏洞研判**：
1. 若使用字符串拼接构造查询条件 → 漏洞
2. 若通过 `FromStr` 反序列化用户输入的查询对象 → 漏洞
3. 若宏接受用户控制的参数 → 漏洞

**误报风险**：
1. 使用参数化 builder 模式且字段为常量 → 低风险
2. 使用 `serde` 进行类型安全反序列化 → 低风险
3. 查询对象完全由后端硬编码 → 低风险

## Low risk

- 使用参数化 builder 模式构造查询
- 使用 `serde` + struct 进行类型安全反序列化
- 字段名使用 Rust enum 或常量
- MongoDB 官方驱动的类型安全接口
- 运行时验证所有用户输入
