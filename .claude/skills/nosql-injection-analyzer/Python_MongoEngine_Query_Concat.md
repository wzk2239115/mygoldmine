# Python MongoEngine Query Concat

## Details

**漏洞成因**：MongoEngine 是 Python 的 MongoDB ODM，提供对象文档映射接口。当查询条件通过字符串拼接、动态属性访问或 `Q` 对象构造时，若参数由用户输入直接提供，攻击者可注入 MongoDB 操作符（如 `$where`、`$ne`、`$gt` 等），突破查询逻辑或执行任意代码。

**代码审计焦点**：
- 是否使用字符串拼接构造查询字段名或条件值
- `.objects()` 或 `.objects(__raw={})` 方法的参数来源
- `Q()` 对象或动态属性构造（如 `Model.objects(**kwargs)`）是否接收用户输入
- 是否使用了 `raw` 查询或直接访问 MongoDB 驱动层
- 字段名是否通过用户输入动态构造

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `.objects(`、`Q(`、`**kwargs`、`__raw`、`format()`、`%`、`f"`、`getattr()` 等关键字
- **(L2: 跳读)** 检查参数是否来自 `request.GET`、`request.POST`、`request.args` 等不可信源，特别关注是否进行了黑名单过滤而非白名单验证
- **(L3: 逐行读)** 追踪用户输入从接收、处理、到查询执行的完整流程，识别参数化缺失点
- **(L4: 跨模块追踪)** 检查查询构造是否跨越多个函数或类方法，追踪参数的动态组合过程

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用 MongoEngine 的参数化查询方法（位置参数或命名参数）
- **(L2: 跳读)** 验证字段名是否来自预定义的常量、枚举或白名单，是否有类型检查（如 `int()`、`bool()`）
- **(L3: 逐行读)** 确认是否使用 `Model._meta.fields` 或自定义校验器验证字段名合法性，是否对操作符前缀进行拦截
- **(L4: 跨模块追踪)** 检查是否通过序列化库（pydantic、marshmallow）进行结构化验证，是否使用了自定义查询构造器封装

## Classify

**漏洞研判**：
1. 若字段名或条件值通过字符串拼接、格式化字符串（`format()`、`%` 操作、f-string）、`getattr()` 动态构造 → 漏洞
2. 若 `Q()` 对象或 `.objects(**kwargs)` 的参数直接来自用户输入，且无字段白名单验证 → 漏洞
3. 若条件值中包含 MongoDB 操作符（`$`、`{}`），且非通过严格类型转换 → 漏洞
4. 若使用 `raw=True` 或直接访问底层 PyMongo 连接 → 漏洞

**误报风险**：
1. 字段名为硬编码常量或通过白名单映射 → 低风险
2. 参数通过 MongoEngine 字段定义的类型强制转换 → 低风险
3. 使用 Pydantic 或 Marshmallow 进行 schema 验证，确保结构合法 → 低风险
4. 查询参数显式限制在预定义的操作符集合内（如仅允许 `$gt`、`$lt`） → 低风险

**代码异味**：
1. 使用黑名单过滤操作符（如 `input.replace('$', '')`） → 可能误报，需进一步追踪是否仍存在绕过
2. 只有部分参数来自用户输入，其他来自常量 → 低风险，但需确认所有变量来源
3. 条件值经过正则表达式验证 → 需评估正则的完整性

## Low risk

- 使用 MongoEngine 的参数化查询方法，字段名为常量或白名单枚举
- 所有用户输入通过显式的位置参数传递给查询方法，如 `Model.objects(name=user_input)` 且 `name` 为已验证字段
- 条件值通过 Python 原生类型转换（`int()`、`float()` 等）或 MongoEngine 字段验证器强制转换
- 使用 Pydantic、Marshmallow 等 schema 验证库进行完整的请求数据结构验证
- MongoDB 连接采用最小权限原则，数据库用户权限受限（禁用 `eval`、`mapReduce`）
- 在应用层实现查询构造器，禁止用户指定字段名或操作符
