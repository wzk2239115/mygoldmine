# NodeJS MongoDB Where Code Injection

## Details

**漏洞成因**：MongoDB 支持 `$where` 操作符用于 JavaScript 代码执行。Node.js 应用若在查询条件中允许用户输入构造 `$where` 操作符，攻击者可执行任意 JavaScript 代码访问数据或破坏完整性。这是一种特殊的代码注入漏洞。

**代码审计焦点**：
- 是否在查询条件中使用了 `$where` 操作符
- 用户输入是否直接进入 `$where` 的 JavaScript 代码
- 是否使用了 `eval()`、`Function()` 等动态代码执行
- 查询条件是否由 JSON 反序列化构造

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `$where`、`eval(`、`Function(`、`JSON.parse` 等关键字
- **(L2: 跳读)** 检查这些危险构造是否涉及用户输入
- **(L3: 逐行读)** 追踪输入从接收到代码执行的过程
- **(L4: 跨模块追踪)** 检查是否通过多个函数处理用户输入后进入代码执行

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否完全禁用了 `$where` 操作符
- **(L2: 跳读)** 验证是否使用了安全的查询方法
- **(L3: 逐行读)** 确认代码执行是否在沙箱环境中
- **(L4: 跨模块追踪)** 检查 MongoDB 连接配置是否禁用了危险操作符

## Classify

**漏洞研判**：
1. 若查询条件中使用了用户输入构造的 `$where` → 高危漏洞
2. 若使用 `eval()` 或 `Function()` 动态执行用户代码 → 高危漏洞
3. 若 JSON 反序列化后的对象被用于 `$where` → 高危漏洞

**误报风险**：
1. 完全禁用 `$where` 操作符 → 低风险
2. 使用安全的查询方法且无代码执行 → 低风险

## Low risk

- 完全禁用 `$where` 操作符
- 仅使用标准 MongoDB 操作符
- 不使用 eval()、Function() 等动态代码执行
- MongoDB 服务器端禁用 JavaScript 执行
- 数据库连接权限受限
