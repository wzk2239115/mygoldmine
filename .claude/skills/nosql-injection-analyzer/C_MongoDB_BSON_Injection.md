# C MongoDB BSON Injection

## Details

**漏洞成因**：MongoDB 的 C 驱动（libmongoc）通过 BSON 文档进行查询。当使用 `bson_append_*` 函数时，若字段名或值由用户输入直接构造且未进行验证，攻击者可注入 BSON 字段或操作符。特别是在使用字符串操作时。

**代码审计焦点**：
- 是否使用 `bson_new()` 创建查询文档
- `bson_append_*` 函数的参数是否来自用户输入
- 字段名是否通过用户输入动态构造
- BSON 文档是否进行了验证

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `bson_append`、`bson_new`、`mongoc_collection_find` 等关键字
- **(L2: 跳读)** 检查参数是否来自不可信源（用户输入、网络数据等）
- **(L3: 逐行读)** 追踪参数从接收到 BSON 构造的过程，确认是否进行了验证
- **(L4: 跨模块追踪)** 检查是否通过多个函数组合构造 BSON

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否存在字段名白名单验证
- **(L2: 跳读)** 验证参数是否通过类型检查（atoi、strtol 等）
- **(L3: 逐行读)** 确认是否使用了 libmongoc 提供的安全接口
- **(L4: 跨模块追踪)** 检查 MongoDB 连接是否启用认证

## Classify

**漏洞研判**：
1. 若 BSON 字段名由用户输入直接构造 → 漏洞
2. 若值为用户输入且类型未限制 → 漏洞
3. 若未进行任何参数验证 → 漏洞

**误报风险**：
1. 字段名使用硬编码白名单 → 低风险
2. 参数通过类型转换限制（atoi、strtol） → 低风险
3. MongoDB 连接启用认证 → 低风险

## Low risk

- BSON 字段名使用硬编码白名单或常量
- 参数通过类型转换和范围检查
- libmongoc 连接启用认证
- 使用 SSL/TLS 加密
- 数据库权限受限
