# NodeJS CouchDB Query Injection

## Details

**漏洞成因**：CouchDB 使用 MapReduce 视图和 Mango 查询语言进行数据查询。Node.js 应用若使用 `nano` 或其他 CouchDB 客户端库，当构造 Mango 查询时，若字段名或选择器由用户输入直接构造，攻击者可绕过查询逻辑。

**代码审计焦点**：
- 是否使用 `db.find()`、`db.get()` 等方法
- Mango 查询的选择器是否包含用户输入
- 是否使用了 MapReduce 的 emit 或 map 函数
- 查询条件的键是否由用户控制

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `db.find(`、`db.get(`、`selector:`、`req.query` 等关键字
- **(L2: 跳读)** 检查选择器对象是否包含用户控制的字段名
- **(L3: 逐行读)** 追踪查询条件从构造到执行的过程，确认是否进行了验证
- **(L4: 跨模块追踪)** 检查是否通过多个函数组合查询

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用了查询白名单
- **(L2: 跳读)** 验证选择器的字段名是否通过白名单验证
- **(L3: 逐行读)** 确认参数值是否通过类型检查
- **(L4: 跨模块追踪)** 检查是否使用了 CouchDB 的高级查询库

## Classify

**漏洞研判**：
1. 若选择器的字段名由用户输入直接构造 → 漏洞
2. 若使用字符串拼接构造 Mango 查询 → 漏洞
3. 若允许用户控制操作符（如 `$eq`、`$ne`） → 漏洞

**误报风险**：
1. 字段名使用白名单验证 → 低风险
2. 参数值通过类型检查 → 低风险
3. 查询完全由后端定义 → 低风险

## Low risk

- Mango 查询的字段名使用白名单
- 参数值通过类型检查
- 数据库连接启用认证
- 查询权限受限
- 使用高级 CouchDB 查询库
