# Rust Redis Command Injection

## Details

**漏洞成因**：Rust 的 Redis 客户端（redis crate）提供类型安全的接口。但使用 `cmd()` 或 `Script` 执行动态命令时，若参数由用户输入构造，攻击者可注入任意 Redis 命令。Lua 脚本执行（`Script::eval()`）若脚本由用户输入提供，更加危险。

**代码审计焦点**：
- 是否使用 `cmd()` 构造动态命令
- Lua 脚本是否由用户输入构造
- 是否使用了 `call()` 或 `query()` 执行用户控制的命令
- 命令参数是否进行了验证或白名单检查

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `cmd(`、`Script::new`、`eval(` 等关键字
- **(L2: 跳读)** 检查命令和脚本是否来自用户输入
- **(L3: 逐行读)** 追踪参数从接收到 Redis 执行的过程，确认是否进行了验证
- **(L4: 跨模块追踪)** 检查是否通过多个函数组合构造命令

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用了特定的 Redis 命令方法而非 `cmd()`
- **(L2: 跳读)** 验证参数是否通过白名单验证
- **(L3: 逐行读)** 确认脚本是否存储在服务器端
- **(L4: 跨模块追踪)** 检查 Redis 连接是否启用了认证

## Classify

**漏洞研判**：
1. 若使用 `cmd()` 执行用户输入构造的命令 → 漏洞
2. 若 Lua 脚本由用户输入构造 → 高危漏洞
3. 若允许执行任意 Redis 命令 → 漏洞

**误报风险**：
1. 使用特定的 Redis 命令方法且参数通过验证 → 低风险
2. 脚本存储在服务器端，用户仅提供参数 → 低风险
3. Redis 连接启用了认证 → 低风险

## Low risk

- 仅使用特定的 Redis 命令方法而非 cmd()
- Lua 脚本存储在服务器端
- 参数通过白名单验证
- Redis 连接启用密码认证
- 连接使用 TLS/SSL 加密
