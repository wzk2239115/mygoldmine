# NodeJS Mongoose Query Concat

## Details

**漏洞成因**：Mongoose 是 Node.js 的 MongoDB ODM，提供链式查询 API。当使用字符串拼接或 `where()` 方法时，若参数由用户输入直接构造，攻击者可注入 MongoDB 操作符。特别是在使用正则表达式或 JavaScript 代码执行时。

**代码审计焦点**：
- 是否使用字符串拼接构造查询条件
- `where()`、`find()`、`findOne()` 方法的参数是否来自用户输入
- 是否使用了 `eval()`、`exec()` 等危险函数
- 查询条件中是否使用了正则表达式，且正则由用户输入

**核心定位技巧**：
- **(L1: 关键词扫描)** 搜索 `.where(`、`.find(`、`eval(`、`/regex/` 等关键字
- **(L2: 跳读)** 检查参数是否来自 `req.query`、`req.body` 等不可信源
- **(L3: 逐行读)** 追踪参数从接收到查询执行的过程，确认是否进行了验证
- **(L4: 跨模块追踪)** 检查是否通过多个函数或中间件组合查询

**保护机制识别**：
- **(L1: 关键词扫描)** 检查是否使用了 Mongoose 的参数化查询方法
- **(L2: 跳读)** 验证参数是否通过 Schema 定义和验证中间件
- **(L3: 逐行读)** 确认是否有白名单字段验证
- **(L4: 跨模块追踪)** 检查是否使用了查询构造器库

## Classify

**漏洞研判**：
1. 若使用字符串拼接构造查询条件 → 漏洞
2. 若 `where()` 的参数直接来自用户输入 → 漏洞
3. 若允许用户控制的正则表达式 → 漏洞

**误报风险**：
1. 使用 Mongoose 的参数化查询方法 → 低风险
2. 参数通过 Schema 验证 → 低风险
3. 字段名为常量 → 低风险

## Low risk

- 仅使用 Mongoose 的参数化查询方法（find、findOne）
- 参数通过 Schema 定义和验证中间件
- 字段名使用常量或枚举
- 使用 Mongoose pre 钩子进行参数验证
- 正则表达式由后端定义，用户仅提供搜索值
