# bypassTricks

会话管理和身份认证漏洞的常见绕过技巧和审计方法汇总

---

## 快速审计清单

### 会话ID相关
- [ ] 会话ID长度是否 >= 32 字符 (128 bits)
- [ ] 是否使用密码学安全的随机数生成器
- [ ] 登录前后会话ID是否发生变化
- [ ] 会话ID是否可在URL中传输
- [ ] 会话ID是否在日志中泄露

### 会话超时
- [ ] Cookie 是否设置 HttpOnly 标志
- [ ] Cookie 是否设置 Secure 标志 (HTTPS only)
- [ ] 会话是否有过期时间
- [ ] 是否有活动超时 (idle timeout)
- [ ] 过期后是否清理会话数据

### 认证绕过
- [ ] 是否有必须的身份验证检查缺失
- [ ] 认证检查的顺序是否正确
- [ ] 是否可跳过MFA验证
- [ ] 密码验证逻辑是否完整
- [ ] 是否有二次认证或验证码验证

### 密码重置
- [ ] 重置令牌是否有过期时间
- [ ] 重置令牌是否只能使用一次
- [ ] 重置流程是否需要身份验证
- [ ] 是否可通过邮箱枚举进行用户识别
- [ ] 重置令牌是否在日志中泄露

### 权限验证
- [ ] 是否检查用户权限而非仅检查身份
- [ ] 用户是否可修改他人的资源 (IDOR)
- [ ] 是否有行级访问控制 (RBAC/ABAC)
- [ ] API 端点是否与 Web 端点有一致的权限

### 多因素认证 (MFA)
- [ ] MFA 验证状态是否在服务端存储
- [ ] 是否可绕过MFA验证
- [ ] 备用码使用后是否销毁
- [ ] 是否可使用其他验证方式绕过

### 并发会话控制
- [ ] 是否限制单用户并发会话数
- [ ] 新登录是否踢出旧会话
- [ ] 同一设备是否可维持多个会话

### 敏感数据保护
- [ ] 会话数据是否加密存储
- [ ] 密码是否使用强哈希算法
- [ ] 敏感操作是否需要二次认证
- [ ] 会话中是否存储了敏感信息

## 常见绕过技巧

### 会话固定攻击
1. **攻击者先访问**：访问应用获得有效会话ID
2. **诱导受害者**：将会话ID通过URL或其他方式发送给受害者
3. **劫持会话**：受害者登录后，攻击者使用该会话ID登录
4. **修复方案**：登录后立即更新会话ID (changeSessionId, regenerate_id)

### 会话劫持
1. **嗅探网络**：中间人攻击获得会话Cookie
2. **XSS 攻击**：JavaScript 窃取 localStorage 中的令牌
3. **CSRF 攻击**：伪造请求使用受害者的会话
4. **修复方案**：HTTPS + HttpOnly + SameSite + CSRF Token

### 密码重置绕过
1. **时间戳枚举**：直接猜测重置令牌时间戳
2. **参数篡改**：修改 user_id 重置他人密码
3. **令牌重放**：多次使用同一重置令牌
4. **流程跳过**：跳过邮箱验证步骤
5. **修复方案**：令牌安全生成、一次性使用、完整流程验证

### 认证绕过
1. **空值检查**：提交空密码或不提交密码字段
2. **类型混淆**：`"0" == 0` 的逻辑错误
3. **SQL 注入**：`admin' --` 绕过密码验证
4. **逻辑缺陷**：认证检查被注释或条件错误
5. **修复方案**：严格的输入验证、使用参数化查询、完整的逻辑检查

### MFA 绕过
1. **验证码爆破**：TOTP 有限的时间窗口允许尝试
2. **验证状态篡改**：前端修改 mfa_verified 标志
3. **备用码重用**：多次使用同一备用码
4. **其他认证方式**：绕过TOTP使用备用码
5. **修复方案**：速率限制、服务端状态检查、一次性使用、所有方式同样安全

### 权限绕过 (IDOR)
1. **ID 枚举**：遍历不同的用户ID访问资源
2. **参数篡改**：修改 user_id 访问他人资源
3. **路径遍历**：使用 `../` 访问其他用户的文件
4. **API 滥用**：调用内部API获取权限外的数据
5. **修复方案**：验证用户权限、实施访问控制、避免在URL中暴露ID

## 审计技巧速查

### 快速定位
- **登录相关**：`/login`, `/auth`, `/authenticate`, 登录处理函数
- **会话管理**：`Session`, `Cookie`, `jwt.sign()`, `session.set()`, `.create()`
- **权限检查**：`hasRole()`, `hasPermission()`, `isAuthenticated()`, `@Auth`
- **密码操作**：`password`, `hash`, `salt`, `bcrypt`, `reset`, `forgot`

### 关键字搜索
- 弱随机：`math.random`, `rand()`, `uuid.uuid4()`, `time.time()`
- 时间戳：`time()`, `now()`, `currentTimeMillis()`, `nanoTime()`
- 直接查询：`SELECT * WHERE user=`, `"INSERT INTO"`, `delete from`
- 权限缺失：`if (authenticated)`, 无 `hasRole()`, 无权限检查

### 审计等级指导
- **L1 (快速扫描)**：关键词和模式识别，用时分钟级
- **L2 (跳读)**：理解代码流程，用时 10 分钟
- **L3 (逐行)**：详细分析每行代码，用时 30 分钟
- **L4 (跨模块)**：追踪多文件和框架，用时 1+ 小时

## 语言特定的注意事项

### PHP
- `strcmp()` 比较可能有类型混淆
- SQL 注入常见，检查所有数据库查询
- Session 文件权限可能不当 (`/tmp/sess_*`)
- 弱密钥和默认配置常见

### Python (Django/Flask)
- `random` 模块不安全，应使用 `secrets`
- 中间件顺序很重要
- ORM 虽然防SQL注入但有其他风险
- 签名密钥强度很关键

### Java
- Spring Security 配置顺序错误导致绕过
- 会话固定在 Java 中常见
- 认证检查缺失导致IDOR
- 时序攻击在密码比较中常见

### Node.js
- JWT 常见的无过期时间或过期时间过长
- 中间件顺序控制权限，顺序错误可绕过
- 会话数据存储在客户端时容易被篡改
- 缺少并发会话限制

### Go
- 会话ID生成常使用弱随机或时间戳
- Gorilla Sessions 配置不当
- 中间件绕过在路由注册顺序不当时发生
- Cookie 标志配置不完整

### Rust
- 使用 `rand` 库但未使用 `OsRng`
- TOTP 实现常有时间窗口问题
- 会话数据序列化和反序列化的安全性
- 内存管理和敏感数据清零

### C/C++
- 弱哈希算法 (MD5, SHA1) 常见
- 时序攻击在密码比较中高风险
- 内存泄露和未清零敏感数据
- 缓冲区溢出导致认证绕过

## 常见漏洞组合

### 完全认证绕过
- 认证检查缺失 + 权限验证缺失 + 无CSRF保护
- 结果：任何人可访问任何资源

### 账户接管
- 密码重置无验证 + 邮箱可枚举 + 无速率限制
- 结果：攻击者可重置任意账户

### 会话劫持
- 会话ID可预测 + 未使用HTTPS + Cookie无HttpOnly
- 结果：攻击者可轻易获得有效会话

### 权限提升
- IDOR 漏洞 + 无行级访问控制 + API 无权限检查
- 结果：用户可访问他人的敏感数据

## 审计工作流

1. **情报收集** (L1 - 5分钟)
   - 识别认证和会话管理功能
   - 列出涉及的路由和端点
   - 确定存储后端 (内存、数据库、Redis)

2. **快速审计** (L2 - 10分钟)
   - 扫描关键代码路径
   - 检查配置和初始化
   - 识别明显的缺陷

3. **深入分析** (L3 - 30分钟)
   - 逐行审读认证和授权代码
   - 追踪敏感数据的流向
   - 验证所有检查和验证

4. **跨模块追踪** (L4 - 1+小时)
   - 追踪框架级的安全机制
   - 检查配置和部署设置
   - 验证相关的安全库

5. **复验** (5分钟)
   - 确认所有发现
   - 检查误报
   - 评估风险等级
