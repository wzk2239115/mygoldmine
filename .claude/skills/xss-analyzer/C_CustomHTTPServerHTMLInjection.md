# C/C++｜自研 HTTP 服务 HTML 注入 XSS

## 基本信息

- **难度等级：** ★★★★☆ (中高级)
- **审计时间：** 25-45分钟（单个漏洞点）
- **先决知识：** C/C++ HTTP 库、字符串拼接、缓冲区管理、HTML 编码
- **复杂度评估：**
  - 简单场景（单点 HTTP 响应）：20-25分钟
  - 复杂场景（多个响应路径、自定义编码）：45-60分钟

## 🚀 30秒快速清单

- [ ] 代码是否包含自研 HTTP 服务器实现？
- [ ] HTTP 响应是否直接拼接用户输入或请求参数？
- [ ] 字符串拼接时是否进行了 HTML 实体编码（如转义 <、>、&、"、'）？
- [ ] 是否使用了标准库的 HTML 编码函数或自定义编码函数？
- [ ] 是否存在缓冲区溢出或格式化字符串漏洞与 XSS 的结合？

**判断：** 如果第 1-2 个问题打勾且第 3 个未打勾，需要进行 L3+ 深度分析

## Details

### 漏洞成因
嵌入式 Web 服务或自研 HTTP 服务器常直接使用 `sprintf`、`strcat` 等函数构造响应。如果将用户输入（查询参数、路径、表单内容）插入 HTML，而未进行实体编码，就会导致 XSS。由于缺乏框架护航，比较常见于 IoT 设备、旧版管理平台。

### 代码示例

**易受攻击的代码：**
```c
char response[4096];
char name[128];
get_query_param(request, "name", name, sizeof(name));

snprintf(response, sizeof(response),
         "HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n"
         "<html><body><h1>Hello %s</h1></body></html>",
         name); // 未编码
send(client_fd, response, strlen(response), 0);
```

**安全示例：**
```c
char escaped[256];
html_escape(name, escaped, sizeof(escaped));
snprintf(response, sizeof(response),
         "HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n"
         "<html><body><h1>Hello %s</h1></body></html>",
         escaped);
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `sprintf("HTTP`, `snprintf`, `strcat`, `send(client_fd`, `write(conn_fd`, `HTML`, `Content-Type`。

**定位步骤：**
1. 搜索构造 HTTP 响应的代码块；
2. 跳读（L2）确认是否插入用户输入；
3. 检查是否存在 HTML 转义或白名单。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 自定义 HTML 转义函数；
- 输出统一封装（render_html）内部编码；
- 限制允许字符集（如仅数字字母）；
- 通过模板引擎（cgicc、Wt）渲染。

**定位技巧：**
- 逐行读（L3）确保每个插入点都进行转义；
- 跨模块追踪（L4）响应模板是否被多个功能复用。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 输出统一转义 | **L0（快速跳过）** | 风险低 |
| 个别插入点遗漏 | **L2（跳读）** | 快速修补 |
| 大量直接拼接用户输入 | **L3（逐行读）** | 高风险 |
| 模块之间传递 HTML 片段 | **L4（跨模块追踪）** | 需完整分析 |

## Classify

### 研判标准

#### 确认漏洞
1. 自研 HTTP 响应拼接用户可控数据；
2. 缺乏转义；
3. 可构造 payload 执行脚本。

#### 误报
1. 输入通过白名单过滤仅包含安全字符；
2. 输出为纯文本或下载文件；
3. 服务仅在隔离网络运行。

#### 代码异味
1. 为性能直接 `strcat` HTML；
2. 转义函数未完整覆盖（如未处理引号）；
3. 缺乏单元测试验证输出。

## Low risk

### 低风险评级场景

#### 1. 服务部署在受控网络
- 攻击面小，可暂降级。

#### 2. 输出仅用于调试
- 风险较低，但建议整改。

#### 3. 已计划引入模板或转义库
- 明确时间表，暂降级并跟踪。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 受控网络 | 攻击面小 | 中 |
| 调试输出 | 影响有限 | 低 |
| 改造计划明确 | 可暂缓 | 低 |
