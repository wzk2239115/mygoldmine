# JavaScript 前端模板注入 XSS

## 基本信息

- **难度等级：** ★★★★☆ (中高级)
- **审计时间：** 20-40分钟（单个漏洞点）
- **先决知识：** 前端模板引擎（EJS、Handlebars、Mustache）、转义机制、DOMPurify 使用
- **复杂度评估：**
  - 简单场景（单个模板）：15-20分钟
  - 复杂场景（多个模板引擎混用）：40-50分钟

## 🚀 30秒快速清单

- [ ] 代码中是否使用了前端模板引擎（EJS、Handlebars、Mustache 等）？
- [ ] 是否使用了不转义的占位符（如 EJS `<%= %>`、Handlebars `{{{ }}}`）？
- [ ] 这些占位符的值是否来自用户输入或外部数据源？
- [ ] 是否使用了安全的占位符（如 EJS `<%- %>`、Handlebars `{{ }}`）？
- [ ] 如果需要富文本渲染，是否先使用 DOMPurify 净化？

**判断：** 如果第 1-2 个问题打勾且第 3 个未打勾，需要进行 L3+ 深度分析

## Details

### 漏洞成因
前端模板引擎（Mustache、Handlebars、EJS、Underscore、Lodash、Art-template 等）若在渲染时直接插入用户输入，或使用显式关闭转义的语法（如 EJS `<%= %>`、Handlebars `{{{ }}}`、Vue `v-html`），会将未净化的内容写入 HTML，触发 XSS。攻击者可通过评论、昵称、接口数据、第三方内容源注入脚本，使浏览器执行恶意代码。

### 代码示例

**易受攻击的代码：**
```javascript
// EJS 模板渲染
const tpl = '<li><%= comment %></li>'; // <%= %> 不转义
const html = ejs.render(tpl, { comment: userInput });
document.querySelector('#comments').innerHTML += html;
```

**安全示例：**
```javascript
const tpl = '<li><%- comment %></li>'; // <%- %> 自动转义
const html = ejs.render(tpl, { comment: userInput });
document.querySelector('#comments').insertAdjacentHTML('beforeend', html);
// 如果需要富文本，使用 DOMPurify.sanitize(userInput) 或后端白名单净化
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `render(`, `template(`, `{{{`, `<%=`, `v-html`, `dangerouslySetInnerHTML`, `bypassSecurityTrustHtml`。

**定位步骤：**
1. 搜索模板渲染代码，确认使用的占位符或指令；
2. 跳读（L2）判断变量来源是否可被用户控制；
3. 检查是否关闭自动转义或使用原始 HTML 指令。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 默认转义占位符（EJS `<%- %>`、Handlebars `{{ }}`、Mustache `{{ }}`）；
- 使用 DOMPurify、sanitize-html 等库净化富文本；
- 框架安全配置（Angular 自动信任、React JSX 自动转义）；
- CSP 禁止内联脚本、限制资源加载。

**定位技巧：**
- 逐行读（L3）富文本渲染链路，确认所有入口都经过净化；
- 跨模块追踪（L4）数据从后端到模板的流转，识别绕过路径。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 仅使用安全占位符或净化后渲染 | **L0（快速跳过）** | 风险极低 |
| 少量模板启用原始 HTML | **L2（跳读）** | 确认净化措施 |
| 广泛使用非转义语法 | **L3（逐行读）** | 高风险 |
| 数据来源复杂跨多模块 | **L4（跨模块追踪）** | 需完整数据流分析 |

## Classify

### 研判标准

#### 确认漏洞
1. 模板使用原始 HTML 语法渲染用户可控输入；
2. 缺乏净化或白名单过滤；
3. 能构造 payload 执行脚本或 DOM 操作。

#### 误报
1. 数据来自可信后端且已严格编码；
2. 非转义语法仅渲染受控常量；
3. 页面不在真实部署路径，仅限内部测试（需证据）。

#### 代码异味
1. 同一模板混用转义与非转义，占位符难以维护；
2. 依赖自定义正则替换过滤危险标签；
3. 内联脚本依赖模板变量构建，影响难以评估。

## Low risk

### 低风险评级场景

#### 1. 内容来源于受控后台
- 只有管理员可编辑，攻击面小；可暂记低风险。

#### 2. 页面仅展示低敏数据
- 成功 XSS 对业务影响有限，但仍建议整改。

#### 3. 已计划接入统一净化方案
- 明确排期上线 DOMPurify/CSP 等，暂降级并跟踪。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 受控来源 | 攻击面小 | 中 |
| 低敏数据 | 影响有限 | 低 |
| 改造计划明确 | 可暂缓 | 低 |
