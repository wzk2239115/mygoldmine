# Rust｜Tera/Handlebars safe 过滤器误用 XSS

## 基本信息

- **难度等级：** ★★★☆☆ (中级)
- **审计时间：** 15-30分钟（单个漏洞点）
- **先决知识：** Tera/Handlebars 模板引擎、safe 过滤器、自动转义机制、HTML 净化库
- **复杂度评估：**
  - 简单场景（单个 safe 过滤器）：15-20分钟
  - 复杂场景（多个模板、链式过滤）：30-45分钟

## 🚀 30秒快速清单

- [ ] 模板中是否使用了 `| safe` 过滤器或禁用自动转义的设置？
- [ ] `| safe` 过滤器处理的数据是否来自用户输入或不可信数据源？
- [ ] 数据在被标记为 safe 前是否经过了可信的净化库处理？
- [ ] 是否为富文本内容使用了专门的白名单配置？
- [ ] 是否存在多个 safe 过滤器使用且管理混乱的情况？

**判断：** 如果第 1-2 个问题打勾且第 3 个未打勾，需要进行 L3+ 深度分析

## Details

### 漏洞成因
Rust 模板引擎（Tera、Handlebars、Askama）默认对变量进行转义。但若使用 `safe` 过滤器、`raw` 块或关闭自动转义，就会将字符串原样输出。若这些字符串来自用户或第三方服务，漏洞将导致 XSS。

### 代码示例

**易受攻击的代码：**
```tera
{# Tera 模板 #}
<div>{{ comment | safe }}</div>
```

**安全示例：**
```tera
<div>{{ comment }}</div>
{# 或在渲染前使用 ammonia/bleach 等白名单净化后再 safe #}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `| safe`, `| raw`, `{% raw %}`, `autoescape = false`, `{{{`。

**定位步骤：**
1. 搜索模板中出现 `safe`/`raw` 的地方；
2. 跳读（L2）确认变量来源；
3. 检查模板配置（`autoescape`）是否关闭。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 仅对经过白名单净化的内容使用 `safe`；
- 使用 ammonia、html5ever 进行过滤；
- 在 Rust 端构造 HTML 元素时使用 `Markup` 类型并具备审计；
- 开启 CSP 限制脚本执行。

**定位技巧：**
- 逐行读（L3）确认 safe 变量是否由可信源生成；
- 跨模块追踪（L4）模板继承/包含是否传递未净化变量。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 未使用 safe/raw，保持默认转义 | **L0（快速跳过）** | 风险低 |
| 少数 safe 应用于受控内容 | **L2（跳读）** | 核实来源 |
| 到处 safe 输出用户输入 | **L3（逐行读）** | 高风险 |
| 模板继承链复杂 | **L4（跨模块追踪）** | 需完整分析 |

## Classify

### 研判标准

#### 确认漏洞
1. 模板使用 `safe` 输出用户可控数据；
2. 缺乏净化或白名单；
3. 可构造 payload 执行脚本。

#### 误报
1. safe 仅应用于硬编码或可信富文本；
2. 数据在 Rust 端经过严格过滤；
3. 模板仅在内网或受控环境使用。

#### 代码异味
1. 在模板顶层关闭 autoescape；
2. 将 HTML 字符串存储在数据库后直接 safe 输出；
3. 缺乏统一白名单策略，开发者随意使用 safe。

## Low risk

### 低风险评级场景

#### 1. 富文本仅来自受控后台
- 攻击面小，可暂列低风险。

#### 2. 页面部署在内部网络
- 仍建议净化，但优先级较低。

#### 3. 已排期接入富文本过滤库
- 明确时间表，可暂降级并跟踪。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 受控来源 | 攻击面小 | 中 |
| 内网部署 | 影响有限 | 低 |
| 改造计划明确 | 可暂缓 | 低 |
