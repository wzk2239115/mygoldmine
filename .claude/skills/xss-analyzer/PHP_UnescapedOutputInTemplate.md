# PHP 模板未转义输出导致 XSS

## 基本信息

- **难度等级：** ★★★☆☆ (中级)
- **审计时间：** 15-30分钟（单个漏洞点）
- **先决知识：** PHP 模板引擎（Twig、Blade）、自动转义配置、变量输出方式
- **复杂度评估：**
  - 简单场景（单个模板）：15-20分钟
  - 复杂场景（多个模板继承、宏调用）：30-45分钟

## 🚀 30秒快速清单

- [ ] 模板文件中是否使用 `{{ }}`、`<?= ?>` 等输出语法？
- [ ] 输出的变量值是否来自用户输入或不可信数据源？
- [ ] 是否使用了模板引擎的自动转义功能（Twig 的 autoescape）？
- [ ] 对于需要输出 HTML 的富文本，是否使用了特殊的转义指令或过滤器？
- [ ] 是否在 PHP 配置或模板配置中禁用了自动转义？

**判断：** 如果第 1-2 个问题打勾且第 3 个未打勾，需要进行 L3+ 深度分析

## Details

### 漏洞成因
在 PHP 模板（原生 PHP、Twig、Blade、Smarty 等）中使用 `echo`、`print` 或不安全的模板语法直接输出用户输入，未经过 `htmlspecialchars`、`htmlentities` 或模板引擎默认转义，会导致 XSS。攻击向量通常来自 GET/POST 参数、数据库内容、配置文件或第三方接口。

### 代码示例

**易受攻击的代码：**
```php
// 原生模板
<p>昵称：<?php echo $_GET['name']; ?></p>

// Twig 模板
{{ comment|raw }}
```

**安全示例：**
```php
<p>昵称：<?php echo htmlspecialchars($_GET['name'] ?? '', ENT_QUOTES, 'UTF-8'); ?></p>

// Twig 默认会转义，避免使用 |raw，必要时执行可信白名单过滤
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `echo`, `print`, `<?=`, `|raw`, `{!!`, `{{{`, `->raw`, `->escape`。

**定位步骤：**
1. 搜索输出语句，识别变量来源；
2. 跳读（L2）确认是否使用转义函数或过滤器；
3. 检查模板配置是否禁用了自动转义。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 使用 `htmlspecialchars`、`e()`、`{{ }}` 默认转义；
- 模板引擎开启自动转义（Twig autoescape、Blade escaped echo）；
- 输出前白名单过滤或 Markdown 安全渲染；
- 统一的输出编码辅助函数。

**定位技巧：**
- 逐行读（L3）确认从数据库/接口加载的数据输出前是否转义；
- 跨模块追踪（L4）模板继承、自定义过滤器是否绕过转义。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 模板启用自动转义且未禁用 | **L0（快速跳过）** | 风险低 |
| 局部位置使用 raw/未转义语法 | **L2（跳读）** | 核实场景 |
| 广泛使用 `echo`/`raw` 输出用户输入 | **L3（逐行读）** | 高风险 |
| 模板复用链路复杂 | **L4（跨模块追踪）** | 需完整梳理 |

## Classify

### 研判标准

#### 确认漏洞
1. 模板输出用户可控数据未转义；
2. 能构造 payload 执行脚本；
3. 影响终端用户或管理员页面。

#### 误报
1. 数据为常量或已在后端转义；
2. 页面仅内网调试，外部无法访问；
3. raw 输出仅用于受控富文本并经过净化。

#### 代码异味
1. 混用转义和未转义输出；
2. 自定义转义函数实现不完整；
3. 将 HTML 直接存数据库并在模板中信任。

## Low risk

### 低风险评级场景

#### 1. 内容来源于受控后台
- 攻击面小，可暂定低风险。

#### 2. 页面只展示低敏数据
- 若 XSS 无法造成实质影响，可降级但需记录。

#### 3. 已计划接入统一输出编码函数
- 具备明确时间表，暂降级并跟踪执行。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 受控来源 | 攻击面小 | 中 |
| 低敏数据 | 影响有限 | 低 |
| 改造计划明确 | 可暂缓 | 低 |
