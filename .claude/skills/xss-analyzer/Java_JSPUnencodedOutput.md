# Java｜JSP 未编码输出导致 XSS

## 基本信息

- **难度等级：** ★★☆☆☆ (初级)
- **审计时间：** 10-20分钟（单个漏洞点）
- **先决知识：** JSP 标签语法、EL 表达式、`<%= %>`、HTML 编码函数、JSTL
- **复杂度评估：**
  - 简单场景（单个 JSP 页面）：10-15分钟
  - 复杂场景（多个 include、自定义标签）：20-35分钟

## 🚀 30秒快速清单

- [ ] JSP 页面中是否使用 `<%= %>` 或 `${}` EL 表达式输出变量？
- [ ] 输出的变量是否来自请求参数或用户输入？
- [ ] 是否使用了 `<c:out>` 标签（JSTL）或其他编码机制？
- [ ] 是否在 JSP 指令中设置了 `pageEncoding` 和正确的字符编码？
- [ ] 是否在 Web.xml 中启用了相关的安全配置？

**判断：** 如果第 1-2 个问题打勾且第 3 个未打勾，需要进行 L2+ 深度分析

## Details

### 漏洞成因
在 JSP 页面中使用 `<%= %>`、`out.println()`、`<c:out value="..." escapeXml="false"/>` 等方式直接输出用户输入，会绕过必要的 HTML 转义。若输入来自请求参数、session、数据库或第三方服务，可被攻击者利用触发 XSS。

### 代码示例

**易受攻击的代码：**
```jsp
<p>欢迎，<%= request.getParameter("name") %></p>
```

**安全示例：**
```jsp
<p>欢迎，<c:out value="${param.name}" /></p>
<!-- 或使用自定义的 EL 函数进行编码 -->
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `<%=`, `out.print`, `out.println`, `escapeXml="false"`, `fn:escapeXml`。

**定位步骤：**
1. 搜索 JSP 页面中的直接输出语句；
2. 跳读（L2）确认变量来源；
3. 检查是否使用 JSTL `c:out` 默认转义或自定义标签。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 统一的编码函数（如 `StringEscapeUtils.escapeHtml4`）；
- Struts/Spring MVC 使用 `HtmlUtils`；
- JSP 设置 `pageContext.setAttribute("escapeXml", true)` 等；
- 后端 Servlets 在写入前调用编码工具。

**定位技巧：**
- 逐行读（L3）识别特殊上下文（属性、事件、脚本）；
- 跨模块追踪（L4）EL 表达式传递链路。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 全部使用 JSTL 默认转义 | **L0（快速跳过）** | 风险低 |
| 局部使用 `<%= %>` 打印变量 | **L2（跳读）** | 快速修复 |
| 大量 out.println 输出用户输入 | **L3（逐行读）** | 高风险 |
| JSP/Servlet 混用且上下文复杂 | **L4（跨模块追踪）** | 需完整审计 |

## Classify

### 研判标准

#### 确认漏洞
1. JSP 输出用户可控数据未编码；
2. 能构造 payload 执行脚本；
3. 影响前台或后台页面。

#### 误报
1. 数据已在后端编码或来自常量；
2. 页面仅内网调试使用；
3. 输出位于 `text/plain` 响应。

#### 代码异味
1. 在属性、脚本上下文拼接变量；
2. 使用旧版 `StringEscapeUtils.escapeHtml`（JDK 1.6）但未覆盖所有字符；
3. 手写过滤替换 `<`、`>`。

## Low risk

### 低风险评级场景

#### 1. 内容来自受控后台
- 攻击面小，可暂列低风险。

#### 2. 页面仅展示低敏信息且有 CSP
- 风险较低，但仍建议编码。

#### 3. 已计划迁移至统一模板引擎
- 有明确时间表，可暂降级并跟踪。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 受控来源 | 攻击面小 | 中 |
| 低敏数据 | 影响有限 | 低 |
| 改造计划明确 | 可暂缓 | 低 |
