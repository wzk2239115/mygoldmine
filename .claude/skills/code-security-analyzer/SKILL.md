## 概述与边界

- 聚焦代码安全分析：对目标代码进行安全审计，识别潜在漏洞
- 识别代码中的安全缺陷，提供具体的加固建议和修复方案
- 不做：漏洞利用、渗透测试、运行时动态分析

## 输入说明

主要输入为**功能点相关的代码片段**，需包含：

- **源文件路径**：代码所在文件
- **行号范围**：代码起止行号
- **代码内容**：带行号的代码片段
- **功能描述**（可选）：该代码片段的功能说明
- **上下文信息**（可选）：路由路径、HTTP 方法、请求参数等

## 分析范围

### 安全缺陷类型

| 类型 | 检测内容 |
|------|----------|
| 输入验证 | 缺失或不完整的输入校验、类型检查、长度限制 |
| 输出编码 | 缺失的 HTML/URL/JS 编码、响应头设置 |
| 认证授权 | 硬编码凭证、弱密码策略、权限检查缺失 |
| 加密安全 | 弱加密算法、不安全的随机数、密钥管理问题 |
| 错误处理 | 敏感信息泄露、异常处理不当、调试信息暴露 |
| 日志安全 | 敏感数据记录、日志注入风险 |
| 配置安全 | 不安全的默认配置、调试模式启用、CORS 配置不当 |

### 分析方法

1. **静态代码审查**：扫描源代码识别安全模式和反模式
2. **配置文件检查**：分析配置文件中的安全设置
3. **依赖安全检查**：识别已知漏洞的依赖项（如有 lock 文件）

## 风险点识别与技能激活

根据代码中识别的潜在风险，**在当前任务中直接激活并使用**对应的漏洞分析技能进行深度扫描。

**风险点与技能映射**：
| 风险点特征 | 激活技能 |
|----------|----------|
| SQL 查询/数据库操作 | `sql-injection-analyzer` |
| 命令执行/系统调用 | `command-injection-analyzer` |
| 文件上传功能 | `insecure-file-uploads-analyzer` |
| URL 跳转/重定向 | `open-redirect-analyzer` |
| XML 解析 | `xxe-analyzer` |
| 用户输入渲染到页面 | `xss-analyzer` |
| 外部 HTTP 请求 | `ssrf-analyzer` |
| 路径操作/目录遍历 | `path-traversal-analyzer` |
| 本地文件包含 | `lfi-analyzer` |
| 远程文件包含 | `rfi-analyzer` |
| LDAP 查询 | `ldap-injection-analyzer` |
| 动态代码执行 | `code-injection-analyzer` |
| 资源 ID 访问 | `idor-analyzer` |
| 表单提交（非 GET） | `csrf-analyzer` |
| HTTP 头构造/响应头设置 | `http-header-injection-analyzer` |

**激活流程**：
1. 分析端点代码，识别潜在风险点
2. 根据风险类型，加载对应技能的 SKILL.md 获取分析指南
3. 按照技能指南对风险代码进行深度分析
4. 确认漏洞后生成 BUG 报告文件

## 输出要求

### 漏洞报告

确认漏洞后，加载 `bug-report` 技能获取标准化报告格式，生成漏洞报告文件。

**加载技能**：`bug-report`

**输出路径**：`.workspace/findings/BUG-{vuln_type}-{file}-L{line}-{source}-{sink}.md`

### 重要约束

- **禁止推荐下游任务**：该技能为分析终点，不生成任何 `tasks` 列表
- 输出格式为 `{"tasks": []}`
- 每个漏洞必须生成独立的 BUG 文件，禁止合并或省略
- 漏洞报告格式严格遵循 `bug-report` 技能定义的模板
