# 通用 XPath 注入漏洞审计小抄

任何涉及 XPath 查询的应用都必须审计以下漏洞模式。这些问题源于 XPath 查询构造缺乏安全控制，与编程语言无关。

## 1. 用户输入直接拼接到 XPath 查询

### 字符串拼接构造 XPath 表达式

**危险代码特征**

```python
xpath = "/users/user[name='" + user_input + "']"
query_result = xpath_eval(xpath, xml_doc)
```

**快速定位**（L1: 关键词扫描）：
- 搜索关键词：`XPath`、`xpath()`、`query()`、`select()`、`evaluate()`、`compile()`
- 搜索 XPath 特殊符号：`"//"`, `"/"`, `"@"`, `"contains("`, `"starts-with("`
- 搜索字符串拼接操作：`+`、`.format()`、`%`、`f-string`、`concat()`

**快速定位保护机制**（L2-L3: 跳读/逐行读）：
- **变量绑定**（L2）：检查是否使用了 `setVariable()`、`registerVariable()` 等变量绑定机制
- **参数化查询**（L2）：查找参数化 XPath 查询接口
- **白名单验证**（L3）：查看是否对用户输入进行了字段或值的白名单校验
- **完整链路**（L4）：追踪用户输入从接收到 XPath 执行的完整过程

---

## 2. 研判标准

### 确认为漏洞

**必须满足**
1. 用户输入直接用于拼接 XPath 查询字符串
2. 未使用参数化 XPath 查询机制
3. 未对用户输入进行有效的白名单验证
4. 攻击者可改变 XPath 逻辑，造成数据泄露或修改

**应用场景**
- 直接拼接用户输入构造 XPath 查询
- 字符串格式化或插值包含用户数据
- XML 解析后的结果直接被 XPath 查询使用

### 判定为误报

**如果满足以下情况之一，可判定为误报**
1. **参数化查询**：使用了参数化 XPath 查询接口（`setVariable()` 等）
2. **完整白名单**：严格的字段名或值白名单校验，无编码绕过
3. **类型强制**：用户输入已强制转换为特定类型（如整数），且有异常处理
4. **隔离执行**：XPath 查询在严格隔离的沙箱环境中执行

---

## 3. 低风险指标

### 以下情况应给予低风险评级

1. **参数化 XPath**：使用了 XPath 的变量绑定和参数化机制
2. **完整白名单**：所有 XPath 操作符和字段都通过精确白名单校验
3. **严格类型检查**：用户输入已通过类型检查（如整数解析）
4. **权限隔离**：XPath 查询在权限受限的上下文执行
5. **防御深度**：即使 XPath 被注入，也无法读取敏感数据
