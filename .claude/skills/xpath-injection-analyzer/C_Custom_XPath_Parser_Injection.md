# C/C++ - 自定义 XPath 解析器注入

## Details

### 漏洞成因
自定义实现的 XPath 解析器或查询引擎在处理用户输入时，若未正确验证输入或转义特殊符号，可能导致注入漏洞。常见问题包括：不完全的词法分析、缺乏语法树验证、不安全的递归解析等。攻击者可通过精心构造的 XPath 表达式绕过应用逻辑或访问非授权数据。

代码示例：
```cpp
struct XPathQuery {
    std::string expression;
    void parse(const std::string& userExpr) {
        expression = userExpr;  // 直接使用，无验证
        // 自定义解析逻辑
        processExpression();
    }
};
```

### 快速定位核心操作 (L1: 关键词扫描)
- 自定义的 XPath 解析类或结构体（通常命名如 `XPathParser`, `XPathEvaluator`, `QueryEngine` 等）
- `parse()`, `evaluate()`, `processExpression()`, `tokenize()` 等方法
- 正则表达式匹配 XPath 表达式的逻辑
- 递归或迭代处理用户输入的代码
- 树形结构构建（AST）时的节点操作

### 快速定位保护机制 (L2-L3: 跳读到逐行读)
- **输入验证** (L2) - 检查是否存在对输入长度、字符集或格式的验证
- **语法检查** (L3) - 确认解析器是否完整实现了 XPath 语法规范，是否有漏洞
- **边界处理** (L3) - 检查是否正确处理了引号、转义符、特殊字符等边界情况
- **跨模块追踪** (L4) - 追踪自定义解析器的所有调用点，确认是否都经过验证

## Classify

### 漏洞判定标准

**确认为漏洞**：
1. 自定义解析器直接使用用户输入，无输入验证
2. 解析器实现不完整，未覆盖所有 XPath 语法规则
3. 存在绕过边界检查的方式

**误报情况**：
- 自定义解析器虽然存在，但所有用户输入都经过严格白名单验证
- 解析器仅用于处理内部生成的表达式，用户无法直接控制
- 虽然代码复杂，但通过充分的单元测试和安全审计，已证实无注入风险

**代码异味**：
- 解析器实现简陋，缺少必要的错误处理和边界检查
- 混合使用了标准库和自定义逻辑，可能导致行为不一致
- 注释中明确指出的"TODO"或"FIXME"与 XPath 处理相关

## Low risk

### 低风险评级场景

1. **非业务关键** - 自定义 XPath 解析仅用于日志分析或调试，不涉及生产数据

2. **受限执行范围** - 解析器仅能查询特定预定义的 XML 结构，无法访问全部数据

3. **静态配置** - 虽然有自定义解析器，但 XPath 表达式完全来自代码，无用户输入

4. **额外防护层** - 即使解析器存在风险，但在其上层有多重防护（权限检查、请求限流等）
