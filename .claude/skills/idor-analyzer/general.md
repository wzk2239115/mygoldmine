# IDOR 审计快速参考（通用模式）

## 核心审计原则

1. **必须验证完整利用链**：用户可控的资源ID → 直接访问资源 → 缺少权限校验 → 越权影响
2. **所有权 ≠ 身份验证**：仅检查登录态不等于检查资源归属，需验证 `resource.user_id == current_user.id`
3. **不同操作需分别审计**：查询、修改、删除可能有不同的权限检查逻辑
4. **注意隐藏接口**：导出、打印、搜索等辅助功能可能缺乏权限验证

## 快速定位技巧

**第一步：找入口**
- 搜索接收用户参数的地方：URL路径参数、查询参数、请求体字段
- 关键字：`@PathVariable`, `@RequestParam`, `req.params`, `req.query`, `$_GET`, `$_POST`, `URL参数`
- 关注资源标识符参数名：`id`, `user_id`, `order_id`, `file_id`, `record_id` 等

**第二步：追踪资源访问**
- 找参数被用到的地方（数据库查询、文件读取、云存储访问）
- 代码走向：参数 → 查询/读取逻辑 → 返回数据
- 记录关键代码位置：文件名、函数名、行号

**第三步：检查权限校验**
- 在资源访问前是否有权限检查代码？
- 校验内容：比较 `resource.owner_id` 与 `current_user_id` 是否相等？
- 检查逻辑是否完整：是否覆盖所有操作（GET/POST/PUT/DELETE）？

## 漏洞模式总览

### 1. 直接访问 - 数据库/文件/云存储

**特征**：用户ID直接用于查询，未验证访问权限
```
危险：GET /api/users/123 → 返回用户123数据（无所有权检查）
安全：GET /api/users/123 → 检查 users.id==123 属于当前登录用户
```
**常见位置**：
- 数据库查询：`SELECT * FROM users WHERE id = ?` (未加 `AND user_id = ?`)
- 文件下载：`download(file_id)` (未验证文件归属)
- 云存储：`s3.getObject(key)` (直接用用户提供的key)

---

### 2. 所有权验证缺失

**情况A：完全未验证**
- 访问用户数据、订单、资料时无任何所有权检查
- 跨组织/租户访问未验证租户隔离
- 团队资源未验证成员关系

**情况B：仅验证身份未验证资源权限**
- 只检查用户是否登录，不检查是否拥有该资源
- 全局权限检查（如都是admin就能访问所有），未做细粒度验证

**情况C：RBAC实现不足**
- 仅验证用户角色（user/admin），未验证该资源用户是否有权访问
- admin角色绕过所有权限检查
- 权限定义过宽（如editor角色能修改所有user，而非仅所属项目内）

---

### 3. 资源ID可预测或可枚举

**自增整数ID** → 直接尝试 1, 2, 3, ... 可枚举所有资源
**可预测模式** → 基于时间戳、用户名、日期组合生成的ID
**UUID v1** → 包含时间和MAC地址，不够随机
**ID泄露** → API响应、错误信息、日志中暴露其他用户的资源ID

---

### 4. 权限校验逻辑缺陷

**条件分支漏过** → 特定条件下跳过权限检查
```
if (isDraft) {
    // 草稿可直接访问，无权限检查 ← 漏洞
} else {
    checkPermission();
}
```

**客户端可控的权限标志** → `isOwner=true` 参数可被篡改
```
POST /edit?isOwner=true → 直接编辑，无权限验证
```

**逻辑短路** → 权限检查异常时继续执行
```
try { checkOwnership(); }
catch { /* 异常被吞掉，继续返回数据 */ }
```

---

### 5. 不同操作权限不一致

**查询有验证，修改/删除无验证**
- GET /order/123 → 检查所有权 ✓
- POST /order/123/update → 直接修改 ✗

**主接口有验证，辅助接口无验证**
- /api/users/123 → 有权限检查
- /api/users/123/export → 直接导出，无检查

**不同HTTP方法验证不一致**
- GET /resource/123 → 验证所有权
- PUT /resource/123 → 不验证直接修改

---

### 6. 批量操作未逐项验证

**批量查询** → `GET /api/records?ids=1,2,3,4,5` 返回所有ID的数据，未逐项检查权限
**批量修改** → `POST /api/records/batch-update` 批量修改未校验每条记录的权限
**批量删除** → `POST /api/records/batch-delete` 批量删除未逐项验证删除权限

---

### 7. 间接引用未实施

**直接暴露内部ID** → URL、API中直接使用数据库自增ID
**缺乏临时令牌** → 文件下载、资源分享无有效期限制
```
危险：GET /download?file_id=123 (永久有效)
安全：GET /download?token=xyz (6小时有效期)
```

---

## 审计检查清单

- [ ] 识别所有接收资源ID的入口（URL参数、查询参数、请求体）
- [ ] 追踪ID被用于查询/访问的代码位置
- [ ] 检查查询前是否有 `if (resource.owner_id != current_user_id) deny`
- [ ] 确认权限检查覆盖所有操作（GET/POST/PUT/DELETE）
- [ ] 检查异常处理是否正确（异常不应导致权限检查被跳过）
- [ ] 验证批量操作逐项验证权限
- [ ] 检查跨租户/组织场景的隔离
- [ ] 验证资源ID是否安全生成（避免自增/可预测）
