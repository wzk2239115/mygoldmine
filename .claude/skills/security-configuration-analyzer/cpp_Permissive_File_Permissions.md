# C/C++ 宽松文件权限 (Permissive File Permissions)

## Details

### 代码示例
```cpp
// 危险：全局可读写执行
open("/tmp/sensitive.dat", O_CREAT|O_WRONLY, 0777);
chmod("/var/app/config.ini", 0666);
mkdir("/opt/uploads", 0777);

// 危险：未设置 umask
FILE* fp = fopen("/etc/app.conf", "w");  // 继承默认权限

// 危险：临时文件宽松权限
mkstemp(template);  // 默认 0600，但可能被 umask 影响
tmpfile();          // 权限依赖实现

// 常见于：
int fd = open(log_path, O_CREAT|O_APPEND|O_WRONLY, 0666);
creat(backup_file, 0777);
```

### 快速定位核心操作 (L1-L2)
**审计等级：L1 关键词扫描 + L2 跳读**
- **关键函数**：`open()` `creat()` `chmod()` `fchmod()` `mkdir()` `fopen()`
- **危险权限模式**：`0777` `0666` `0755` `S_IRWXO` `S_IWOTH` `S_IROTH`
- **搜索模式**：正则 `\b0[0-7]{3}\b` 快速定位八进制权限常量
- **上下文识别**：文件操作前后未调用 `umask()`，权限参数来自宏定义或配置
- **高危场景**：配置文件/密钥文件/临时文件/socket文件/日志文件的创建
- **定位技巧**：搜索 `O_CREAT` 标志，检查第三参数；搜索 `"w"` 模式 `fopen`，查看后续 `chmod`

### 快速定位保护机制 (L2-L3)
**审计等级：L2 跳读 + L3 逐行读（关键路径）**
- **umask 调用**：函数入口或初始化处 `umask(0077)` `umask(0027)` 限制默认权限
- **权限验证**：创建后立即检查 `stat()` `fstat()` 验证实际权限值
- **目录权限继承**：检查父目录权限，确认 ACL 或 SELinux 策略生效
- **条件编译**：`#ifdef SECURE_MODE` 包裹的权限设置
- **权限常量定义**：头文件或配置中定义 `APP_FILE_MODE 0600` 的使用
- **无保护特征**：权限参数硬编码、直接使用 `0666`/`0777`、注释标记 `TODO` `FIXME` `临时`

## Classify

**漏洞判定标准**：
- 敏感数据文件（密钥/配置/会话/凭证）设置他人可读 (o+r) 或可写 (o+w)
- 可执行文件/脚本设置全局可写 (0777/0666)
- 临时文件未使用 `O_EXCL` 且权限宽松，存在竞态条件
- 用户可控路径结合宽松权限，导致权限提升或信息泄露

**误报识别**：
- 日志目录/公共资源目录有意设为可读，业务需求明确
- 代码位于示例/测试/文档目录，非生产代码
- 已通过外层 `chroot`/`namespace`/`容器` 隔离，宿主权限不影响安全
- 立即后续调用 `chmod` 收紧权限（创建时宽松仅为兼容性）

**代码异味**：
- 权限设置合理但缺少注释说明，审计性差
- 权限通过多层宏展开，可读性低但实际安全
- 使用 `0644` 等相对安全权限，但未使用符号常量 (S_IRUSR|S_IWUSR|S_IRGRP|S_IROTH)

## Low risk

**低风险场景理论指导**：
- **已有保护层**：文件系统挂载为 `noexec`，执行权限无效；或通过 ACL/MAC 强制访问控制覆盖
- **非敏感数据**：公开日志、缓存、临时计算结果，泄露不影响机密性
- **生命周期短**：进程内存临时文件 `memfd_create()`，或立即删除的临时文件
- **受限访问环境**：容器/沙箱内运行，宿主权限已隔离；或仅单用户系统
- **显式降权**：后续通过 `setuid()`/`chown()` 转移所有权，配合权限限制
- **补偿控制**：应用层实现访问控制，文件系统权限仅为冗余保护
- **历史遗留**：老旧系统兼容需求，已通过外部监控/审计工具补偿风险
