# 证据检查清单

| 检查项 | 合格证据 | 不合格写法 |
|---|---|---|
| 输入控制 | 入口参数、配置键或文件字段到处理函数的路径 | “看起来可控” |
| 真实入口 | 生产入口或明确调用方，附 `path:line` | 测试函数、示例脚本、未被调用的工具函数 |
| 可达性 | 默认、需要配置、仅开发或未知，附条件 | 未核实就写默认可达 |
| 防护条件 | 认证、白名单、规范化、安全加载、沙箱的实际检查 | 只写“可能有校验” |
| 影响 | 能说明权限、数据、执行或拒绝服务后果的最小证据 | 只写严重度名称 |
| 反证 | 能排除路径的具体条件或运行结果 | “扫描器没报” |
| 运行确认 | 可重算的工具输出、随机标记来源或验证报告 | 模型自述、截图、计划动作 |

状态使用：

- `unchecked`：只有线索，还没有读调用链。
- `analyzed`：已读路径，但结论或影响不完整。
- `needs_evidence`：明确了缺哪类证据。
- `blocked`：环境、权限、依赖或预算导致无法继续。
- `counterevidence`：有具体反证，不是“没发现”。
- `runtime_confirmed`：有运行证据和来源链。

读文件、跑扫描器、调用技能都不能单独算覆盖完成。
