# PHP Header Location User Input

## Details

### 代码特征

开放重定向漏洞在 PHP 中的典型表现为使用 `header('Location: ...')` 直接转向用户可控的 URL，核心风险在于攻击者可控制重定向目标：

```php
// 漏洞示例
$redirect_url = $_GET['redirect'];
header('Location: ' . $redirect_url);
exit;
```

**快速定位核心操作** `(L1:关键词扫描)`
- 扫描 `header('Location:'` 或 `header("Location:")` 的调用点
- 检查 `Location` 头后面是否直接拼接 `$_GET`、`$_POST`、`$_REQUEST` 或其他用户输入变量
- 特别关注 `redirect`、`url`、`goto`、`return`、`target` 等参数名

**快速定位保护机制** `(L2:跳读)`
- 检查是否存在 URL 验证函数调用（如 `filter_var()` with `FILTER_VALIDATE_URL`）
- 查找是否有白名单检查（如 `in_array()` 验证域名）
- 扫描是否通过 `parse_url()` 检查 scheme 和 host
- 留意是否使用相对路径限制（如强制 `/` 开头且不含 `://`）
- 检查是否存在针对 `javascript:`、`data:`、`//` 的显式过滤

## Classify

研判标准分三个维度：

**数据流完整性**：追踪用户输入从源点到 `header()` 调用的全路径
- 若输入经过强白名单校验（如仅允许 `/path` 格式或预定义域名列表），视为有保护
- 若输入仅经过简单字符串替换或黑名单过滤，需深入分析有效性
- 若输入无任何处理直接使用，判定为漏洞

**场景合理性**：区分业务需求与漏洞
- 登录后跳转、OAuth 回调等合理场景需要更强的上下文验证
- 单纯的内部跳转（如 `/page?redirect=/dashboard`）如有域名限制可接受
- 跨域重定向需严格白名单

**验证有效性**：评估现有防护措施
- 漏洞：无验证、黑名单绕过（如 `//example.com`、`///example.com`、`data:` 等）
- 误报：完整的 URL 解析 + 域名白名单 + scheme 检查
- 代码异味：部分防护但存在明显绕过点、依赖前端验证、使用了失效的库函数

## Low risk

以下情况可评级为低风险：

**1. 纯相对路径重定向**
- 限制重定向目标为相对路径（如仅允许 `/` 开头，不含 `://`）
- 通过正则验证 `^/[a-zA-Z0-9/_-]*$` 等严格格式
- 此类场景攻击者无法重定向至外部网站

**2. 严格的白名单机制**
- 明确列举所有允许的目标域名或 URL 列表
- 使用 `parse_url()` 解析后进行精确匹配
- 白名单存储在配置文件或数据库（非用户输入驱动生成）

**3. 框架级别的保护**
- 某些框架（如 Laravel）提供的重定向辅助函数内置验证
- 已显式禁用外部重定向或强制域名检查

**4. 低敏感度场景**
- 仅用于记录日志或非关键功能的跳转
- 用户已通过强认证且操作在审计日志中可追踪
- 重定向发生在高度受限的上下文中（如内网系统）
