# Go JWT 静态密钥漏洞审计

## Details

**代码示例：**
```go
// 硬编码密钥
var jwtSecret = []byte("my-secret-key-12345")

func GenerateToken(userID string) (string, error) {
    token := jwt.NewWithClaims(jwt.SigningMethodHS256, jwt.MapClaims{
        "user_id": userID,
        "exp": time.Now().Add(time.Hour * 24).Unix(),
    })
    return token.SignedString(jwtSecret)
}

// 从配置读取但未轮换
var secretKey = os.Getenv("JWT_SECRET")
```

**快速定位核心操作（L1-L2）：**
- L1：关键词扫描 `jwt.SignedString`、`jwt.ParseWithClaims`、`SigningMethodHS256`
- L2：跳读签名/验证函数，定位密钥来源，检查是否为字符串字面量、全局常量、单次读取的环境变量

**快速定位保护机制（L2-L4）：**
- L2：扫描是否存在密钥管理模块、配置热加载、密钥轮换逻辑
- L3：逐行检查密钥初始化代码，确认是否支持动态更新（如定时刷新、版本化密钥）
- L4：跨模块追踪密钥管理服务调用（KMS、Vault）、密钥版本控制逻辑、多密钥验证机制

## Classify

**漏洞标准：**
- 密钥硬编码在源码中
- 密钥仅在程序启动时读取一次，运行期间无法更新
- 未实现密钥版本化或轮换机制
- 生产环境使用默认/示例密钥

**误报场景：**
- 测试代码或示例代码中的静态密钥
- 已实现外部密钥管理系统（KMS/Vault）但未直接体现在 JWT 签名代码中
- 密钥虽静态但通过其他机制保证安全（如硬件加密模块）

**代码异味：**
- 密钥从配置读取但缺少轮换文档说明
- 使用环境变量但无密钥强度校验
- 单一密钥用于所有用户/场景

## Audit Pro Tips

**深度审计技巧：**

1. **密钥强度与熵分析**
   - 检查密钥长度：HS256 推荐 256 bits (32 字节)，低于 16 字节为严重漏洞
   - 识别弱密钥模式：数字序列、常见单词、默认值、人名等
   - 查看密钥生成方式：是否使用密码学安全的 RNG（如 `rand.Read()`）
   - 样例鉴别：检查 README、示例代码中的密钥是否可能泄露到生产环境

2. **密钥生命周期追踪**
   - 确认密钥初始化位置：启动脚本、main 函数、init 包、配置加载器
   - 验证密钥读取方式：硬编码字面量 > 环境变量 > 本地配置文件 > 远程 KMS
   - 查找密钥修改点：搜索对 JWT 密钥变量的赋值操作，确认是否支持热加载
   - 检查版本控制：git 历史中是否提交过真实密钥，使用 `git log -p` 追踪敏感文件变更

3. **真实漏洞 vs 误报区分**
   - 真实漏洞线索：
     * 密钥硬编码 + 代码在 GitHub/公开仓库中
     * 密钥长度 < 12 字符 + HS256 对称算法
     * 环境变量未设置时有硬编码的默认值作为 fallback
     * Token 有效期 > 30 天且无强制刷新机制
     * 同一密钥用于多个微服务/多个租户

   - 误报信号：
     * 代码注释明确标注为 "example"、"test"、"sample"
     * 密钥由 `crypto/rand` 或 `uuid` 等加密库生成
     * 环境变量使用 `os.Getenv()` 但无硬编码 fallback，且 CI 配置中含密钥注入逻辑
     * 使用了 RS256/RS384/RS512 等非对称算法，硬编码的是公钥而非私钥
     * 有明确的密钥轮换事件日志、版本号或时间戳标记

4. **多密钥场景判断**
   - 搜索是否存在密钥数组/切片：`[]string`、`map[string]string`、slice of structs
   - 验证验证逻辑：是否尝试多个密钥进行验证（允许密钥更新期间的兼容性）
   - 检查版本化机制：token 中是否含 `kid`（Key ID）字段指示使用的密钥版本

5. **外部密钥管理系统检测**
   - 搜索 KMS/Vault 相关依赖：`aws-sdk-go`、`hashicorp/vault`、`google/kms` 等
   - 查找密钥注入入口：`init()`、启动脚本、容器环境变量配置
   - 验证密钥缓存策略：是否有本地缓存且未定期刷新（可能导致密钥过期未更新）

## Low risk

**低风险评定条件：**
- 内部系统，无外部暴露，且网络隔离良好
- 密钥由可信的密钥管理系统生成并注入（即使静态，但强度足够且访问受限）
- 已实施其他补偿控制：短期 token、严格的 IP 白名单、多因素认证
- Token 有效期极短（如 5 分钟内），且有 refresh token 轮换机制
- 仅用于临时开发/测试环境，明确标注非生产用途

## Real Cases

**真实漏洞案例分析：**

1. **案例：123 字符密钥但实际有效长度只有 8 字符**
   - 常见误导：开发者认为密钥长 = 密钥强，但实际使用时只截取前 8 位
   - 审计要点：不仅检查密钥字面量长度，还需检查实际使用时的截取逻辑
   - 验证方法：跟踪密钥传入 SignedString 前是否有 `[:8]`、`substr()` 等截取操作

2. **案例：密钥动态读取但无版本隔离**
   ```go
   // 误区：定期读取新密钥但未隔离旧密钥的有效期
   func RefreshSecret() {
       newSecret := os.Getenv("JWT_SECRET")
       jwtSecret = newSecret  // 直接覆盖，导致已签发的 token 无法验证
   }
   ```
   - 修复标志：应维护密钥版本列表，新密钥生成时旧密钥保留一段时间（grace period）

3. **案例：环境变量未设置时的降级方案**
   ```go
   // 反面示例
   secret := os.Getenv("JWT_SECRET")
   if secret == "" {
       secret = "default-unsafe-key"  // 致命漏洞
   }
   ```
   - 正确做法：若环境变量不存在应报错启动失败，不应有硬编码降级方案

4. **案例：测试密钥泄露到生产**
   - 警示：即使代码中注释标注为 "仅测试"，若密钥实际被编译进二进制，仍需视为真实漏洞
   - 检查方式：运行 `strings` 命令检查编译后二进制中的硬编码字符串

## Audit CheckList

**审计检查清单：**

- [ ] **代码层面**
  - [ ] 搜索所有 `jwt.` 相关函数调用，确认密钥来源
  - [ ] 检查密钥变量是否为导出符号（大写开头），可能被外部代码引用
  - [ ] 验证密钥长度至少 32 字节（256 bits），并检查是否有截取操作
  - [ ] 确认 token 的 `exp`（过期时间）字段存在且不过长（建议 1-24 小时）
  - [ ] 查找是否存在 refresh token 机制与密钥更新的协调逻辑

- [ ] **配置层面**
  - [ ] 确认 `os.Getenv()` 调用没有硬编码 fallback（除非注释明确说明为测试）
  - [ ] 检查配置文件是否被提交到版本控制，且包含生产密钥
  - [ ] 验证容器化部署中环境变量的注入方式（Dockerfile、K8s Secret、CI/CD）
  - [ ] 确认 `.env` 文件在 `.gitignore` 中

- [ ] **运行时层面**
  - [ ] 启动日志是否输出密钥内容或密钥相关信息
  - [ ] Token 生成失败时的错误处理是否泄露密钥信息
  - [ ] 是否有日志打印环境变量值（含密钥）

- [ ] **依赖层面**
  - [ ] 扫描是否集成了密钥管理库（Vault、AWS KMS）
  - [ ] 检查 JWT 库版本是否为已知漏洞版本（如算法绕过漏洞）
  - [ ] 验证是否有密钥轮换相关的第三方库依赖

## Distinguishing Tips

**常见误报排查指南：**

| 信号 | 可能原因 | 排查方法 |
|------|--------|--------|
| 硬编码密钥字符串 | 开发环境 Demo 代码 | 检查 CI/CD 配置，确认该代码分支是否进入生产 |
| 很长的密钥 | 开发者串联了多个密钥或包含版本号 | 分析密钥实际使用逻辑，检查是否有截取操作 |
| 环境变量读取 | 密钥通过外部系统注入 | 跟踪容器启动脚本、K8s manifest、CI/CD pipeline 配置 |
| 注释提到密钥轮换 | 代码中有实现但不明显 | 搜索 `map`、`slice`、`version` 相关结构，查找新旧密钥并存的逻辑 |
| RS256 + 硬编码字符串 | 硬编码的是公钥而非私钥 | 检查字符串内容，`-----BEGIN PUBLIC KEY-----` 是公钥，安全的 |

**高效审计工具命令：**

```bash
# 快速定位 JWT 相关代码
grep -r "jwt\." . --include="*.go" | head -20

# 查找密钥相关的变量定义
grep -r "secret\|key\|SECRET\|KEY" . --include="*.go" | grep -i "var\|const\|="

# 检查 git 历史中是否提交过敏感信息
git log -p -S "secret" | head -100

# 查看编译后二进制中的字符串
strings ./app | grep -i "secret\|key" | head -10

# 检查环境变量的读取和使用
grep -r "os.Getenv" . --include="*.go" -A 3
```
