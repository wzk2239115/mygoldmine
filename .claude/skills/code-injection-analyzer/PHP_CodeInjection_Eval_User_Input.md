# PHP Code Injection - eval() 用户输入执行

## Details

### 核心漏洞代码示例
```php
// 直接执行用户输入 - 严重漏洞
$code = $_GET['code'];
eval($code);

// 拼接用户输入 - 严重漏洞
$expression = "return " . $_POST['expr'] . ";";
eval($expression);

// 动态变量赋值 - 严重漏洞
eval('$' . $_GET['var'] . '=' . $_GET['val'] . ';');

// 创建回调函数 - 严重漏洞
$callback = eval("return function() { " . $_GET['func'] . " };");
$callback();
```

### 快速定位到核心操作的技巧 **[L1:关键词扫描]**
- **直接扫描 eval()、assert()、create_function() 等危险函数**
  - grep 搜索：`eval\s*\(` 、`assert\s*\(` 、`create_function\s*\(`
  - 重点关注传入参数是否包含用户可控数据（GET、POST、COOKIE、FILE 等）

- **识别用户输入源**
  - 跟踪 `$_GET`、`$_POST`、`$_COOKIE`、`$_REQUEST`、`$_FILES`、`$_SERVER` 等超全局变量
  - 检查是否经过数据库查询结果、序列化数据或 JSON 解析

- **识别二阶注入的变量传递**
  - 查找将用户输入保存到数据库/文件的逻辑
  - 追踪这些数据被读取并传入 eval() 的路径

### 快速定位到保护机制的技巧 **[L3:逐行读]**
- **检查输入白名单验证**
  - 是否存在 switch/if-elseif 等确定性的映射关系
  - 是否使用正则表达式进行严格格式校验：`if (!preg_match('/^[a-zA-Z0-9_]+$/', $input))`

- **检查表达式容器隔离**
  - 代码是否被限制在特定的命名空间或类的沙箱内
  - 是否使用 disable_functions 配置限制 eval 可用性（但不可靠）

- **检查间接执行的替代方案**
  - 是否使用 call_user_func()、call_user_func_array() 替代 eval()（仍需验证参数源）
  - 是否使用 preg_replace() 的 /e 修饰符（已废弃但可能存在历史代码）

## Classify

### 漏洞/误报/代码异味的研判标准

**漏洞确认条件**（满足以下任一项即可定为漏洞）：
1. eval/assert/create_function 直接接收用户输入或用户可控数据（无任何验证）
2. 用户输入经过简单字符串检查后被拼接进 eval（如仅检查长度、格式验证不足）
3. 通过数据库/文件存储的用户数据被重新读取并传入 eval（二阶注入）
4. eval 中的代码涉及敏感操作（文件操作、数据库操作、系统命令等）且参数不可信

**误报判断条件**（以下情况可判定为误报）：
1. eval 中仅包含开发者可控的常量或硬编码字符串
2. 用户输入经过严格的白名单验证（如 in_array($input, $whitelist, true)）
3. eval 的执行环境完全隔离（如在沙箱、容器或权限受限的进程中）
4. 代码已使用 disable_functions 禁用 eval（但此手段不够可靠）

**代码异味判断条件**（存在潜在风险但非直接漏洞）：
1. eval 使用但无法完全确认用户输入的流向（需要跨模块追踪）
2. eval 执行的代码来自缓存、临时文件等中间存储（路径注入风险）
3. eval 前存在较弱的验证（如 json_decode 后直接执行，未检查反序列化内容）

## Low risk

### 低风险场景评级指南

以下情况可评定为低风险或安全：

1. **完全静态代码执行**
   - eval 中的所有内容都来自源代码硬编码
   - 不涉及任何动态拼接或变量引用

2. **严格的白名单机制**
   - 使用有限的预定义函数列表（如仅允许调用 array_sum、count 等）
   - 通过 in_array($input, $safe_list, true) 进行精确匹配
   - 白名单列表在代码库中可见且不由用户控制

3. **执行上下文完全隔离**
   - eval 限制在特定的变量作用域内（使用闭包或临时变量）
   - 执行结果不影响全局变量或敏感资源

4. **防御性输入转义**
   - 虽然不推荐，但如果使用了强制的参数化方式（如通过 sprintf 限制格式）
   - 或使用了安全的模板引擎代替手动 eval

5. **已弃用的代码路径**
   - 确认代码不会在生产环境执行（如被注释、条件永不满足）
   - 或已被现代替代方案覆盖且无法到达
