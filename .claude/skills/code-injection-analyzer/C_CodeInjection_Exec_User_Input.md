# C/C++ 代码注入：exec 系列函数用户输入执行

## Details

### 漏洞成因

exec 系列函数（execve、execvp、execl、execlp、execv 等）用于进程替换，直接将用户输入作为命令参数或命令字符串执行时，攻击者可通过特殊字符、环境变量污染或路径遍历等方式执行任意命令。

### 代码示例

```c
// 危险示例：用户输入直接作为 shell 命令
char command[256];
sprintf(command, "ping %s", user_input);
system(command);  // 若底层使用 execl("/bin/sh", "sh", "-c", command, NULL)

// 危险示例：argv 数组包含用户数据
execv("/bin/sh", argv);  // argv[1] 来自网络输入

// 危险示例：exec 与环境变量污染
execvp("utility", argv);  // PATH 环境变量未清理
```

### 快速定位核心操作 `[L1:关键词扫描]`

- 搜索 exec 族函数：execve、execvp、execl、execlp、execv、execle、execvpe
- 关键特征标记：
  - 函数参数中包含用户可控变量（来自网络、文件、环境变量等不可信源）
  - 使用 "-c" 参数调用 shell 包装器（/bin/sh, /bin/bash）
  - argv 数组动态构造或外部传入
- 示例搜索模式：
  ```
  execl\s*\(\s*["/].*sh  // shell 包装器
  execv\s*\([^,]+,\s*argv|user_input|data
  ```

### 快速定位保护机制 `[L2:跳读]`

**参数验证层：**
- 检查 exec 调用前是否存在输入验证函数
- 白名单检查：固定的命令集合或枚举值
- 字符过滤：禁止特殊字符（`;`, `|`, `&`, `$`, 反引号、`>`, `<`, `(`, `)` 等）
- 长度限制：参数长度上限约束

**执行环境隔离：**
- 环境变量清理：clearenv()、unsetenv() 或显式设置 envp 参数
- 工作目录切换：chdir() 到受控目录
- 权限降级：setuid()、setgid()、setresuid() 等
- 进程隔离：setrlimit()、pledge()、seccomp 等沙箱机制

**执行模式检查：**
- 直接模式：execve(绝对路径, 完全受控的 argv, 清理后的 envp)
- Shell 模式：使用 "-c" 参数时，参数必须通过严格白名单或完整验证

## Classify

### 漏洞判定理论

**确定为漏洞的必要条件：**
1. 用户输入可达 exec 函数参数
2. 参数内容未经充分验证或验证机制可绕过
3. 执行环境允许任意命令执行（如环境变量污染、PATH 搜索等）

**判定流程：**
- **源头追踪**：用户输入来自网络、文件、环境变量等外部源 → 继续分析
- **验证评估**：
  - 完整白名单覆盖所有分支 → 低风险或误报
  - 仅黑名单或不完整验证 → 漏洞
  - 无验证 → 漏洞
- **执行模式分析**：
  - Shell 模式（"-c"）+ 用户数据 → 高危
  - 直接模式（execve）+ 内部构造 → 低危
- **环境隔离评估**：
  - 完整隔离（环境清理、权限降级、沙箱）→ 降低风险等级
  - 环境污染风险 → 提升风险等级

**误报的典型特征：**
- 参数为编译时常量，无用户数据流入
- exec 调用的路径和参数来自内部逻辑生成，源头可追溯无外部输入
- 虽有 exec 调用但参数完全由应用逻辑控制，用户仅能选择预设命令

**代码异味的识别：**
- exec 调用参数来源不明确，需深入追踪
- 多层函数调用链，用户输入在中间环节流入（L4:跨模块追踪 需求）
- 存在条件分支动态选择命令或参数
- 环境变量未显式清理或白名单机制不完整

## Low risk

### 低风险评级场景

**场景一：完整参数白名单**
- exec 函数参数值范围严格限定于预定义的安全命令集合
- 白名单基于业务功能需求完整设计，覆盖所有代码分支
- 用户输入仅用于索引或选择白名单项，不作为参数内容本身
- 评级依据：参数空间有限且完全受控，攻击面消除

**场景二：直接程序执行模式**
- 使用 execve 指定绝对路径程序（如 "/usr/bin/curl"）
- argv 数组通过应用内部流程构造，无用户数据混入
- envp 参数已清理或采用最小化的安全环境变量集合
- 评级依据：绕过 PATH 搜索的路径污染，环境变量隔离消除环境攻击面

**场景三：严格的权限和上下文限制**
- exec 调用的代码仅在特定系统用户权限下执行（如 nobody、专用服务账户）
- 部署环境中该代码在容器或虚拟机内运行，容器进程隔离限制了影响范围
- 命令执行失败的影响范围有限（如仅影响当前会话，无法持久化）
- 评级依据：执行权限受限和环境隔离降低了漏洞利用的实际风险

**场景四：严格的参数内容约束**
- 用户输入的字符集严格限制于安全子集（如数字、字母、点、连字符）
- 参数长度有明确上限约束，防止缓冲区溢出和超长参数注入
- 参数值经过规范化处理（移除特殊含义的字符序列或转义处理）
- 评级依据：参数内容高度约束，特殊字符禁用消除了 shell 元字符利用

**场景五：多层防护组合**
- 虽未达成完整白名单，但包含多个防御层的联合防护
- 例：路径绝对化 + 字符过滤（移除 `;`, `|`, `&`) + 环境变量清理 + 权限降级
- 各防护层独立有效，联合作用覆盖了常见利用手段
- 评级依据：纵深防御和多层控制提升了攻击难度，综合风险降低

### 评级决策补充

- 仅参数白名单而环境变量污染存在 → 中等风险（非低风险）
- 参数经过部分过滤（黑名单）且存在绕过可能 → 中等风险或高风险（非低风险）
- 单一防护层有效但缺乏纵深防御 → 评估为中等风险（除非白名单完整）
