# 通用代码注入漏洞审计小抄

任何涉及代码执行或动态代码加载的应用都必须审计以下漏洞模式。这些问题源于不安全的代码执行方式，与编程语言无关。

## 1. 直接代码执行与评估

### eval/exec 函数滥用

**危险代码特征**

```python
user_code = request.get('code')
eval(user_code)  # 直接执行用户代码
```

**快速定位**（L1: 关键词扫描）：
- 搜索危险函数：`eval()`、`exec()`、`System.compile()`、`compile()`、`eval()`
- Python：`eval()`、`exec()`、`compile()`
- PHP：`eval()`、`assert()`、`create_function()`
- JavaScript：`eval()`、`Function()`、`new Function()`
- Java：`ScriptEngine`、`GroovyShell`、`MvelEngine`

**快速定位保护机制**（L2-L3: 跳读/逐行读）：

- **沙箱隔离**（L2）：检查是否在沙箱环境中执行代码（如 Python RestrictedExecution）
- **黑名单限制**（L2）：查看是否限制了危险函数（`__import__`、`exec`、`os.system` 等）
- **代码检查**（L3）：分析用户代码是否经过静态分析或白名单验证
- **完整链路**（L4）：追踪用户代码从输入到执行的完整过程

---

## 2. 表达式与模板注入

### EL/SpEL 表达式注入

**危险模式**

- Java JSP EL：`${user_input}`
- Spring SpEL：`#{user_input}`
- 模板引擎动态表达式求值

**快速定位保护机制**（L2-L3: 跳读/逐行读）：
- **表达式禁用**（L2）：检查模板引擎是否禁用了表达式评估
- **变量隔离**（L2）：查看上下文中暴露的对象是否包含危险类或方法
- **反射限制**（L3）：检查是否限制了反射调用、方法调用等危险操作

---

## 3. 动态导入与加载

### 模块/类加载注入

**危险代码特征**
- Python：`__import__(user_input)`、`importlib`
- Java：`Class.forName(user_input)`
- C：`dlopen(user_input)`

**快速定位保护机制**（L2-L3）：

- **白名单限制**（L2）：检查导入/加载的模块或类是否通过白名单验证
- **路径校验**（L3）：检查加载路径是否进行了验证，防止目录穿越

---

## 4. 反序列化注入

### 不安全的反序列化

**危险模式**

- Python：`pickle.loads()`、`cPickle.loads()`
- PHP：`unserialize()`
- Java：`ObjectInputStream.readObject()`
- YAML：`yaml.load()`

---

## 5. 研判标准

### 确认为漏洞

**必须满足**
1. 用户输入被用于代码执行或动态加载
2. 未进行代码检查、沙箱隔离或白名单验证
3. 攻击者可执行任意代码（RCE）
4. 造成系统被完全控制

**特殊场景**
- SQL 注入可导致代码执行（如 MySQL UDF）
- SSTI（模板注入）可导致 RCE
- 反序列化可通过 Gadget Chain 导致 RCE

### 判定为误报

**如果满足以下情况之一，可判定为误报**
1. **沙箱隔离**：代码在严格隔离的沙箱环境执行
2. **白名单限制**：仅允许预定义的操作或模块
3. **类型验证**：用户输入已进行严格类型验证
4. **权限最小**：执行环境权限受限，无法访问敏感资源

---

## 6. 低风险指标

### 以下情况应给予低风险评级

1. **沙箱隔离**：代码在容器或进程隔离中执行
2. **完整白名单**：仅允许特定的预定义操作
3. **权限限制**：执行用户权限受限，无法访问系统资源
4. **防御深度**：即使代码被注入，也无法获取敏感数据或执行危险操作
5. **监控告警**：存在代码执行的审计日志和告警机制
