# Python eval() 代码注入

**漏洞成因**：使用 `eval()` 函数直接执行用户输入的代码字符串，常见于动态表达式计算、规则引擎、配置解析等场景。`eval()` 具有完整的 Python 语法支持和全局/局部命名空间访问权限，攻击者可执行任意 Python 代码。

---

## Details

**代码示例**：
```python
# 危险：直接执行用户输入
user_expr = request.args.get('expr')
result = eval(user_expr)

# 危险：eval 配合格式化字符串
user_input = request.form.get('math')
eval(f"x = {user_input}; print(x)")

# 危险：eval 在全局命名空间中执行
code_str = "import os; os.system('rm -rf /')"
eval(code_str)

# 虚假安全：限制命名空间的 eval（仍可绕过）
eval(user_input, {"__builtins__": {}})  # 仍可访问对象方法
```

**快速定位核心操作**（L1-L2）：
- 关键词：`eval(`、`exec(`、`compile(` 等代码执行函数调用
- 查看被执行字符串是否包含用户输入（直接参数或拼接/格式化）
- 检查是否存在字符串拼接、f-string、format 等动态构造
- 追踪用户输入来源：`request.args`、`request.form`、`request.json`、环境变量、文件、数据库

**快速定位保护机制**（L2-L3）：
- 是否使用限制的命名空间：`eval(code, {}, {})`、`eval(code, {"__builtins__": {}})`
- 是否存在白名单校验：允许的操作符、变量、函数列表
- 是否使用 AST 解析代替 eval：`ast.literal_eval()` 只支持字面量
- 是否存在长度限制、特殊字符过滤（易绕过）

**审计等级**：**L2-L4**
- **L2**：跳读含有 eval 的代码块，快速确认用户输入来源
- **L3**：逐行读取 eval 及其参数构造，确认防护机制（如果有）
- **L4**：跨模块追踪用户输入到 eval 的完整数据流，检查所有转换点

---

## Classify

**确认为漏洞**：
- 用户输入直接或间接作为 eval 的第一个参数
- 无防护或防护可绕过（如仅过滤部分字符）
- 即使使用限制命名空间，仍可通过对象属性访问（如 `().__class__.__bases__[0].__subclasses__()` 绕过）

**误报**：
- eval 仅执行硬编码常量字符串
- eval 仅用于 `ast.literal_eval()` 等安全函数（仅支持 Python 字面量）
- 用户输入被严格白名单限制（如仅允许 `+`, `-`, `*`, `/` 等操作符）

**代码异味**：
- eval 存在但有防护（如限制命名空间），但防护机制未经充分验证
- eval 仅在管理员界面使用，但权限控制依赖前端或 session
- 业务功能可用 `ast.literal_eval()` 或表达式解析库替代

---

## Low Risk

以下情况可评为低风险：
- **受限执行环境**：虚拟机/容器内执行，无敏感操作权限（如无网络、无文件写权限）
- **权限受限**：执行代码权限受限，无法访问敏感库（如已删除 `__builtins__` 且不可恢复）
- **内网隔离**：仅限管理员、内网、或特定 IP 段访问
- **输入严格限制**：虽接受用户输入但限制在固定集合（如仅支持预定义的表达式）
- **审计日志完整**：所有 eval 执行被完整记录、监控
