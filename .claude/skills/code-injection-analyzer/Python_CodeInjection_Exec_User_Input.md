# Python exec() 代码注入

**漏洞成因**：使用 `exec()` 函数执行用户可控的代码字符串，常见于命令执行、动态脚本加载、批量操作等场景。与 `eval()` 不同，`exec()` 无返回值但可执行任意 Python 语句（包括导入、函数定义等），攻击者可执行完整的恶意程序。

---

## Details

**代码示例**：
```python
# 危险：直接执行用户输入
user_code = request.form.get('code')
exec(user_code)

# 危险：exec 与字符串拼接
template = "x = " + user_input + "; print(x)"
exec(template)

# 危险：exec 在 locals 变量中直接修改全局状态
exec("import os; os.system('whoami')")

# 虚假安全：限制命名空间的 exec（仍可通过对象访问绕过）
exec(user_code, {"__builtins__": {}})
```

**快速定位核心操作**（L1-L2）：
- 关键词：`exec(`、`exec ` (Python 2 语法)、`eval(` 相关调用
- 查看被执行字符串来源：直接用户输入、字符串拼接、格式化、f-string
- 检查是否涉及代码块执行：多行语句、语句组合、逻辑控制
- 追踪数据流：`request.files`、`request.form`、数据库查询、文件读取

**快速定位保护机制**（L2-L3）：
- 是否使用受限命名空间：`exec(code, restricted_globals, restricted_locals)`
- 是否存在代码合法性验证：AST 检查、语法树遍历、危险操作符过滤
- 是否采用白名单方式：仅允许特定的模块导入、函数调用
- 是否使用了沙箱库（如 RestrictedPython、Pydantic）

**审计等级**：**L2-L4**
- **L2**：跳读含有 exec 的代码块，快速确认参数来源
- **L3**：逐行读取 exec 及其参数，检查是否存在防护机制
- **L4**：跨模块追踪用户数据到 exec 的完整流程

---

## Classify

**确认为漏洞**：
- 用户输入直接或间接作为 exec() 的参数
- 无防护或防护机制可绕过（限制命名空间可通过 `__class__` 等方式绕过）
- 多行代码执行，攻击面更大

**误报**：
- exec() 执行硬编码字符串常量
- exec() 仅在调试/REPL 模式下使用（非生产环境）
- 用户输入被严格白名单限制（如仅允许数字、基本操作符）

**代码异味**：
- exec() 存在但有部分防护（需详细评估防护有效性）
- 权限控制依赖会话或前端验证
- 业务可用 `eval()` 等更安全的替代方案

---

## Low Risk

以下情况可评为低风险：
- **受限执行环境**：容器/沙箱内执行，无敏感操作权限
- **权限隔离**：执行用户权限极低，无法访问敏感文件、网络
- **内网保护**：仅限内部用户、管理员、或特定 IP 段
- **输入严格限制**：虽接受输入但限制在固定的安全操作集合
- **执行时间限制**：使用 signal 或 timeout 机制限制执行时间，防止死循环
