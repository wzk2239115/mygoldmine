# Python __import__() 动态导入注入

**漏洞成因**：使用 `__import__()` 或 `importlib` 动态导入用户可控的模块名称，常见于插件系统、模块加载器、配置驱动的模块导入等场景。攻击者可通过构造恶意模块名称（如相对导入、绝对导入、../遍历等）导入任意模块或执行其中的代码。

---

## Details

**代码示例**：
```python
# 危险：直接导入用户输入的模块名
module_name = request.args.get('module')
mod = __import__(module_name)

# 危险：importlib 动态导入
import importlib
user_module = request.form.get('mod_name')
module = importlib.import_module(user_module)

# 危险：字符串拼接构造模块名
lib = __import__("lib_" + user_input)

# 危险：目录遍历绕过限制
# 如果限制了模块名，仍可通过相对导入绕过
import_name = request.args.get('plugin')  # 假设限制为 'plugin_*'
# 但可输入 '../evil_module' 绕过
module = __import__('plugins.' + import_name)
```

**快速定位核心操作**（L1-L2）：
- 关键词：`__import__(`、`importlib.import_module(`、`importlib.import_all`
- 查看导入的模块名是否来自用户输入
- 检查是否涉及字符串拼接、格式化、动态构造
- 追踪导入来源：`request.args`、`request.form`、配置文件、数据库

**快速定位保护机制**（L2-L3）：
- 是否使用白名单限制模块名：固定列表或正则匹配
- 是否禁止相对导入、点号（`.`）、斜线（`/`）等特殊字符
- 是否存在路径检查：防止目录遍历（`..`）
- 是否验证导入后的模块来源：文件路径检查

**审计等级**：**L2-L4**
- **L2**：跳读导入语句，确认模块名来源
- **L3**：逐行读取导入参数及其构造、白名单验证
- **L4**：跨模块追踪用户输入到导入的完整流程

---

## Classify

**确认为漏洞**：
- 用户输入直接或间接作为模块名
- 无白名单限制或白名单可绕过（允许点号、斜线等）
- 相对导入或目录遍历（`..`）未被禁用

**误报**：
- 模块名为硬编码常量
- 模块名来自受信任源（硬编码配置、本地文件）
- 存在严格的白名单（仅允许固定的几个模块）

**代码异味**：
- 导入存在但有部分防护（需评估白名单完整性）
- 权限控制依赖前端或会话验证
- 可用配置文件或枚举替代动态导入

---

## Low Risk

以下情况可评为低风险：
- **受限模块目录**：导入路径限制在特定目录，无法加载系统模块
- **权限隔离**：导入的模块在最小权限用户下执行
- **内网保护**：仅限管理员、开发者、或内网访问
- **严格白名单**：模块名限制在固定的预定义模块集合
- **导入监控**：所有动态导入被完整审计、监控、记录
