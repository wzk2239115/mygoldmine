# PHP Code Injection - Include/Require with User Input

## Details

### 核心漏洞原理
PHP 的 `include` 和 `require` 语句用于加载并执行文件。当文件路径由用户可控数据构成时，攻击者可通过目录遍历或文件上传等方式引入恶意代码。主要风险：
- 远程代码执行（RCE）：通过 Local File Inclusion (LFI) 包含上传文件或临时文件
- 本地文件包含：读取敏感文件内容（如配置文件、数据库凭证）
- 日志投毒：利用可写日志文件进行代码注入

### 代码示例与审计方向

**示例1：直接用户输入拼接路径**
```php
$page = $_GET['page'];
include($page . '.php');  // 核心风险操作
```
**快速定位技巧（L1:关键词扫描）**：搜索 `include`, `require`, `include_once`, `require_once` 关键字及其后续的变量来源追踪。

**示例2：带局部限制的不完全防护**
```php
$page = basename($_GET['page']);  // 存在防护
include('pages/' . $page . '.php');  // 核心风险操作
```
**保护机制识别（L2:跳读）**：识别 `basename()`, `pathinfo()`, `realpath()`, `preg_match()` 等防护函数是否真正有效。`basename()` 无法防止目录遍历（如 `../../../etc/passwd`），需检查：
- 白名单机制是否存在
- 是否使用了 `open_basedir` 限制
- 文件路径是否通过 `realpath()` 规范化并验证

**示例3：带文件包含条件判断**
```php
$action = $_POST['action'];
if (in_array($action, ['login', 'register', 'profile'])) {
    include('handlers/' . $action . '.php');  // 核心风险操作
}
```
**保护机制识别（L3:逐行读）**：审查白名单数组的完整性、是否穷尽了所有可能的值、白名单是否可被绕过（如大小写、类型转换）。

**示例4：跨模块的用户输入追踪**
```php
// config.php
$config_file = $_SERVER['HTTP_HOST'];  // 用户可控
$template_dir = 'templates/';

// index.php
include $template_dir . $config_file . '/header.php';  // 核心风险操作
```
**跨模块追踪（L4:跨模块追踪）**：追踪用户输入来源（GET/POST/HTTP头/文件上传），识别中间转换（序列化、反序列化）是否保持可控性，检查全局变量和配置文件中的间接注入点。

## Classify

### 漏洞 vs 误报 vs 代码异味

**确认为漏洞的条件：**
1. 存在 `include`/`require` 语句的文件路径由用户直接或间接控制
2. 未存在有效的文件路径白名单验证
3. 可被证明存在攻击向量（目录遍历、上传文件包含、日志投毒等）
4. 路径限制不足（如仅使用 `basename()` 而无后续验证）

**判断为误报的条件：**
1. 文件路径使用硬编码或仅通过受控枚举构成（如明确的 `switch` 语句处理所有分支）
2. 存在完整的白名单验证，且白名单通过逻辑证明穷尽所有合法输入
3. 配合 `open_basedir` 等 PHP 级别的路径限制
4. 文件仅在临时或不可执行目录（无代码执行风险）

**判断为代码异味的条件：**
1. 存在防护机制但防护不完整（如 `basename()` 结合多重 `../`）
2. 白名单存在但存在逻辑漏洞（如类型强制转换绕过）
3. 只在特定条件下触发的包含（如特定用户角色、特定时间窗口）
4. 防护依赖外部配置而非代码内置验证

## Low risk

### 低风险评级的理由与场景

**风险等级降低的情形：**
1. **完整的白名单验证**：通过 PHP 数组或数据库预定义合法文件列表，使用 `in_array()` 严格比对（非弱类型）
2. **路径规范化验证**：使用 `realpath()` 获取真实路径后，与预期基础目录进行 `strpos()` 验证，确保结果在安全范围内
3. **受限执行环境**：配置 `open_basedir` 限制包含路径范围，使目录遍历无法突破设定目录
4. **非代码包含**：包含的文件仅为数据文件（配置数组、JSON 数据）而非 PHP 代码，且文件内容由管理员控制
5. **多层防御叠加**：白名单验证 + 路径规范化 + 文件存在性检查 (`file_exists()`) + 权限检查 (`is_readable()`)
6. **隔离式上传处理**：用户上传文件存储在完全隔离的目录（如 `/uploads/hash_uuid/`），且该目录配置为不可直接执行 PHP，仅作为数据存储

**审计建议**：即使满足上述条件之一，仍需检查防护的有效性和实现的完整性，防止编码错误或逻辑缺陷破坏防护机制。
