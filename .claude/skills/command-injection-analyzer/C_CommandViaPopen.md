# C_CommandViaPopen - popen() 命令注入审计

## Details

**代码特征：**
```c
FILE *fp = popen(command, "r");  // 或 "w" 模式
pclose(fp);
```

**快速定位核心操作：**
- 搜索关键词：`popen(`、`_popen(`（Windows）
- 检查第一个参数是否存在字符串拼接、sprintf、snprintf、strcat 等操作
- 回溯拼接来源，判断是否包含外部输入（argv、getenv、文件读取、网络接收等）

**快速定位保护机制：**
- 是否存在白名单校验（如：枚举允许的命令列表）
- 是否使用参数化数组（但 popen 本身不支持，需改用 execv 系列）
- 是否对特殊字符进行过滤（`;`、`|`、`&`、`$`、`` ` ``、`\n`、`(`、`)`）
- 是否使用绝对路径且避免空格

**审计等级：L3（逐行读）**  
popen 直接调用 `/bin/sh`，拼接用户输入必然存在高风险，需逐行追踪数据流。

## Classify

**✅ 确认漏洞：**
- 用户可控输入直接或间接拼接到 popen 参数中
- 过滤不完整（仅过滤部分特殊字符，如只过滤 `;` 但未过滤 `|`、`\n` 等）
- 使用黑名单过滤但可被绕过（如未处理换行符、IFS 变量、通配符等）

**❌ 误报：**
- popen 参数完全硬编码，无任何外部输入
- 输入经过严格白名单校验（枚举固定值，且白名单不可突破）

**⚠️ 代码异味：**
- popen 参数部分硬编码 + 部分变量，但变量来自配置文件（需进一步确认配置来源可信度）
- 虽有过滤但实现粗糙（如简单替换而非拒绝）

## Low risk

- 输入来源为配置文件且配置文件需要 root 权限修改（仍需在报告中提及风险）
- 命令执行结果不可见且无副作用（如仅用于触发内部进程通信）
- 运行在隔离容器内且进程权限极低（UID 限制、无网络权限）
- 输入长度严格限制（<8 字符）且强制字母数字（仍存在理论风险但利用难度极高）

**注意：** 即使评为低风险，popen 本身的设计就不适合处理外部输入，建议在审计报告中标注为"设计缺陷"。
