
**通用命令注入缺陷模式（所有项目必审）**

拿到任何涉及外部命令执行的项目，无论使用何种编程语言，以下命令注入缺陷模式都必须进行审计。这些问题源于不安全的命令执行方式，与具体语言实现无关。

**直接拼接用户输入到命令字符串**

将用户输入直接拼接到命令字符串中执行，包括：
- 字符串拼接或格式化嵌入用户输入，如 `cmd = "ls " + user_input` 或 `f"grep {pattern} file.txt"`
- 使用模板字符串或字符串插值构造命令，未进行任何验证或转义
- 动态构造命令路径或命令名称包含用户输入，如根据用户选择执行不同命令

**使用 Shell 模式执行命令**

使用 shell 模式（如 shell=True、sh -c、bash -c）执行命令时，shell 会解析特殊字符和元字符，导致注入：
- 使用 shell=True 或类似参数执行命令，Python subprocess.Popen(..., shell=True)
- 通过 sh -c 或 bash -c 执行动态构造的命令字符串，如 `/bin/sh -c "cmd + user_input"`
- 使用管道、重定向等 shell 特性时未隔离用户输入

**特殊字符未过滤或转义**

未对 shell 特殊字符进行过滤、转义或白名单验证，常见注入方式：
- 分号 (;) 用于分隔多条命令
- 管道符 (|) 用于传递命令输出
- 逻辑运算符 (&&、||) 用于条件执行
- 命令替换 ($()、反引号) 用于嵌套执行
- 重定向符号 (<、>、>>) 用于读写文件
- 后台执行符号 (&) 用于后台运行命令

**未使用参数化命令执行**

未使用参数数组或参数化方式传递命令参数，而是构造整个命令字符串：
- 将命令和参数混在一个字符串中传递，而非使用 `execve(cmd, [arg1, arg2])` 这样的分离方式
- 未使用参数列表（argv）方式传递参数，导致 shell 元字符被解析
- 命令执行 API 使用不当，如 PHP `exec()` 代替 `escapeshellarg()` 保护

**环境变量注入**

通过注入或污染环境变量来影响命令执行行为：
- PATH 环境变量污染，注入恶意目录路径
- LD_PRELOAD 注入，在 Linux 中预加载恶意共享库
- LD_LIBRARY_PATH 注入，指定恶意库搜索路径
- IFS（内部字段分隔符）变量污染，绕过命令解析防护
- 其他环境变量注入（如 LANG、TZ、HOME 等）

**通配符展开注入**

Shell 的文件名展开（glob expansion）机制被利用来注入命令参数：
- 星号 (*) 通配符展开，特殊文件名被展开为注入参数
- 问号 (?) 通配符展开，单字符匹配被利用
- 大括号展开 ({}) 注入，bash 中的大括号展开被利用
- 波浪线 (~) 展开注入，用户主目录展开被利用
- 方括号 ([]) 字符类展开，字符集匹配被利用

**输入验证不足**

对用户输入的验证不充分或使用了不安全的验证方式：
- 仅使用黑名单过滤特殊字符（如删除 `;` 和 `|`），可通过编码（`%3b`）、大小写变化或其他方式绕过
- 白名单验证不严格，只检查前缀或文件扩展名，允许部分危险字符通过
- 未验证命令参数的类型、格式或取值范围，如允许任意路径而不检查目录遍历
