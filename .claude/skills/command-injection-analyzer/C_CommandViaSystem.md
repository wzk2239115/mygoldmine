# C_CommandViaSystem - system()命令注入

## Details

**典型代码模式：**
```c
char cmd[256];
sprintf(cmd, "ping -c 4 %s", user_input);  // 直接拼接用户输入
system(cmd);  // 调用system执行
```

**快速定位核心操作：**
- 关键函数：`system()`、`popen()`
- 搜索模式：`system\s*\(.*%s`、字符串拼接后传入system
- 数据流追踪：argv、环境变量、网络输入 → sprintf/strcat/snprintf → system()

**快速定位保护机制：**
- 白名单校验：`if (strcmp(input, "allowed") == 0)`
- 字符过滤：检查是否过滤了 `;|&$()<>\``
- 参数化调用：是否使用 `execve()`/`execl()` 等不调用shell的API
- 沙箱机制：检查是否有chroot、seccomp、capability限制

**审计等级：L3-L4（逐行读-跨模块追踪）**  
需要逐行追踪数据流，确认用户输入到system()的完整路径，检查中间是否有有效过滤。

## Classify

**确认为漏洞：**
- 用户可控输入直接/间接拼接到system()参数，且无有效过滤
- 可控输入来自：HTTP参数、文件内容、环境变量、命令行参数
- 过滤不充分：仅过滤空格/特定命令，但未过滤元字符 `;|&`

**误报/代码异味：**
- system()参数完全硬编码，无任何外部输入
- 用户输入经过严格白名单校验（如：`^[a-zA-Z0-9._-]+$`）且应用场景限定
- 已使用 `execve()`/`execl()` 等安全API替代，但变量命名误导

**边界情况：**
- 间接注入：用户输入先写入配置文件，后续被system()读取执行（仍为漏洞）
- 环境变量注入：`$PATH`、`$LD_PRELOAD` 被污染（降级为中危或配置问题）

## Low risk

**以下情况可降低风险评级：**
- 输入已被限制在有限字符集（纯数字、字母），且长度严格限制（< 32字符）
- 执行上下文为低权限用户，且已启用SELinux/AppArmor强制访问控制
- 仅用于内部管理工具，不对外暴露接口，且需多因素认证
- 已有日志审计机制，能及时发现异常命令执行
- 业务场景限制：仅处理可信来源数据（如：本地配置文件，非用户可编辑）

**注意：** 即使低风险，仍建议重构为安全API（execve等），从根本上消除命令注入可能性。
