# Python os.system() 命令注入

**漏洞成因**：通过 `os.system()` 函数直接执行包含用户输入的 shell 命令字符串，常见于自动化部署、数据处理、批量操作、文件转换、系统监控等业务场景。

---

## Details

**代码示例**：
```python
import os

# 危险：直接拼接用户输入
filename = request.args.get('file')
os.system('cat ' + filename)
os.system(f'ls -la {user_path}')
os.system('ping -c 4 %s' % host)

# 危险：动态命令构造
cmd = f"convert {input_file} output.png"
os.system(cmd)
```

**快速定位核心操作**：
- 关键词：`os.system(`、`import os`
- 查看参数是否包含字符串拼接（`+`、f-string `f"...{var}..."`、`%s` 格式化、`.format()`）
- 重点关注 shell 特殊字符：`;`、`|`、`&`、`&&`、`||`、`$(...)`、`` `...` ``、`\n`
- 追踪命令字符串的数据流，定位用户输入来源（request、form、query、json、环境变量、外部 API）

**快速定位保护机制**：
- 是否使用 `subprocess` 模块代替 `os.system()`：`subprocess.run([cmd, arg1, arg2], shell=False)`
- 是否存在白名单校验：正则匹配 `re.match(r'^[a-zA-Z0-9_-]+$', input)`、枚举值、字典映射
- 是否使用 `shlex.quote()` 转义参数（Python 3.3+）或 `pipes.quote()`（Python 2）
- 是否限制可执行命令范围：路径白名单、命令白名单、参数白名单

**审计等级**：**L3-L4**  
- **L3**：逐行读取 os.system 调用上下文，确认参数来源和拼接方式
- **L4**：跨模块追踪用户输入到 os.system 调用的完整数据流，检查所有校验点和数据转换

---

## Classify

**确认为漏洞**：
- 用户输入直接或间接参与命令字符串拼接
- 未对特殊字符进行转义或过滤
- 过滤不完整（仅黑名单部分特殊字符，可通过其他字符绕过）
- 白名单校验存在逻辑缺陷（路径遍历 `../`、二次编码、换行符注入）

**误报**：
- 命令字符串完全硬编码，无任何动态部分
- 用户输入仅用于选择预定义命令（通过字典/枚举映射，键值严格校验）
- 存在严格的正则白名单或 `shlex.quote()` 转义，用户输入被完全限制在安全范围

**代码异味**：
- 存在校验但不够严格（黑名单过滤、简单字符串替换 `replace(';', '')`）
- 使用 os.system 但业务逻辑可用 Python 标准库替代（如 `shutil`、`pathlib`、`requests`）
- 权限控制依赖前端校验或弱认证机制
- 注释标注"临时实现"或"待重构"但长期未修复

---

## Low Risk

以下情况可评为低风险，但仍建议修复：
- **受限执行环境**：Docker 容器无特权运行、AppArmor/SELinux 强制访问控制、chroot 沙箱
- **内网隔离接口**：仅限内网/管理员访问，有二次认证（MFA、堡垒机、IP 白名单）
- **业务价值低**：开发/测试环境、POC 验证代码、已下线功能、日志查询工具
- **影响范围小**：仅能执行只读命令（如 `ls`、`cat`、`grep`），无法写入文件或建立网络连接
- **存在部分防护**：输入长度限制（如 `len(input) < 20`）、命令执行超时、审计日志、异常监控告警

**注意**：低风险≠可忽略，需结合实际部署环境、数据敏感度和攻击面综合判断。优先建议使用 `subprocess` 模块的参数化调用。
