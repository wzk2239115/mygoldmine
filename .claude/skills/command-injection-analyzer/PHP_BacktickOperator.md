# PHP 反引号运算符命令注入

**审计等级：L3（逐行读）**  
常出现在文件管理、备份恢复、图像处理、第三方服务调用等业务场景。

---

## Details

### 漏洞成因
PHP 反引号运算符（`` ` ``）直接执行 shell 命令，等同于 `shell_exec()`。用户输入未过滤直接拼接到反引号内时触发命令注入。

### 代码示例
```php
// 危险模式 1：直接拼接超全局变量
$file = $_GET['filename'];
$output = `cat /var/log/$file`;

// 危险模式 2：变量传递后拼接
$dir = $_POST['directory'];
$cmd = "ls -la " . $dir;
$result = `$cmd`;

// 危险模式 3：字符串插值
$backup = $_REQUEST['path'];
$size = `du -sh $backup`;
```

### 快速定位核心操作
1. **全局搜索**：查找反引号 `` ` `` 或 `shell_exec()`（功能等价）
2. **变量追踪**：检查反引号内是否含变量（`$`符号）
3. **来源确认**：回溯变量是否源自：
   - `$_GET` / `$_POST` / `$_REQUEST` / `$_COOKIE`
   - 数据库查询结果（需进一步追踪写入点）
   - 文件读取内容（需确认文件可控性）

### 快速定位保护机制
1. **参数过滤**：
   - `escapeshellarg()`：包裹单个参数（推荐）
   - `escapeshellcmd()`：转义整个命令（较弱，可能参数注入）
2. **白名单验证**：
   - `in_array($input, ['opt1', 'opt2'])`：枚举白名单
   - `preg_match('/^[a-zA-Z0-9_.-]+$/', $input)`：字符集白名单
3. **配置限制**：检查 `php.ini` 中 `disable_functions` 是否禁用反引号

---

## Classify

### 🔴 漏洞（Vulnerability）
- 用户输入**直接拼接**无任何过滤
- 仅黑名单过滤（如只过滤 `;` `|` `&`，易被 `$()` `\n` 绕过）
- 仅使用 `htmlspecialchars()` 等 XSS 防护函数（对命令注入无效）

### ⚪ 误报（False Positive）
- 反引号内为**纯硬编码**字符串（如 `` `date +%s` ``）
- 变量来自**常量/配置文件**（如 `define('BASE_PATH', '/var/www')`）
- 已通过**严格白名单**且逻辑无误（需人工复核白名单合理性）

### 🟡 代码异味（Code Smell）
- 仅用 `escapeshellcmd()` 未用 `escapeshellarg()`（存在参数注入风险）
- 白名单正则**过于宽松**（如允许 `*` `?` 等 shell 通配符）
- 过滤逻辑**分散在多处**，难以验证完整性

---

## Low risk

以下情况可评为**低风险**，但仍需记录：

1. **权限限制**：仅管理员/超级用户可访问（需验证鉴权逻辑可靠性）
2. **严格过滤**：
   - 使用 `escapeshellarg()` 正确包裹每个用户输入参数
   - 白名单限制为字母数字下划线：`/^[a-zA-Z0-9_]+$/`
3. **环境隔离**：
   - 容器/沙箱环境运行（Docker、chroot）
   - Web 服务器用户权限极低（如 www-data，禁止写敏感目录）
4. **功能禁用**：`php.ini` 已设置 `disable_functions=shell_exec,passthru,exec`（需确认反引号同步禁用）
5. **输入约束**：长度限制 ≤ 16 字符且仅允许字母数字

**⚠️ 注意**：低风险不等于无风险，需结合业务场景综合研判。
