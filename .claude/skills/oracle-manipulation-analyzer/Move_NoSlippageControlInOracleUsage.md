# Move_NoSlippageControlInOracleUsage

**漏洞类型**：预言机使用无滑点控制  
**影响范围**：Aptos/Sui 生态中的资产定价、清算、杠杆交易、流动性挖矿等场景  
**风险等级**：High

## Details

**代码示例**：
```move
public fun swap_with_oracle(
    account: &signer,
    oracle: &Oracle,
    amount_in: u64
) {
    let price = oracle::get_price(oracle);  // 直接使用预言机价格
    let amount_out = amount_in * price / PRECISION;
    transfer_tokens(account, amount_out);  // 无滑点检查
}
```

**快速定位核心操作技巧（L2-L3审计等级）**：
- 搜索预言机读取函数：`get_price`、`read_data`、`fetch_rate`、`query_value`
- 跳读定位价格应用点：乘法运算 `* price`、除法运算 `/ price`、价格赋值后的转账/铸币操作
- 关注清算函数 `liquidate`、兑换函数 `swap`、抵押借贷函数 `borrow`/`mint` 中的预言机调用链
- 追踪 `amount_out` 或 `value` 变量从预言机价格计算到实际执行的完整路径

**快速定位保护机制技巧（L1-L2审计等级）**：
- 关键词扫描：`slippage`、`min_amount_out`、`max_price`、`price_bound`、`tolerance`、`deviation`
- 跳读检查条件语句：`assert!`、`require` 中是否存在 `expected_amount`、`min_received` 等边界值比较
- 查找参数列表：函数签名中是否包含 `min_*` 或 `max_*` 前缀的限价参数
- 检查是否存在价格时效性验证：`timestamp`、`last_update`、`staleness_check`

## Classify

**漏洞判定标准**：
- 存在预言机价格直接参与资产转移、铸币、清算等价值变动操作
- 缺乏用户指定的最小输出金额或最大输入金额保护
- 价格剧烈波动时可造成用户非预期损失（MEV攻击、三明治攻击、抢跑）

**误报识别**：
- 预言机价格仅用于展示/查询，不直接参与状态变更
- 存在外部调用层的滑点控制（需跨模块验证，L4审计）
- 场景为时间加权平均价格（TWAP）且更新频率高、波动已被平滑

**代码异味**：
- 滑点参数存在但设置过大（>5%），形同虚设
- 滑点检查在可选分支中，存在绕过路径
- 仅检查价格上限或下限，未形成完整区间保护

## Low risk

**低风险场景**：
- 预言机价格用于非关键路径：如奖励积分计算、UI展示值、日志记录
- 交易金额微小且有全局上限：单笔交易限额 < 总锁仓量的0.1%
- 存在多轮确认机制：时间锁 + 人工审核 + 多签确认的组合
- 价格源为去中心化聚合预言机（如Pyth、Switchboard）且配置了置信度阈值、数据源数量要求
- 应用场景为内部核算：链上资产总值统计、协议TVL计算等非交易场景

## 审计专业技巧

**多层级价格读取链追踪**：
- 不仅检查直接的 `oracle::get_price()` 调用，还要追踪经过中间函数的间接调用
- 在 Aptos/Sui 中，价格数据可能通过 `PriceIdentifier` → `get_price_no_older_than()` → `price.value` 三层调用
- 关键技巧：在函数定义时搜索参数使用，例如查找 `price_feed` 参数的所有使用位置，而非仅看函数签名

**滑点保护的隐蔽性检查**：
- L1误区：仅检查 `min_amount_out` 是否存在，忽视其取值逻辑
- 正确做法：验证 `min_amount_out` 的来源是否由用户指定还是从固定值或常量推导
  - 真正保护：`let min_out = expected_amount * (10000 - slippage_bps) / 10000;`
  - 虚假保护：`let min_out = expected_amount / 2;` 或 `let min_out = 1u64;`
- 追踪参数来源：从函数入口参数 → 参数验证 → 计算应用的完整调用栈

**价格时效性与延迟验证**：
- 检查预言机数据的更新时间戳与当前区块时间的差值
- Aptos 常见模式：`assert!(now - last_updated < MAX_STALENESS, 0x123);`
- 误报陷阱：某些协议虽有时间检查但 `MAX_STALENESS` 设置过大（如24小时），需评估业务场景适用性
- 对于高波动资产，即使有时间检查也可能存在风险

**MEV与三明治攻击向量分析**：
- 审计时需判断函数是否公开可调用（`public` 或 `public entry`）
- 识别攻击者控制的变量：用户指定的 `min_amount_out` 为0或过低时，是否能被机器人前置/后置执行
- 实战技巧：检查区块内价格变化范围，通过flashloan诱发极端价格后立即调用该函数的可行性

**跨合约调用的责任边界**：
- 常见误报来源：A合约调用B合约的定价函数，认为B合约的滑点检查足以保护
- 实际风险：需验证B的滑点参数是否可由A的用户直接控制，避免A中绕过B的保护
- 追踪方法：在调用点处停留，确认参数是否来自外部输入还是内部常量

## 真实漏洞与误报的区分经验

**真实漏洞特征（高置信度）**：
1. **价格直接驱动转账**：价格读取 → 数学计算 → transfer 或 withdraw 的直接路径，且没有边界参数
   - 示例：`amount_out = amount_in * price / 10^8` 后直接 `transfer(user, amount_out)`
   - 红旗信号：函数中同时存在预言机读取和状态修改操作

2. **参数绕过风险**：函数提供的滑点参数为可选项或有隐蔽的默认值
   - 示例：`public fun swap(..., slippage: Option<u64>)` 而 `slippage` 未被使用
   - 或者在 `if (option::is_some(&slippage))` 分支外的主逻辑中缺少检查

3. **价格源不可信**：依赖单一中心化预言机或未经验证的链下签名者
   - Aptos Pyth 集成应检查是否调用了官方的 `pyth::verify_vaa()` 进行签名验证
   - Sui Move 应确认预言机模块来自官方，避免恶意模块伪装

**常见误报案例（应该排除）**：
1. **被动报价系统**：虽然使用预言机价格，但操作对象是协议资金而非用户资金
   - 示例：协议在 swap 时自动确定汇率而非让用户指定，但用户事前知晓此机制且自愿参与
   - 判断标准：是否存在用户明确知晓的价格滑动上限（如文档或 UI 中的透明信息）

2. **聚合预言机已含内部防护**：Pyth 或 Switchboard 本身的置信度机制已过滤异常价格
   - 但需验证：应用层是否真正读取了 `confidence_interval` 并据此进行过滤
   - 误报例：只读取 `price` 字段而忽视 `confidence`，就不能认为 Pyth 的防护生效

3. **TWAP 配置合理的情况**：时间加权平均价格若更新频繁且覆盖足够长时间窗口
   - Aptos 应用常用的 `amm::get_amount_out()` 返回 TWAP，大幅降低瞬时价格操纵风险
   - 判断标准：窗口长度是否大于 MEV 攻击的实际可控时间（通常>15分钟）

4. **内部操作的价格引用**：预言机价格用于协议内部清算边界或风险评估，不直接触及用户资金转账
   - 示例：`if (collateral_value * price < debt * liquidation_threshold)` 用于状态判定，但实际扣款通过另一个机制
   - 需验证：不存在隐蔽的价格驱动状态变更路径

**灰度案例与分类决策**：
- **高风险→中风险降级条件**：存在官方多签时间锁、动态参数可由治理DAO修改、市场规模小
- **中风险→低风险降级条件**：额外的跨链冗余预言机、链上或链下的人工风险控制流程、历史上无漏洞利用记录
- **低风险→高风险升级条件**：发现曾有超大额交易、识别到 flashloan 可注入流动性、预言机维护者背景不明

**审计报告的严谨措辞**：
- 避免："存在预言机风险" ← 过于宽泛
- 改为："用户在调用 `swap()` 时若不指定 `min_amount_out` 参数，可遭受 MEV 抢跑导致的 5-10% 滑点损失"
- 或："虽存在滑点参数，但合约未验证该参数由用户签名授权，后端可篡改参数并重放交易"
