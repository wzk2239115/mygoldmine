# JavaScript_Loop_Boundary_Issue

**漏洞类型**: 循环边界条件问题，for/while 循环中使用可能导致溢出的表达式

**JavaScript/TypeScript**

---

专注于这一垂直漏洞类型研判任务，从漏洞成因触发，编写该md文件，包含一下三个小标题，【注意语言精炼，表达简洁，可以作为审计小抄，仅专注于审计，不包含攻击与修复】：

## Details

**代码示例**：`for (let i = 0; i < userCount; i++)`、`while (counter < limit)`、`for (let i = start; i < start + length; i++)`

- **核心操作定位技巧** (L1: 关键词扫描)：扫描 for/while 循环的边界条件，特别关注边界值来自用户输入、计算结果或外部数据的情况。检查循环变量的递增/递减操作，以及边界表达式中的算术运算（`start + length`）。追踪循环变量的来源，在HTTP参数、API输入、数据库查询结果中重点检视。

- **保护机制定位技巧** (L2: 跳读)：查找边界上限验证（`Math.min(count, MAX_ITERATIONS)`）、循环计数器限制、或使用安全的迭代方式（如 forEach、for...of）。检查是否有防止无限循环的机制。关注try-catch捕获或timeout机制。

### 审计专业技巧

**关键审计点：**

1. **边界值溢出场景识别**
   - `start + length` 型：start与length均来自用户时，两数相加可能超过Number.MAX_SAFE_INTEGER
   - `i < array.length` 型：虽然JavaScript数组长度有上限，但需检查length是否被人为修改
   - 浮点数循环：`for (let i = 0.1; i < 1; i += 0.2)` 易因精度问题产生无限循环

2. **数据流追踪重点**
   - 直接使用：`for (let i = 0; i < req.body.count; i++)` —— 高风险
   - 简单乘法：`for (let i = 0; i < multiplier * baseCount; i++)` —— 中风险
   - 嵌套计算：`for (let i = 0; i < obj[key1][key2] + offset; i++)` —— 需深度追踪

3. **循环表现异常信号**
   - 循环体时间复杂度O(n)以上：`for (let i = 0; i < n; i++) { for (let j = 0; j < m; j++) }`
   - 无明确终止条件：`while (true)` 需要单独分析break条件
   - 递归与循环混用：尾调用可能导致堆栈溢出而非整数溢出

## Classify

判断是否为漏洞的要点：

**确定漏洞的判断标准：**
- 循环边界无上限检查，直接使用用户输入：`for (let i = 0; i < userLimit; i++)` 无任何验证
- 边界计算存在溢出风险：`start + length` 两个大数相加超过安全整数范围
- 循环体内存在高成本操作且无迭代次数限制：数据库查询、文件操作、API调用
- 浮点数精度导致无限循环：`while (sum !== targetSum)` 浮点数累加

**真实漏洞案例特征：**
- 用户可控的参数作为循环上限，参数值可达几百万级别
- 循环体执行成本高（数据库查询、网络I/O），循环次数无限制
- 在处理用户上传文件大小、数组分页、分批处理时没有合理的上限
- 循环条件依赖外部API响应结果，API响应可被延迟或返回极大值

**常见误报形式：**
- 循环次数固定常量：`for (let i = 0; i < 100; i++)`
- 边界值虽动态但有明确上限：`const limit = Math.min(userCount, 10000)`
- 来自数据库配置表的值，配置值本身已受控
- 使用现代数据结构如Set/Map的自动遍历：`for (const item of collection)`
- 循环体为简单赋值操作，不存在时间放大效应

**代码异味，需进一步追踪：**
- 边界值经过多步转换：`const count = parseInt(params); const limit = count * 2; for (let i = 0; i < limit;)`
- 使用了条件上限但逻辑复杂：`for (let i = 0; i < (flag ? limitA : limitB); i++)`
- 循环次数与数据大小线性相关：处理集合时的迭代

## Low risk

- 循环边界为常量或有明确上限（如 `Math.min(count, 1000)`）
- 使用 forEach、map、for...of 等安全迭代方法，边界由数据结构本身决定
- 边界值经过范围验证（如 `count = Math.min(Math.max(count, 0), MAX_LIMIT)`）
- 有循环计数器防止无限循环（显式的最大迭代次数控制）
- 边界来自可信配置（配置文件、环境变量、数据库配置表的硬编码规则）
- 循环体内仅进行简单计算或赋值，无高成本操作
- 使用递归深度限制或栈大小限制的递归遍历

**审计决策树：**
```
边界值来自用户输入？
├─ 是 → 是否有上限验证？
│   ├─ 否 → 确定漏洞
│   └─ 是 → 是否为 Math.min/max 类强制上限？
│       ├─ 是 → Low Risk
│       └─ 否（如条件判断）→ 代码异味，需深度分析
└─ 否 → 值是否来自可信配置？
    ├─ 是 → Low Risk
    └─ 否（计算结果、API响应等）→ 追踪数据流来源
```

**现场审计查检清单：**
- [ ] 确认循环边界条件的完整表达式
- [ ] 追踪边界值到数据源头（参数/配置/计算）
- [ ] 验证是否存在上限检查及其有效性
- [ ] 评估循环体时间复杂度及总体执行成本
- [ ] 检查是否有超时机制或最大迭代次数限制
- [ ] 对动态计算的边界，分析中间步骤是否存在溢出
