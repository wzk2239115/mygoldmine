# Go_Type_Conversion_Overflow

**漏洞类型**: 类型转换溢出，不同整数类型之间的转换可能导致溢出或截断

## Details

**代码示例**：`int32(largeValue)`、`uint(negativeValue)`、`byte(bigNumber)`、`int(uint64Value)`

- **核心操作定位技巧** (L1: 关键词扫描)：扫描显式类型转换（如 `int32()`、`uint()`、`byte()`）。Go 不会自动提升类型，转换可能静默截断。关注从宽类型转窄类型（int64 → int32）、有符号与无符号互转（int ↔ uint）的情况。

- **保护机制定位技巧** (L2: 跳读)：查找转换前的范围检查（`if value > math.MaxInt32`、`if value < 0`），使用 `math` 包的常量进行验证，或避免不必要的类型转换。检查转换结果是否参与关键运算。

## Classify

判断是否为漏洞的要点：
- **确定漏洞**：类型转换无范围检查，导致数据截断或符号错误，影响程序逻辑或安全性
- **误报**：转换前有范围验证、值明确在目标类型范围内、转换仅用于非关键场景
- **代码异味**：频繁类型转换，需确认是否可能丢失数据

## Low risk

- 转换前进行范围检查（如 `value <= math.MaxInt32`）
- 值为常量或明确在目标类型范围内
- 使用类型一致的变量避免转换
- 转换结果仅用于显示或日志
- 使用更宽的类型统一处理

## Audit Skills

### 专业审计技巧

**关键点1：静态类型转换 vs 动态值转换**
- 静态语法不代表安全：`int32(x)` 语法正确但不检查值范围
- 追踪值的来源：输入源（网络、文件、系统调用）→ 转换点 → 使用点
- 特别关注循环中的累积转换，可能导致多次截断损失

**关键点2：隐式数据流分析**
- 扫描 `strconv` 包的使用：`strconv.ParseInt()`、`strconv.ParseUint()` 虽然返回正确类型，但后续转换仍可能溢出
- 关注数组索引场景：`arr[int(floatValue)]` 虽然浮点转int，但需验证范围
- 注意位移操作前的类型转换：`value << uint(count)` 中的count转换

**关键点3：有符号与无符号互转陷阱**
- 负数转无符号：`uint(-1)` 会产生最大uint值，可能导致缓冲区溢出
- 检查是否有负值检查：`if value >= 0` 的位置，缺失此检查时高危
- 比较前的隐式转换：`int32(a) > uint32(b)` 可能发生自动类型提升

**关键点4：常见高危模式识别**
- 模式1：`int(unsafe.Pointer)` 的指针转换，易引发内存安全问题
- 模式2：`int(float64(data)/scale)` 浮点中间值损失精度后转整数
- 模式3：`uint8(len(slice))` 长度转换，仅限小于256的数组
- 模式4：`int32(time.Duration)` 或 `int64(nanoseconds)` 时间相关转换

### 真实漏洞 vs 误报区分

**这是漏洞的表现**：
1. 转换后的值直接用于内存访问（数组索引、切片偏移）
2. 转换前值来自不信任输入，无边界检查
3. 转换导致符号位改变，影响比较逻辑（如 `if count > 0` 变假）
4. 循环计数器转换：`for i := 0; i < int(maxVal); i++` 中maxVal无验证
5. 长度/容量转换：`make([]T, int(userInput))` 可能分配巨大内存

**这是误报的表现**：
1. 转换前已显式验证范围（如 `if n > 0 && n <= 100 { return int32(n) }`）
2. 编译时常量转换（如 `const limit = 1000; int32(limit)`）
3. 转换结果仅用于日志输出或格式化，不影响程序控制流
4. 转换涉及的值被之前的条件守护（如 `ParseInt(s, 10, 32)` 已保证范围）
5. 转换在受保护的代码路径（如 mutex 保护的临界区，且值不会改变）

### 审计检查清单

- [ ] 定位所有显式类型转换，特别是宽→窄的转换
- [ ] 追踪转换前的值来源（用户输入、API返回、系统调用）
- [ ] 检查转换前是否存在相关的范围验证语句
- [ ] 验证转换后的值是否用于敏感操作（索引、长度、符号判断）
- [ ] 对于有符号↔无符号转换，确认负值处理
- [ ] 检查循环条件和边界条件中的转换
- [ ] 关注错误返回路径，转换可能在异常流中发生
- [ ] 多文件追踪，某个转换的前置条件可能在调用函数中
