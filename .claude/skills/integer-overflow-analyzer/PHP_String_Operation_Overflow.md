# PHP_String_Operation_Overflow

**漏洞类型**: 字符串操作溢出，substr、str_repeat 等函数使用大数值参数

**PHP**

## Details

**代码示例**：`str_repeat($str, $count)`、`substr($str, $offset, $length)`、`str_pad($input, $length)`

- **核心操作定位技巧** (L1: 关键词扫描)：扫描字符串操作函数（`str_repeat`、`str_pad`、`substr`、`mb_substr`）。关注长度/次数参数来自用户输入的情况。`str_repeat()` 使用大 count 值会导致内存耗尽。检查偏移量和长度计算。

- **保护机制定位技巧** (L2: 跳读)：查找参数上限验证、使用字符串流代替大字符串操作、或设置内存限制。检查偏移量是否可能为负数或超出字符串长度。

## Classify

判断是否为漏洞的要点：
- **确定漏洞**：字符串操作参数来自不受信任的源，无上限检查，可能导致内存耗尽（DoS）
- **误报**：参数有明确上限、使用流式处理、有内存限制
- **代码异味**：字符串操作参数动态计算，需评估内存影响

## Audit Skills (审计专业技巧)

### 1. 参数溯源分析
- **用户输入追踪**：从 GET/POST/Cookie 参数、文件上传、API 请求等入口追踪字符串操作函数的参数源
- **隐性输入识别**：检查数据库查询结果、缓存数据、Redis 值等作为参数的场景，这些也属于不完全受信的源
- **类型转换陷阱**：留意 PHP 弱类型特性，如 `"1024abc" * 2` 会被转换为 `2048`，审查隐性类型转换

### 2. 上限验证的精细判断
- **多层上限检查**：追踪参数经过的所有验证函数，确保验证逻辑正确无遗漏
- **条件分支覆盖**：审查不同分支中是否都存在上限检查，警惕某些分支遗漏验证
- **数学溢出风险**：参数计算过程中可能溢出（如 `$offset + $length > PHP_INT_MAX`），需评估中间值

### 3. 功能上下文分析
- **业务函数意图**：判断长字符串操作是否为业务必须，还是可被替代
- **隐性内存压力**：多次字符串操作的累积效应，单个操作虽小但频繁调用可导致内存耗尽
- **异步处理识别**：检查是否在队列任务或后台任务中，DoS 风险评估方式不同

## Distinguish Real Bugs vs False Positives (漏洞与误报区分)

### 真实漏洞案例特征

**案例1：控制台日志导出漏洞**
```php
$log_content = $_GET['logs'];  // 用户输入
$repeat_times = intval($_GET['repeat']) ?? 1;
echo str_repeat($log_content, $repeat_times);  // 直接使用无上限
```
- 特征：参数来自用户输入，无验证，可直接指定重复次数（如 repeat=10000000）
- 风险等级：HIGH - 单个请求即可导致内存耗尽和进程崩溃

**案例2：文件处理缓冲区溢出**
```php
$chunk_size = $_POST['size'] ?? 8192;
$buffer = str_repeat(' ', $chunk_size);  // 根据用户输入动态分配缓冲
```
- 特征：参数动态计算、无业务上限、直接分配内存
- 风险等级：HIGH - 攻击者可指定极大的缓冲区大小

**案例3：报表生成中的截断溢出**
```php
$full_content = $this->getReportData();  // 假设返回 1GB+ 数据
$excerpt = substr($full_content, 0, $_GET['length'] ?? 1000);
```
- 特征：虽有默认值但可被覆盖，无上限检查，数据源本身超大
- 风险等级：MEDIUM - 组合风险，substr 操作本身是安全的，但加载完整数据是瓶颈

### 误报案例特征

**误报1：常量上限**
```php
define('MAX_REPEAT', 100);
str_repeat($data, min($_GET['times'], MAX_REPEAT));
```
- 特征：使用 `min()` 或 `max()` 强制上限，参数被明确限制
- 判定：安全 - 即使用户输入 10000，也只会重复 100 次

**误报2：严格的类型转换和范围检查**
```php
if (!is_numeric($length) || $length < 1 || $length > 10000) {
    throw new Exception('Invalid length');
}
$result = str_repeat($str, $length);
```
- 特征：显式类型检查、范围验证、异常处理
- 判定：安全 - 所有可能的输入都经过了白名单验证

**误报3：流式处理替代**
```php
// 不直接创建大字符串，而是流式输出
echo str_repeat($char, 100);  // 仅重复 100 次，符合业务
for ($i = 0; $i < 10000; $i++) {
    echo $this->generateChunk($i);  // 分块输出，避免内存爆炸
}
```
- 特征：单个字符串操作体量有限，总体使用流式处理
- 判定：安全 - 虽然循环次数多，但单次操作量受控

**误报4：配置文件参数**
```php
$max_padding = config('string.max_padding');  // 从配置文件读取
$padded = str_pad($input, $max_padding, ' ');
```
- 特征：参数来自不可被终端用户修改的配置文件
- 判定：安全 - 参数源受信任

## Advanced Audit Techniques (高级审计技巧)

### 参数依赖链分析
- **跨函数传递链**：追踪参数如何跨越多个函数传递，某个中间函数可能修改参数含义
- **条件判断隐性控制**：条件语句中虽然检查了范围，但之后的执行路径可能因为逻辑错误绕过限制
- **全局状态污染**：检查全局变量或类属性是否被用作参数，其值是否可被其他入口污染

### 内存安全评估
- **PHP 配置审查**：检查 php.ini 的 `memory_limit` 设置，评估操作系统整体资源压力
- **单进程 vs 多进程**：PHP-FPM 的进程池模式下，单个进程崩溃影响相对有限，但高并发场景下 DoS 风险等级提升
- **字符串编码影响**：多字节字符（UTF-8）的长度计算可能导致 substr/str_repeat 行为异常

### 代码审计检查清单
- [ ] 定位所有字符串操作函数调用点
- [ ] 追踪参数源，判断是否来自不信任的输入
- [ ] 验证是否存在上限检查及其有效性
- [ ] 评估单次操作内存占用（参数值 × 字符宽度）
- [ ] 检查循环中的累积效应
- [ ] 查看异常处理是否完整
- [ ] 验证类型强制转换不会绕过验证逻辑
- [ ] 评估并发场景下的累积内存压力

## Low risk

- 参数有明确上限（如 `min($count, 1000)`）
- 使用字符串流或分块处理
- 设置合理的 memory_limit
- 偏移量和长度经过范围验证
- 参数来自已验证的配置
- 字符串操作在业务逻辑允许的范围内
- 使用 strlen/mb_strlen 进行预先大小检查
