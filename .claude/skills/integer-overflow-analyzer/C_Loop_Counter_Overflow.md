## Details

**代码示例**：`for (unsigned int i = 0; i <= userInputSize; i++)`、`while (counter < MAX_INT) { counter++; }`、循环边界 `i = userSize + 1`

- **核心操作定位技巧** (L1: 关键词扫描)：扫描循环头 `for/while` 中的递增/递减操作 `++/--`，特别关注 `<=` 比较符号（vs `<`）和循环变量类型（`unsigned int/int/char`）。检查循环边界来自用户输入或计算结果的地方。

- **保护机制定位技巧** (L2: 跳读)：查找循环前的边界校验（`if (size > MAX_LIMIT)`）、使用 `size_t` 等适当宽度类型、或循环条件中显式的溢出检查（如 `i < size && i <= INT_MAX`）。

## Classify

判断是否为漏洞的要点：
- **确定漏洞**：循环边界来自用户输入/外部数据，无验证，循环次数不可预测
- **误报**：循环边界为常量、固定数组长度、或明确验证过的值
- **代码异味**：循环逻辑复杂，需追踪循环变量的所有修改点

## Audit Professions & Real vs False Positives

### 审计关键技巧与陷阱

**1. 边界类型差异审计** (L2-L3)
- 区分 `unsigned int` 与 `signed int`：unsigned 下 0 不存在负溢出，但上界溢出更隐蔽；signed 可能触发未定义行为
- 循环条件 `i <= INT_MAX` vs `i < INT_MAX`：前者在 i = INT_MAX 时继续循环，导致溢出
- 实战案例：`for (unsigned int i = 0; i <= length; i++)` 当 length = UINT_MAX 时循环溢出，但 length 若为 size_t（来自 strlen）则需追踪源头

**2. 用户输入关联度审计** (L3-L4)
- 不仅检查直接输入，还需追踪通过函数参数、结构体字段、全局变量等间接传入的边界值
- 关键追踪节点：函数参数验证、结构体初始化、网络消息解析、配置文件读取
- 示例陷阱：`ProcessData(int userCount)` 中若 userCount 来自网络包且无范围校验，循环 `for (int i = 0; i < userCount; i++)` 即使使用 `<` 也可能数据竞争或堆溢出

**3. 数据流溢出链审计** (L4)
- 关键问题：循环边界值经过计算时（如 `i < size + offset`），计算本身可能溢出
- 区分点：`int size = ...; int limit = size + 1;`（计算溢出）vs `for (...; i < size + 1; ...)`（条件运算相对安全）
- 追踪要点：所有参与循环边界计算的变量的初值与修改路径

**4. 真实漏洞特征** ✓
- 循环变量类型为 signed/unsigned int，边界来自用户数据或网络解析
- 循环条件涉及 `<=` 或边界计算（+1, *2）且无先验验证
- 循环体内访问缓冲区、指针递增或资源释放，溢出导致越界/泄漏
- 实例：`while (count < user_input) { buffer[idx++] = ...; }` 当 user_input 为 INT_MAX 时越界

**5. 常见误报模式** ✗
- 循环边界来自 `strlen()`, `sizeof()`, `array_length_constant`（内部自我验证）
- 循环条件使用 `size_t` 或 `int` 但显式存在范围校验：`if (size > MAX) return error; for (...; i < size; ...)`
- 循环仅遍历已分配内存：`malloc(userSize); for (i = 0; i < userSize; i++)`（风险在 malloc 而非循环）
- RAII 或引用计数场景：循环对对象计数，溢出导致逻辑错误而非内存破坏

**6. 跨函数审计陷阱** (L4)
- 内联函数中的循环边界可能在调用处才绑定值，需回溯调用链
- 宏展开中的循环：`#define LOOP(n) for(i=0; i<=n; i++)` 隐藏边界问题
- 多态/虚函数中的循环：基类中定义的循环，子类覆盖参数可能改变语义

### 真实漏洞 vs 误报 决策树

```
发现循环递增操作 i++ / i+=step
  ├─ 循环边界来自用户输入或网络数据？
  │  ├─ YES → 检查边界是否经过范围校验 (size_t, <=MAX_VALUE)?
  │  │  ├─ YES 且使用 size_t → 误报 (系统类型已限制)
  │  │  ├─ NO 或 signed int → 继续检查
  │  │  └─ 计算涉及 +1/-1/数学运算？→ 漏洞 (计算溢出)
  │  └─ NO → 检查边界值本身是否验证
  │     ├─ 常量 / 编译期确定 → 误报
  │     └─ 全局变量 / 静态初始化 → 查找初值，追踪修改
  └─ 循环体是否触及缓冲区/指针?
     ├─ YES 且无边界检查 → 漏洞 (内存越界可能)
     └─ NO 或逻辑操作 → 代码异味 (DDoS/性能风险)
```

### 实战高频误报

1. **数组索引循环** (正常)：`for (i = 0; i < array_length; i++) use(arr[i]);` 若 array_length 来自 `sizeof(arr)/sizeof(arr[0])` 编译期计算则安全

2. **链表/树遍历** (正常)：`while (node != NULL) node = node->next;` 受链表结构约束，不会因计数溢出而越界

3. **页表/内存映射循环** (需特别关注)：`for (page = start; page <= end; page++)` 若 start/end 来自虚拟地址计算且无页对齐检查，`<=` 会导致额外一页访问

4. **超大循环优化路径** (隐蔽真漏)：编译器优化可能移除"冗余"溢出检查，如 `for (int i = 0; i < n; i++) if (i < MAX) {...}` 优化后第二个检查可能被删除
