# 通用密码学缺陷审计小抄

任何涉及密码学操作的项目，无论使用何种编程语言，都必须审查以下缺陷模式。这些是算法与参数层面的通用问题，与具体语言实现无关。

## 不安全的加密算法或模式

### 已破解或弱加密算法
- **DES、3DES**：已被破解，禁止使用
- **RC4、RC2**：流密码算法，存在已知漏洞
- **密钥长度 < 128位**：对称加密强度不足

### 不安全的加密模式
- **ECB 模式**：相同明文产生相同密文，导致模式泄露，禁止使用
- **CBC 模式无 MAC**：无消息认证码，无法检测篡改
- **无认证加密**：应使用 GCM、CCM、ChaCha20-Poly1305

## 初始化向量（IV）使用不当

### IV 不随机或可预测
- **固定值或零值**：IV 完全不随机
- **时间戳/计数器**：可预测的 IV 生成方式
- **弱随机数生成**：Math.random()、rand() 等非密码学安全 RNG

### IV 重复使用或共享
- **同一密钥多次加密**：重复使用相同 IV，导致加密失效
- **不同数据共享 IV**：降低安全性
- **IV 未重新生成**：每次加密必须使用新的随机 IV

## 密钥管理缺陷

### 密钥存储不安全
- **硬编码密钥**：密钥在源代码中硬编码
- **明文配置文件**：密钥以明文形式存储在配置文件
- **内存未清理**：密钥在内存中以明文形式长期保留，未安全擦除

### 密钥长度不足
- **对称密钥 < 128位**：强度不符合现代标准
- **RSA 密钥 < 2048位**：易被因式分解
- **ECC 密钥 < 256位**：强度不足

## 密钥派生函数（KDF）参数不足

### PBKDF2 配置缺陷
- **迭代次数 < 600,000**：参数过少，易被爆破
- **弱哈希函数**：使用 MD5、SHA-1，应使用 SHA-256 或更强
- **盐长度不足/固定盐**：盐应随机生成，长度 ≥ 16 字节

### 未使用现代 KDF
- **应用场景错误**：密码存储应使用 Bcrypt/Scrypt/Argon2，不应使用 PBKDF2
- **直接哈希密钥**：直接使用 SHA-256 派生密钥，应使用专用 KDF

## 不安全的哈希算法

- **MD5**：已被破解，禁止用于完整性校验或密码哈希
- **SHA-1**：碰撞已被找到，禁止用于签名或完整性校验
- **MD2、MD4**：过时算法，禁止使用
- **推荐**：SHA-256、SHA-3、BLAKE2

## 随机数生成器不安全

### 弱 RNG 生成关键参数
- **伪随机数生成器**：Math.random()、rand()、java.util.Random
- **可预测种子**：基于时间戳或计数器的种子
- **正确做法**：使用 /dev/urandom、os.urandom()、SecureRandom、crypto.randomBytes()

## 填充（Padding）实现错误

### Padding 实现缺陷
- **手动实现 Padding**：应使用库内置实现，避免自定义
- **Padding Oracle 风险**：解密失败时返回详细错误消息，泄露填充信息
- **弱填充方案**：使用零填充（PKCS#7/PKCS#5），应使用标准方案

## 使用废弃或过时的密码学库

- **Python**：pycrypto（已停止维护），应使用 cryptography
- **PHP**：mcrypt（PHP 7.1+ 移除），应使用 openssl
- **JavaScript**：crypto-js（浏览器端不安全），应使用 TweetNaCl.js、libsodium.js
- **通用**：过时版本的 OpenSSL（< 1.1.1）、OpenSSH（< 7.3）
