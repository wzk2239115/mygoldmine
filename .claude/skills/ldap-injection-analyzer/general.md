**通用 LDAP 注入漏洞审计小抄**

任何涉及 LDAP 查询的应用都必须审计以下漏洞模式。这些问题源于 LDAP 过滤器构造缺乏安全控制，与编程语言无关。

## 1. 用户输入直接拼接到 LDAP 过滤器

### 字符串拼接构造 LDAP 过滤器

**危险代码特征**
```
filter = "(uid=" + username + ")"
ldap_search(ldap_conn, base_dn, filter)
```

**快速定位**（L1: 关键词扫描）：
- 搜索关键词：`LDAP`、`ldap_search`、`filter`、`uid=`、`cn=`、`mail=`
- 搜索字符串拼接操作：`+`、`.format()`、`%`、`f-string`、`concat()`
- 搜索 LDAP 特殊字符：`*`、`()`、`&`、`|`、`!`、`\`

**快速定位保护机制**（L2-L3: 跳读/逐行读）：
- **特殊字符过滤**（L2）：检查是否对用户输入进行了 LDAP 特殊字符转义（如 `ldap_escape()`）
- **输入验证**（L2）：查看是否对过滤器进行了白名单验证
- **参数化接口**（L3）：查找是否使用了参数化的 LDAP 查询 API
- **完整链路**（L4）：追踪用户输入从接收到 LDAP 查询执行的完整过程

---

## 2. 研判标准

### 确认为漏洞

**必须满足**
1. 用户输入直接用于构造 LDAP 过滤器字符串
2. 未对 LDAP 特殊字符进行转义或过滤
3. 攻击者可通过注入通配符 `*` 或逻辑运算符 `&|!` 改变查询逻辑
4. 导致数据泄露、身份认证绕过或信息枚举

**特殊字符注入**
- 星号 `*`：匹配任意字符串，用于列举所有账户
- 左右括号 `()`：改变过滤器结构
- 与 `&` 和或 `|`、非 `!`：修改逻辑条件
- 反斜杠 `\`：转义特殊字符
- 空字符 NUL：截断过滤器

### 判定为误报

**如果满足以下情况之一，可判定为误报**
1. **特殊字符转义**：使用了 `ldap_escape()` 或等效的转义函数
2. **完整白名单**：对用户输入进行了严格的白名单验证
3. **参数化接口**：使用了参数化的 LDAP 查询接口
4. **权限隔离**：LDAP 连接账户权限受限，只读访问


## 3. 低风险指标

### 以下情况应给予低风险评级

1. **特殊字符转义**：所有 LDAP 特殊字符都被正确转义
2. **输入验证**：用户输入通过严格的白名单验证（如只允许字母数字）
3. **参数化查询**：使用了参数化的 LDAP API
4. **权限限制**：LDAP 认证账户权限受限，无法读取敏感数据
5. **双重防护**：即使注入成功，也无实质危害
