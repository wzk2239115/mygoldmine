# 通用路径遍历与文件包含漏洞审计小抄

任何涉及文件系统操作的 Web 应用都必须审计这些漏洞模式。这些问题源于文件路径构建和访问控制缺陷，与编程语言无关。

---

## 快速审计流程

### 第 1 步：定位文件操作
搜索关键词：`open`, `read`, `include`, `require`, `load`, `parse`, `execute`

### 第 2 步：判断路径可控性
- **不可控** → L0（跳过）
- **可控但有白名单** → L1-L2
- **可控且无防护** → L3+

### 第 3 步：验证防护机制
| 防护方式 | 效果 |
|---------|------|
| 无防护 | **高危** |
| 字符串替换（如 replace `..`) | **可绕过** |
| 路径规范化（realpath/clean） | **基础防护** |
| 规范化 + 前缀检查 | **有效防护** |
| 白名单验证 | **最安全** |

### 第 4 步：尝试绕过（必做）
```
../../../../../etc/passwd          # 基础遍历
%2e%2e%2f                          # URL编码
..%252f                            # 双重编码
....//                             # 替换后绕过
/etc/passwd                        # 绝对路径
```

## 路径构建缺陷

**用户输入直接拼接到路径**
- 未过滤 `../` 或绝对路径的字符串拼接：`base_dir + user_input`
- 使用路径函数（`path.join`/`Paths.get`/`os.path.join`）但未验证输入
- 文件名参数直接用于访问，无路径遍历检查

**路径规范化不完整或可绕过**
- 仅处理 `../`，未处理 URL 编码变体（`%2e%2e%2f`、`..%252f`）
- 路径清理函数使用顺序错误（先验证后拼接 vs 拼接后验证）
- 多次调用规范化，每次规范化前后都可能被篡改

**缺少白名单和根目录检查**
- 未限制访问基础目录外的文件
- 使用黑名单而非白名单（总有绕过方式）
- 规范化后未验证最终路径是否仍在安全目录内

**前导斜杠或绝对路径绕过**
- 输入 `/etc/passwd` 时，`base + user_input` 被斜杠中断
- 用户提供 `C:\Windows` 或 `//server/share` 覆盖基础路径
- 相对路径未转换为绝对路径验证

## 符号链接/硬链接绕过

**符号链接指向受限目录外**
- 访问前未检查是否为符号链接
- 检查时间过早（解析前检查，解析后未重新验证）
- 符号链接指向 `/etc/passwd`、`/proc` 等敏感文件

**硬链接和挂载点**
- 硬链接可指向受限文件，无法通过 `readlink` 检测
- 挂载点、bind mount 可绕过目录限制

## 本地文件包含 (LFI)

**动态文件包含**
- `include($_GET['file'])`、`require()` 使用用户输入
- 模板加载器接受用户提供的模板路径
- 配置、插件、脚本路径由参数控制

**包含敏感文件**
- 读取 `/etc/passwd`、`web.config`、数据库配置
- 读取应用密钥、凭证、私钥文件
- 读取日志文件泄露敏感信息

**日志注入+包含 RCE**
- 用户输入写入日志文件（`<?php ...?>`）
- 再通过 LFI 包含日志文件执行
- Session 文件、临时文件包含可控数据

## 远程文件包含 (RFI)

**允许远程 URL 包含**
- PHP `allow_url_include` 或 `allow_url_fopen` 启用
- `include/require/fopen/file_get_contents` 支持 `http://`、`ftp://` 等协议
- 远程资源下载后执行，未验证来源

**用户可控 URL**
- 参数指定远程 URL 下载或包含执行
- Webhook 回调、API 调用未验证目标 URL
- 远程模板、插件、配置由用户 URL 指定

## 常见场景

**文件下载/预览接口**
- 文件名参数包含 `../`、绝对路径、符号链接
- 查询参数未验证：`/download?file=../../../etc/passwd`

**日志查看功能**
- 参数指定日志文件路径：`/logs?file=../../var/log/app.log`
- 调试接口允许任意文件读取

**文件上传**
- 上传文件名包含 `../` 导致写入任意位置
- 上传后处理路径未清理文件名

**归档解压 (Zip Slip)**
- ZIP/TAR 解压未验证目标路径
- 解压项目名包含 `../` 可写入目录外
- 可覆盖应用文件或系统文件

**静态文件服务**
- 根目录配置不当可访问上级目录
- 反向代理路径重写规则可被绕过

## 跨平台绕过

**路径分隔符差异**
- Windows 使用 `\`，Unix 使用 `/`
- 验证仅检查 `/` 但未检查 `\`
- 混合分隔符可绕过规范化

**大小写敏感性**
- Linux 区分大小写，Windows 不区分
- 黑名单 `blocked.txt`，绕过用 `BLOCKED.TXT` (Windows)

## 研判标准

### 确认漏洞的 3 个条件
1. **路径来自外部输入**（URL、表单、API、命令行）
2. **缺乏有效防护**（无验证、黑名单或防护可绕过）
3. **能访问敏感文件或超出预期目录**

### 代码异味（高度怀疑）
- `open(user_input)` 或 `include(user_input)`
- 仅使用 `basename()` 或 `replace()`
- 使用黑名单过滤（如禁止 `..`）
- 符号链接未检查
- 错误消息泄露路径信息

### 误报场景
- 输入仅作为索引值（如 `files[user_input]`，返回固定文件）
- 使用 `realpath()` + 前缀检查 + 白名单
- 路径完全硬编码，无变量

## 低风险评估

即使存在路径参数，以下场景可降低风险等级：

| 场景 | 风险降低原因 |
|------|------------|
| 只读公开目录 | 泄露有限，但仍需修复 |
| 管理员限定 | 减少攻击面，但管理账号泄露仍高危 |
| 白名单 + 规范化 | 有效防护，定期审查白名单 |
| 容器/chroot 隔离 | 限制影响范围，但源代码问题仍需修复 |
| 文件权限限制 | 系统加固，需配合代码修复 |

**注意：低风险不等于无风险，仍应修复代码**
