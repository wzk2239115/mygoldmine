# 批量赋值漏洞审计快速参考

任何使用自动数据绑定、对象映射或 ORM 的 Web 应用都必须检查以下漏洞模式。这些问题与编程语言无关，源于自动赋值机制缺乏字段控制。

### 1. 自动数据绑定缺乏字段白名单

**表单/JSON 直接绑定无白名单**
- HTTP 请求数据自动绑定到模型/实体，未限制可写字段
- 数据绑定使用黑名单（允许列表以外都可写），可绕过
- 自动绑定配置允许所有字段可写

**DTO 与实体未隔离**
- 直接将用户输入绑定到实体类，未使用 DTO 层隔离
- DTO 到实体映射包含敏感字段未过滤
- 自动映射工具（ModelMapper、AutoMapper 等）未配置字段过滤

### 2. 敏感字段未设置只读保护

**权限、角色、身份相关字段**
- 用户角色、权限级别可通过请求参数修改
- 管理员标识、超级用户标志可被覆盖
- 权限组、权限列表字段可写
- 用户 ID、创建者 ID 可被修改
- 资源所有者、归属用户可被覆盖
- 多租户 ID、组织 ID 可被篡改

**业务状态相关字段**
- 订单状态、审核状态可直接修改
- 账号锁定标识、封禁状态可被解除
- 工作流状态可被跳过或回退

**财务字段**
- 订单金额、商品价格可通过参数修改
- 账户余额、积分数量可被覆盖
- 优惠金额、折扣比例可被篡改

**元数据字段**
- 创建时间、更新时间可被修改
- 版本号、修订号可被覆盖（影响并发控制）

### 3. ORM 批量更新接受未过滤输入

**直接传递用户输入**
- ORM 的 `update`、`save`、`merge` 直接接受请求体或参数字典
- 批量更新未过滤敏感字段，全部写入数据库
- `save` 或 `merge` 接受用户构造的实体对象

**字典/Map 更新未验证**
- 使用字典/Map 作为更新参数，未验证键名
- 动态 SQL 构造使用用户提供的字段名，未验证

**白名单不完整**
- 创建操作有白名单，但更新操作缺少
- 不同控制器/接口白名单配置不一致
- 管理后台或内部接口未配置字段限制

### 4. 反序列化未限制可写字段

**JSON/XML 反序列化配置**
- JSON 反序列化时未标记敏感字段为只读
- XML 反序列化未限制可写元素
- 反序列化库配置允许设置私有/保护字段

**序列化器未控制字段可见性**
- 反序列化时未使用 `@JsonIgnore`、`readonly` 等控制注解
- 序列化器未区分读写模式，所有字段双向可用

### 5. 对象合并或属性复制未验证来源

**对象合并函数**
- 直接合并用户输入，未过滤敏感属性（`Object.assign`、`lodash.merge` 等）
- 使用展开运算符合并对象未验证
- 深度合并覆盖嵌套对象敏感字段

**反射或动态赋值**
- 反射 API 动态设置属性，未验证属性名
- 动态属性访问（`obj[key] = value`）未过滤 key

### 6. 配置或环境参数可被覆盖

**配置热更新**
- 配置更新未限制可修改的配置键
- 用户可通过 API 修改应用级配置参数

**环境参数**
- 应用启动参数或环境变量可被用户覆盖

### 7. GraphQL 输入类型未限制字段

- GraphQL 输入类型包含敏感字段（角色、权限）可被客户端提交
- Mutation Resolver 直接将 input 参数传入 ORM

### 8. 多层嵌套对象未递归验证

- 嵌套对象的敏感字段未设置只读保护
- 关联对象更新时未验证关联实体的字段
- 数组/集合中的对象元素未进行字段验证

---

## 审计检查清单

1. **定位数据绑定点**：所有接收外部输入的控制器、API 端点、GraphQL Resolver
2. **查看字段白名单**：是否明确指定了可写字段（白名单优于黑名单）
3. **检查敏感字段标记**：权限、角色、状态、价格、ID 等是否标记为只读
4. **验证 DTO 隔离**：是否使用了 DTO 层，DTO 是否包含敏感字段
5. **审计 ORM 操作**：`update`、`save`、`merge` 是否接收了未过滤的用户输入
6. **审查映射配置**：自动映射工具是否配置了字段过滤
7. **检查嵌套对象**：关联对象、数组元素是否也受到保护
8. **验证完整性**：检查是否所有更新路径都配置了一致的保护
