## VERL-005 应缩小的验证目标

上一轮从本地分词器原型扩大到完整 `RewardLoopManager`、多工作进程及 Ray 启动，连续调整进程/PID 参数并等待，最后超时；脚本未写到指定目录，包装脚本无法接管。

本轮先确定命题：配置的 `trust_remote_code=False` 是否被真实组件覆盖并传入加载器。按当前源码检查 `reward_loop.py` 的工作组件初始化、分词器辅助函数和配置来源；能在隔离容器里调用最小真实组件，就不启动管理器和 Ray 集群。

本地测试工件只执行良性标记。不要用替换加载器返回值、复制函数或仅检查参数字面量来冒充动态确认。若真实组件只能在当前不可用的调度器中运行，保存可执行脚本、已核实配置和具体启动错误，标记覆盖不足或受阻；不继续穷举进程数和长时间等待，也不安装 GPU 训练后端。

## 对红队场景构建的影响

这些候选在该版本分别属于进程内奖励计算、模型工件加载或命令行操作。蓝队运行确认不证明存在远程 HTTP 入口。红队必须根据自己的任务 `supported_modes` 核对真实入口；不要为复用这些蓝队证据而新造 HTTP 包装服务。
