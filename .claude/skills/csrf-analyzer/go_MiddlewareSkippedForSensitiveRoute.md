# Go CSRF 中间件被豁免敏感路由漏洞

## Details

### 漏洞成因
即使项目使用 CSRF 中间件，如果在路由配置中通过白名单、正则或条件判断跳过某些路径（例如开放 API、支付回调、文件上传），而这些路径实际执行敏感操作，攻击者仍可利用 CSRF。典型情况是在 Gin/Echo 中利用 `Skip`/`Exclude` 功能，或在 `gorilla/csrf` 中对 `/api/*` 统一豁免，却忘记新加的 `/api/user/delete` 属于敏感接口。

### 代码示例

**易受攻击的代码：**
```go
csrfMw := csrf.Protect(
    []byte("secret-key"),
    csrf.Path("/"),
    csrf.SkipCheck(func(r *http.Request) bool {
        return strings.HasPrefix(r.URL.Path, "/api/") // 整个 API 被豁免
    }),
)

r.Handle("/api/user/delete", csrfMw(http.HandlerFunc(deleteUser))) // 删除接口被跳过
```

**另一个不安全示例（Gin 中间件豁免）：**
```go
r := gin.Default()
r.Use(csrf.Middleware(csrf.Options{
    Secret: "secret",
    ErrorFunc: func(c *gin.Context) { c.AbortWithStatus(403) },
    ExemptPaths: []string{"/api/*"}, // 包含敏感操作
}))

r.POST("/api/orders/approve", approveOrder) // 无 CSRF 校验
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- `SkipCheck`, `ExemptPaths`, `Ignore`, `Skip`
- `if shouldSkipCsrf(path)`
- 路由分组：`Group("/api")`, `Use(csrfMiddleware)`

**定位步骤：**
1. 搜索 CSRF 中间件配置中的豁免列表。
2. 逐条审核豁免路径是否包含敏感操作。
3. 跳读（L2）新增路由是否落在豁免范围内。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **精确白名单**：仅豁免第三方回调，并再次校验签名。
- **路由注释**：标明为何豁免、风险评估。
- **自动测试**：确保敏感端点未进入豁免列表。
- **多层防护**：对于 API，启用双重提交或 Bearer Token。

**定位技巧：**
- 检查 `OPTIONS`、`HEAD` 豁免是否误包含 `POST`.
- 分析路由注册顺序，确认豁免功能是否覆盖子路由。
- 关注微服务或网关是否追加了新的敏感路径。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 豁免仅限外部回调且有签名 | **L0（快速跳过）** | 风险低 |
| 某些敏感路由被误豁免 | **L3（逐行读）** | 高风险 |
| 整个路由组豁免，含敏感接口 | **L4（跨模块追踪）** | 极高风险 |
| 豁免路径缺乏记录与测试 | **L2（跳读）** | 易被忘记 |

## Classify

### 研判标准

#### 确认漏洞
需满足：
1. CSRF 中间件对敏感路径被豁免。
2. 这些路径依赖 Cookie 认证且无额外签名/Token。
3. 攻击者可构造跨站请求触发敏感操作。

#### 误报
以下情况非漏洞：
1. 路由仅用于第三方回调并附带 HMAC 签名且不依赖 Cookie。
2. API 使用 Bearer Token，无 Cookie。
3. 豁免仅限 `GET`/只读。

#### 代码异味
需记录：
1. `ExemptPaths` 使用通配符 `/api/*`，范围过大。
2. 代码注释中写 “临时豁免” 但未移除。
3. 自动生成的路由无法使用中间件。
4. 依赖环境变量控制豁免，生产环境不一致。

## Low risk

### 低风险评级场景

#### 1. 可信第三方回调
- **场景：** 端点仅接受签名校验的第三方请求。
- **风险评估：** 风险较低，但需确保签名严格。

#### 2. 内部 API
- **场景：** 豁免路径仅内部系统调用。
- **风险评估：** 攻击面有限。

#### 3. 多层验证
- **场景：** 即使无 CSRF，中间还有验证码/MFA。
- **风险评估：** 提高攻击成本，仍建议移除豁免。

#### 4. 审计与自动测试
- **场景：** 定期扫描豁免列表并进行安全审计。
- **风险评估：** 有助于发现遗漏，但非根治。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 第三方签名验证 | 可信来源 | 中 |
| 内部 API | 攻击面有限 | 中 |
| 多重验证 | 提升攻击成本 | 中 |
| 审计/测试 | 提升检测能力 | 高（仍需收紧豁免）|
