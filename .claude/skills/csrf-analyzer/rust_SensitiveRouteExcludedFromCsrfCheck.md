# Rust 关键路由绕过 CSRF 检查漏洞

## Details

### 漏洞成因
即使引入了 CSRF Guard，中间件通常允许按路径、方法或条件跳过检查（例如 `allowlist`, `skip_paths`). 若敏感路由（如 `/admin/delete`, `/api/transfer`) 被错误地加入豁免列表，或路由重构后路径匹配规则变化，CSRF 防护将形同虚设。常见于 Actix `Csrf::skipped_paths`, Axum `Layer::layer_if`, Rocket 使用 `Fairing` 时针对特定路由禁用。

### 代码示例

**易受攻击的代码：**
```rust
let csrf = Csrf::new(b"secret")
    .skipped_paths(vec!["/api/"])
    .cookie_name("csrf-token");

let app = App::new()
    .wrap(csrf)
    .route("/api/user/delete", web::post().to(delete_user)); // 敏感端点被跳过
```

**另一个不安全示例（Rocket）：**
```rust
#[launch]
fn rocket() -> _ {
    rocket::build()
        .attach(CsrfTokenFairing::default().allow_path("/webhook"))
        // `/webhook` 同时处理管理员审批请求，误被允许
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- `skipped_paths`, `allow_path`, `exempt`, `skip_check`
- 条件判断：`if path.starts_with("/api/") { return true; }`
- 路由定义：`route("/admin", ...)`, `Router::route`

**定位步骤：**
1. 搜索 CSRF 中间件配置，查看豁免路径列表。
2. 核查敏感路由是否包含在豁免模式中（通配符、前缀匹配）。
3. 跳读（L2）路由配置文件，确认新增路由是否落入豁免。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **精确匹配**：只豁免第三方回调并验证签名。
- **测试覆盖**：自动化测试验证关键路由含 CSRF 检查。
- **日志与告警**：记录被豁免路由及访问。

**定位技巧：**
- 注意大小写、尾斜杠等字符串匹配差异。
- 检查 API 版本更迭时是否更新豁免规则。
- 确认路由分组是否在 wrap 顺序上覆盖。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 豁免仅限可信第三方回调 | **L0（快速跳过）** | 风险低 |
| 敏感端点被通配符豁免 | **L3（逐行读）** | 高风险 |
| 路由重构导致豁免范围扩大 | **L4（跨模块追踪）** | 极高风险 |
| 豁免列表无文档或测试 | **L2（跳读）** | 需补充治理 |

## Classify

### 研判标准

#### 确认漏洞
需满足：
1. CSRF 中间件对敏感路由豁免。
2. 路由依赖 Cookie/Session。
3. 无额外签名或验证机制。

#### 误报
以下情况非漏洞：
1. 豁免路由仅用于第三方回调且带签名验证。
2. 接口使用 Bearer Token，不依赖 Cookie。
3. 豁免的是只读 GET 接口。

#### 代码异味
需记录：
1. `skip_paths` 使用通配符，例如 `"/api/"`.
2. 配置散落在多个模块，难以维护。
3. 缺少审计，开发者不清楚豁免影响。
4. 依赖环境变量控制豁免，生产与测试不同。

## Low risk

### 低风险评级场景

#### 1. 可信回调 + 签名
- **场景：** 仅第三方回调被豁免且验证签名。
- **风险评估：** 较低，但需保证签名正确。

#### 2. 内部 API
- **场景：** 豁免路径仅内部服务调用。
- **风险评估：** 攻击面有限。

#### 3. 多层验证
- **场景：** 路由虽豁免，但仍需管理员审批/PIN。
- **风险评估：** 提高攻击成本。

#### 4. 审计告警
- **场景：** 记录豁免路由访问并设告警。
- **风险评估：** 有助于发现异常，仍需收紧豁免。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 签名验证 | 可信来源 | 中 |
| 内部 API | 攻击面有限 | 中 |
| 多重验证 | 提高攻击成本 | 中 |
| 审计告警 | 提升检测能力 | 高（需优化配置）|
