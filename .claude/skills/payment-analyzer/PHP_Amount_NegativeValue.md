# PHP_Amount_NegativeValue

## Details

**核心漏洞特征**：PHP应用中金额字段未验证为正数，允许负数金额操作，导致反向扣款或充值漏洞。

**代码示例定位**：查找金额验证代码，关键词包括 `$amount`, `$price`, `$balance`, `validate`, `check` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `$amount = $_POST['amount']` - 检查是否直接使用客户端输入
- 搜索 `if ($amount <` - 检查是否验证正数
- 搜索 `UPDATE users SET balance = balance -` - 检查减法操作
- 搜索 `is_numeric()` 但无符号检查 - 检查验证逻辑

**快速定位保护机制**（L2: 跳读）：
- 检查是否有金额范围验证（>0, <MAX）
- 检查是否在数据库级别有CHECK约束
- 检查是否有金额类型验证
- 检查是否记录异常金额操作

## Classify

**漏洞判定标准**：
- 无金额正数验证 → **漏洞**
- 允许负数金额输入 → **漏洞**
- 无金额上界验证 → **漏洞**
- 数据库无CHECK约束 → **漏洞**

**误报情况**：
- 有明确的金额范围验证 → 低风险
- 数据库CHECK约束 → 低风险
- 类型验证正确 → 低风险

**代码异味**：
- 虽有验证但不完整 → 审计
- 某些路径缺少验证 → 审计

## Low risk

**低风险评级条件**：
1. **范围验证**：金额必须 > 0 且 < MAX_AMOUNT
2. **类型验证**：使用Decimal或整数，非浮点
3. **数据库约束**：CHECK (amount > 0)
4. **统一单位**：全局使用分为单位
5. **异常日志**：异常金额操作有警告日志
