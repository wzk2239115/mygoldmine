# Java_PaymentCallback_SignatureVerification

## Details

**核心漏洞特征**：Java应用中回调签名验证不完整或逻辑有缺陷，允许伪造的支付通知被接受。

**代码示例定位**：查找签名验证代码，关键词包括 `verify()`, `signature`, `hmac`, `MessageDigest` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `mac.doFinal()` - 检查HMAC计算
- 搜索 `equals()` - 检查签名比对
- 搜索 `MessageDigest` - 检查摘要算法
- 搜索验证逻辑 - 检查是否全面

**快速定位保护机制**（L2: 跳读）：
- 检查是否使用HMAC-SHA256
- 检查是否验证所有参数
- 检查是否使用timing-safe比对
- 检查是否验证时间戳

## Classify

**漏洞判定标准**：
- 无签名验证 → **漏洞**
- 使用弱算法（MD5）→ **漏洞**
- 仅验证部分参数 → **漏洞**
- 使用==比对签名 → **漏洞**

**误报情况**：
- 完整的HMAC-SHA256验证 → 低风险
- 所有参数都验证 → 低风险
- 使用MessageDigest.isEqual() → 低风险

**代码异味**：
- 虽有验证但有跳过路径 → 审计
- 验证逻辑复杂 → 审计

## Low risk

**低风险评级条件**：
1. **算法强度**：HMAC-SHA256或更强
2. **参数完整**：验证所有回调参数
3. **安全比对**：使用MessageDigest.isEqual()
4. **时间验证**：验证回调时间戳
5. **失败处理**：验证失败拒绝并记录
