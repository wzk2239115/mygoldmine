# PHP_Callback_ReplayAttack

## Details

**核心漏洞特征**：PHP支付回调处理无重放保护，缺少时间戳验证、消息ID去重、随机数校验，攻击者可拦截并重复发送回调通知，导致重复扣款、重复充值。

**代码示例定位**：查找支付回调处理函数（通常命名为 `handleCallback()`, `processPaymentNotification()`, `webhookHandler()`），关键词包括 `$_POST`, `$_REQUEST`, `json_decode()`, `verify signature` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `isset($_POST['trade_id'])` - 检查回调参数处理
- 搜索 `hash_hmac()` 或 `md5()` - 检查签名验证逻辑
- 搜索 `INSERT INTO orders` 或数据库更新操作 - 检查是否验证重复
- 搜索时间戳变量 (`timestamp`, `time`, `notify_time`) - 检查时间验证

**快速定位保护机制**（L2: 跳读）：
- 检查是否有时间戳检查（±5分钟内有效）
- 检查是否有消息ID去重（数据库唯一约束或SELECT检查）
- 检查是否验证签名（HMAC-SHA256）
- 检查是否有数据库事务确保幂等性（UPDATE WHERE NOT EXISTS或UNIQUE约束）

## Classify

**漏洞判定标准**：
- 回调处理无签名验证 → **漏洞**
- 无时间戳验证或验证不严格（允许旧消息重放） → **漏洞**
- 无消息ID去重机制 → **漏洞**
- 更新订单状态前无幂等性检查 → **漏洞**
- 直接使用回调数据更新订单，无验证 → **漏洞**

**误报情况**：
- 有完整的签名验证（HMAC-SHA256）+ 时间戳检查 → 低风险
- 数据库有UNIQUE约束确保消息ID唯一 → 低风险
- 业务逻辑中有幂等性设计（如状态机）→ 低风险

**代码异味**：
- 签名验证使用弱算法（MD5）→ 审计
- 时间戳验证不严格（允许偏差> 10分钟） → 审计
- 消息ID存储但未用于去重 → 审计

## Low risk

**低风险评级条件**：
1. **签名验证**：使用HMAC-SHA256或更强算法验证回调签名
2. **时间戳检查**：验证消息时间戳在可接受范围内（±5分钟）
3. **消息去重**：每条回调消息有唯一ID，数据库记录并检查重复
4. **幂等性设计**：业务逻辑或数据库约束确保重复回调不会重复扣款
5. **IP白名单**：可选加强，仅接受来自支付服务器的IP地址
