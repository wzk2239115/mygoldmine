# Go_Amount_IntegerOverflow

## Details

**核心漏洞特征**：Go应用中金额字段整数溢出，特别是使用int而非uint64，导致计算结果不正确或金额翻转。

**代码示例定位**：查找金额计算代码，关键词包括 `int`, `int64`, `balance`, `amount`, `+`, `*` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `var amount int` - 检查是否使用int而非uint64
- 搜索 `amount + ` - 检查是否有溢出保护
- 搜索 `math.MaxInt` 或边界检查 - 检查是否验证范围
- 搜索强制转换 `int64(x) + int64(y)` - 检查转换逻辑

**快速定位保护机制**（L2: 跳读）：
- 检查金额字段声明类型（应使用uint64或Decimal）
- 检查是否有最大值和最小值验证
- 检查所有算术操作是否有边界检查
- 检查是否有溢出时的错误处理

## Classify

**漏洞判定标准**：
- 使用有符号整数（int/int64）表示金额 → **漏洞**
- 无边界验证直接进行算术运算 → **漏洞**
- 溢出时未返回错误或异常 → **漏洞**
- 浮点表示金额 → **漏洞**

**误报情况**：
- 使用uint64表示金额且有边界检查 → 低风险
- 使用Decimal库 → 低风险
- 有明确的最大值验证 → 低风险

**代码异味**：
- 虽有检查但逻辑不完整 → 审计
- 某些操作路径缺少检查 → 审计

## Low risk

**低风险评级条件**：
1. **类型选择**：使用uint64或Decimal表示金额
2. **范围验证**：所有金额输入有最大值检查
3. **操作安全**：所有算术运算前验证不会溢出
4. **统一单位**：全局使用分或元，不混用
5. **错误处理**：溢出情况返回错误而非继续
