# Rust_Amount_OverflowHandling

## Details

**核心漏洞特征**：Rust支付应用中金额字段溢出处理不当，大金额操作导致整数溢出或浮点精度丧失，造成金额计算错误。

**代码示例定位**：查找金额计算代码，关键词包括 `balance`, `amount`, `total`, `+`, `*`, `as i64`, `as f64` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `amount +` 或 `balance -` - 检查溢出保护
- 搜索 `.checked_add()` 或 `.saturating_add()` - 检查是否使用安全操作
- 搜索 `as i64` 或类型转换 - 检查是否有边界检查
- 搜索 `f64` 或浮点计算 - 检查浮点精度问题

**快速定位保护机制**（L2: 跳读）：
- 检查是否使用Decimal库处理金额（如rust_decimal）
- 检查是否使用checked/saturating操作而非普通运算
- 检查是否有上下界验证
- 检查是否有单位统一（分/元）

## Classify

**漏洞判定标准**：
- 使用普通 `+`, `-`, `*` 运算无溢出检查 → **漏洞**
- 直接使用浮点数表示金额 → **漏洞**
- 无金额上下界验证 → **漏洞**
- 不同单位混合使用无转换 → **漏洞**

**误报情况**：
- 使用Decimal类库和checked操作 → 低风险
- 有明确的边界检查和验证 → 低风险
- 统一使用整数表示（分为单位） → 低风险

**代码异味**：
- 有溢出检查但未处理溢出情况 → 审计
- 浮点操作但有四舍五入逻辑 → 审计

## Low risk

**低风险评级条件**：
1. **类型选择**：使用Decimal或i64整数表示金额
2. **运算安全**：使用checked/saturating操作或库函数
3. **边界检查**：金额有最大值和最小值限制
4. **单位统一**：全局统一使用分或元，不混用
5. **错误处理**：溢出和异常情况有明确处理
