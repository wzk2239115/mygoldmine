# Rust_Callback_VerificationIncomplete

## Details

**核心漏洞特征**：Rust支付回调验证不完整，缺少签名验证、时间戳检查或消息ID去重，攻击者可伪造或重放回调。

**代码示例定位**：查找回调处理代码，关键词包括 `verify`, `signature`, `callback`, `webhook`, `hmac` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `hmac::verify()` 或 `verify_signature()` - 检查签名验证
- 搜索 `timestamp` 或时间相关逻辑 - 检查时间验证
- 搜索 `callback_id` 或 `message_id` - 检查去重机制
- 搜索 `if signature ==` - 检查验证逻辑

**快速定位保护机制**（L2: 跳读）：
- 检查是否验证HMAC签名（使用hmac库）
- 检查是否验证时间戳（±N秒）
- 检查是否有回调ID去重
- 检查是否记录回调日志

## Classify

**漏洞判定标准**：
- 无签名验证 → **漏洞**
- 无时间戳验证 → **漏洞**
- 无消息去重 → **漏洞**
- 验证不完整（只验证部分字段） → **漏洞**

**误报情况**：
- 完整的HMAC验证+时间戳检查 → 低风险
- 有消息ID去重 → 低风险
- 多层验证 → 低风险

**代码异味**：
- 验证逻辑分散 → 审计
- 验证失败无日志 → 审计

## Low risk

**低风险评级条件**：
1. **签名验证**：使用HMAC验证回调签名
2. **时间检查**：验证时间戳在可接受范围
3. **消息去重**：检查回调ID是否已处理
4. **完整性检查**：验证所有关键字段
5. **日志记录**：所有验证失败都有日志
