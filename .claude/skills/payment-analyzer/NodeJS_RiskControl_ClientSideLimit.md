# NodeJS_RiskControl_ClientSideLimit

## Details

**核心漏洞特征**：NodeJS应用中风控限制完全在客户端实现，可被绕过或禁用。

**代码示例定位**：查找客户端代码和风控实现，关键词包括 `if (count < limit)`, `disabled`, `localStorage` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索JavaScript中的风控逻辑 - 检查是否客户端
- 搜索disabled按钮属性 - 检查是否客户端禁用
- 搜索localStorage或sessionStorage - 检查是否本地存储
- 搜索计数器逻辑 - 检查是否信任客户端数据

**快速定位保护机制**（L2: 跳读）：
- 检查是否有服务端风控
- 检查是否验证请求频率
- 检查是否有IP/用户维度的限制
- 检查是否有异常检测

## Classify

**漏洞判定标准**：
- 风控仅在客户端 → **漏洞**
- 可通过禁用JavaScript绕过 → **漏洞**
- 无服务端验证 → **漏洞**
- 计数器可被篡改 → **漏洞**

**误报情况**：
- 有服务端风控 → 低风险
- 客户端仅用于用户体验 → 低风险
- 服务端强制执行 → 低风险

**代码异味**：
- 虽有服务端但与客户端不一致 → 审计
- 客户端限制过宽 → 审计

## Low risk

**低风险评级条件**：
1. **服务端强制**：风控限制必须在服务端实现
2. **独立验证**：服务端独立验证频率
3. **多维度限制**：按IP、用户维度限制
4. **异常检测**：检测异常行为
5. **客户端辅助**：客户端仅用于UX，非安全控制
