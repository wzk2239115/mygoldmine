# NodeJS_PaymentState_ClientTampering

## Details

**核心漏洞特征**：NodeJS应用中支付状态存储在客户端（Cookie、Session、本地存储等），可被篡改。

**代码示例定位**：查找状态管理代码，关键词包括 `req.session`, `req.cookies`, `localStorage`, `order_status` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `req.session.order_status =` - 检查状态存储位置
- 搜索 `res.cookie()` - 检查是否使用Cookie存储
- 搜索客户端状态 - 检查是否从请求中读取
- 搜索 `req.body.status` - 检查是否信任客户端数据

**快速定位保护机制**（L2: 跳读）：
- 检查状态是否存储在服务端
- 检查是否验证客户端状态
- 检查是否使用数据库存储
- 检查是否有状态转换验证

## Classify

**漏洞判定标准**：
- 状态存储在客户端 → **漏洞**
- 直接信任客户端状态 → **漏洞**
- 无服务端验证 → **漏洞**
- Session未签名 → **漏洞**

**误报情况**：
- 状态存储在服务端 → 低风险
- 有服务端验证 → 低风险
- Session签名 → 低风险

**代码异味**：
- 虽有验证但不完整 → 审计
- 某些状态被信任 → 审计

## Low risk

**低风险评级条件**：
1. **服务端存储**：状态完全存储在服务端数据库
2. **会话管理**：使用Session ID而非直接存储状态
3. **签名保护**：Session数据被签名防篡改
4. **验证强制**：所有操作都验证服务端状态
5. **审计日志**：状态变化都被记录
