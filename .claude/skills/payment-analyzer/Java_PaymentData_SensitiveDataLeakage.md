# Java_PaymentData_SensitiveDataLeakage

## Details

**核心漏洞特征**：Java应用中敏感支付数据（卡号、密码、CVV等）在日志、错误消息或内存中泄露。

**代码示例定位**：查找日志和输出代码，关键词包括 `log.`, `System.out`, `toString()`, `printStackTrace()` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `log.info(payment)` 或 `log.error(e)` - 检查是否记录敏感数据
- 搜索 `toString()` 方法 - 检查是否输出敏感数据
- 搜索 `printStackTrace()` - 检查是否暴露堆栈跟踪
- 搜索 `System.out.println()` - 检查控制台输出

**快速定位保护机制**（L2: 跳读）：
- 检查是否masking或redacting敏感字段
- 检查日志级别是否适当
- 检查toString()是否排除敏感字段
- 检查异常处理是否暴露详情

## Classify

**漏洞判定标准**：
- 日志记录卡号或密码 → **漏洞**
- toString()输出敏感数据 → **漏洞**
- 错误信息暴露堆栈跟踪 → **漏洞**
- 控制台输出敏感数据 → **漏洞**

**误报情况**：
- 敏感字段被masking → 低风险
- 异常消息不包含敏感数据 → 低风险
- 只记录交易ID不记录详情 → 低风险

**代码异味**：
- 虽有masking但不完整 → 审计
- 某些路径未被masking → 审计

## Low risk

**低风险评级条件**：
1. **字段掩码**：敏感字段在日志中被掩码（如****1234）
2. **选择日志**：仅记录非敏感字段（交易ID、金额类别）
3. **异常处理**：异常消息不包含敏感数据
4. **输出清理**：toString()排除敏感字段
5. **日志级别**：敏感操作使用DEBUG而非INFO级别
