# NodeJS_PaymentData_PlainTextTransmission

## Details

**核心漏洞特征**：NodeJS应用中敏感支付数据通过HTTP明文或不安全的HTTPS传输，可被截取。

**代码示例定位**：查找网络通信代码，关键词包括 `http://`, `request()`, `fetch()`, `https` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `http://` - 检查是否有HTTP链接
- 搜索 `http.request()` - 检查协议选择
- 搜索 `request({ url: ...})` - 检查是否HTTPS
- 搜索支付相关请求 - 检查是否加密

**快速定位保护机制**（L2: 跳读）：
- 检查是否强制HTTPS
- 检查是否验证证书
- 检查是否有密钥加密额外层
- 检查传输中的数据加密

## Classify

**漏洞判定标准**：
- 支付数据通过HTTP传输 → **漏洞**
- HTTPS但不验证证书 → **漏洞**
- 无额外的数据加密层 → **漏洞**
- 明文存储敏感数据 → **漏洞**

**误报情况**：
- 强制HTTPS + 证书验证 → 低风险
- 传输层加密 → 低风险
- TLS 1.2+ → 低风险

**代码异味**：
- 虽有HTTPS但证书验证可绕过 → 审计
- 跳过证书验证 → 审计

## Low risk

**低风险评级条件**：
1. **强制HTTPS**：所有支付请求使用HTTPS
2. **证书验证**：验证服务器证书有效性
3. **TLS版本**：使用TLS 1.2或更新
4. **额外加密**：敏感数据有额外加密层
5. **HSTS**：使用HTTP Strict-Transport-Security头
