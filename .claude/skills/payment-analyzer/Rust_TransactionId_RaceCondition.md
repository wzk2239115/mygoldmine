# Rust_TransactionId_RaceCondition

## Details

**核心漏洞特征**：Rust应用中交易ID生成或验证存在竞态条件，并发请求可能生成相同的ID或绕过唯一性检查。

**代码示例定位**：查找并发代码和ID相关逻辑，关键词包括 `tokio`, `async`, `Mutex`, `Arc`, `transaction_id` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `Arc<Mutex>` 或同步原语 - 检查并发保护
- 搜索 `tokio::spawn()` - 检查异步任务
- 搜索 `SELECT ... FOR UPDATE` - 检查数据库锁
- 搜索ID检查和INSERT之间的代码 - 检查原子性

**快速定位保护机制**（L2: 跳读）：
- 检查是否使用数据库级别的UNIQUE约束
- 检查是否使用悲观锁（SELECT ... FOR UPDATE）
- 检查是否使用乐观锁（版本号）
- 检查异步操作是否有正确同步

## Classify

**漏洞判定标准**：
- 检查和INSERT非原子操作 → **漏洞**
- 无数据库约束保护 → **漏洞**
- 异步代码无同步保护 → **漏洞**
- 并发修改ID无锁 → **漏洞**

**误报情况**：
- UNIQUE约束+INSERT错误处理 → 低风险
- 使用悲观锁 → 低风险
- 异步原子操作 → 低风险

**代码异味**：
- 虽有锁但范围太小 → 审计
- 锁的粒度不恰当 → 审计

## Low risk

**低风险评级条件**：
1. **数据库约束**：UNIQUE约束确保ID唯一
2. **原子操作**：检查和INSERT在同一事务
3. **锁保护**：异步操作有正确的Mutex或锁
4. **错误处理**：冲突异常正确处理
5. **测试覆盖**：并发场景有单元测试
