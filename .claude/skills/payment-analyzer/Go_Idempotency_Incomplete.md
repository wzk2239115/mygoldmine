# Go_Idempotency_Incomplete

## Details

**核心漏洞特征**：Go应用中支付幂等性实现不完整，虽然有幂等性设计但某些操作路径或边界情况未覆盖。

**代码示例定位**：查找支付处理代码，关键词包括 `idempotentKey`, `Idempotency-Key`, `cache`, `database` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `Idempotency-Key` 或 `idempotent_key` - 检查幂等Key实现
- 搜索 `cache.Get()` 或 `redis` - 检查是否缓存结果
- 搜索支付处理逻辑 - 检查所有路径是否幂等
- 搜索错误处理 - 检查异常路径

**快速定位保护机制**（L2: 跳读）：
- 检查幂等Key是否应用于所有支付操作
- 检查缓存的Key和过期时间
- 检查数据库事务设计
- 检查异常恢复机制

## Classify

**漏洞判定标准**：
- 某些操作路径缺少幂等性检查 → **漏洞**
- 幂等Key在某些情况被忽略 → **漏洞**
- 缓存不完整或过期时间不合理 → **漏洞**
- 异常情况不幂等 → **漏洞**

**误报情况**：
- 所有路径都有幂等检查 → 低风险
- 完整的缓存和去重 → 低风险
- 异常也幂等 → 低风险

**代码异味**：
- 虽有幂等但未覆盖重试情况 → 审计
- 幂等Key来源不可信 → 审计

## Low risk

**低风险评级条件**：
1. **Key生成**：客户端生成唯一的幂等性Key
2. **存储方案**：Key和结果缓存在Redis或数据库
3. **完整覆盖**：所有支付操作都使用幂等Key
4. **异常处理**：异常情况也被幂等化
5. **过期管理**：缓存有合理的过期时间（如24小时）
