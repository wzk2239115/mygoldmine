# Go_RiskControl_FrequencyLimit

## Details

**核心漏洞特征**：Go应用中风控频率限制实现不当，允许用户进行高频操作（快速转账、充值等），导致风险控制失效。

**代码示例定位**：查找频率限制代码，关键词包括 `limit`, `rate`, `frequency`, `counter`, `timestamp` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `time.Since()` 或时间比对 - 检查时间窗口
- 搜索 `counter++` 或计数器 - 检查操作计数
- 搜索 `redis` 或缓存 - 检查限流实现
- 搜索 `if count >` - 检查限制检查

**快速定位保护机制**（L2: 跳读）：
- 检查是否使用令牌桶或漏桶算法
- 检查是否正确处理并发请求
- 检查限制是否按用户/IP/设备维度
- 检查是否有动态调整机制

## Classify

**漏洞判定标准**：
- 无频率限制 → **漏洞**
- 限制逻辑有漏洞 → **漏洞**
- 并发情况下绕过 → **漏洞**
- 限制维度不合理 → **漏洞**

**误报情况**：
- 使用成熟的限流库 → 低风险
- 有完整的限制逻辑 → 低风险
- 多维度限制 → 低风险

**代码异味**：
- 虽有限制但粒度不够 → 审计
- 限制标准不清晰 → 审计

## Low risk

**低风险评级条件**：
1. **算法选择**：使用令牌桶或漏桶算法
2. **库选择**：使用golang.org/x/time/rate或redis
3. **维度设置**：按用户ID、IP、设备维度限制
4. **阈值合理**：频率限制阈值与业务相符
5. **可观测性**：限制触发有日志和告警
