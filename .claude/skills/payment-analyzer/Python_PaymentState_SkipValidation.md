# Python_PaymentState_SkipValidation

## Details

**核心漏洞特征**：Python支付处理代码跳过了支付状态验证，允许订单直接从待支付转为已支付，或跳过某些验证步骤。

**代码示例定位**：查找状态检查代码，关键词包括 `if order.status`, `payment_state`, `validate`, `check_state` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `if not order.status` 或 `if order.status ==` - 检查状态验证逻辑
- 搜索 `order.status = 'PAID'` - 检查状态修改
- 搜索 `#` 注释掉的验证代码 - 检查被跳过的检查
- 搜索异常处理中的pass - 检查是否吞掉异常

**快速定位保护机制**（L2: 跳读）：
- 检查是否有显式的状态转换验证
- 检查是否使用装饰器或中间件强制检查
- 检查是否有数据库约束
- 检查日志是否记录所有状态变化

## Classify

**漏洞判定标准**：
- 缺少状态转换前的验证 → **漏洞**
- 验证逻辑被注释或跳过 → **漏洞**
- 异常被吞掉导致验证失效 → **漏洞**
- 无状态机约束 → **漏洞**

**误报情况**：
- 有显式的状态验证函数 → 低风险
- 使用装饰器强制验证 → 低风险
- 数据库约束保护 → 低风险

**代码异味**：
- 验证逻辑出现多次 → 审计
- 异常处理过宽泛 → 审计

## Low risk

**低风险评级条件**：
1. **显式验证**：支付前有明确的状态检查
2. **状态机**：使用状态枚举或常量，非字符串
3. **强制检查**：使用装饰器或中间件保证验证
4. **错误处理**：异常不被吞掉，正确传播
5. **数据库保护**：约束限制非法转换
