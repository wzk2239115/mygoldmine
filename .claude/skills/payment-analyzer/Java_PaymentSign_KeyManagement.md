# Java_PaymentSign_KeyManagement

## Details

**核心漏洞特征**：Java应用中支付签名密钥存储在代码中、明文配置文件、内存中，或使用弱密钥算法（如RSA 512位）、过期的密钥库，导致密钥被盗用或签名被伪造。

**代码示例定位**：查找密钥初始化代码（KeyStore加载、密钥对生成、签名对象创建），关键词包括 `KeyStore`, `KeyFactory`, `Signature`, `loadKeyStore()`, `getPrivateKey()`, `initSign()` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `new String("password")` 或 `"sk_live_xxx"` - 硬编码密钥或密码
- 搜索 `KeyStore.getInstance()` - 检查密钥库类型和加载方式
- 搜索 `Signature.getInstance("SHA1withRSA")` - 检查签名算法（SHA1已弃用）
- 搜索 `.jks`, `.pfx`, `.p12` 文件路径 - 检查密钥库位置和保护

**快速定位保护机制**（L3: 逐行读）：
- 检查密钥库密码是否硬编码或从环境变量加载
- 检查是否使用 `KeyStore` 管理密钥库（而非直接操作密钥数据）
- 检查签名算法是否为当前安全标准（SHA256 or higher）
- 检查密钥库文件权限（应限制为owner-readable）
- 检查是否有密钥轮换和版本管理机制

## Classify

**漏洞判定标准**：
- 密钥库密码硬编码在源代码中 → **漏洞**
- 密钥库存储在Web根目录或可访问位置 → **漏洞**
- 使用已弃用的签名算法（SHA1, MD5）→ **漏洞**
- RSA密钥长度低于2048位 → **漏洞**
- 密钥库无密码保护或密码为空 → **漏洞**

**误报情况**：
- 密钥库通过环境变量或密钥管理系统加载 → 低风险
- 使用安全标准算法（SHA256、RSA-2048+） → 低风险
- 密钥库有严格的文件权限保护 → 低风险

**代码异味**：
- 虽然密钥库加载正确，但签名验证在客户端进行 → 审计
- 密钥轮换没有版本控制机制 → 审计
- 多个应用共享同一个密钥库 → 审计

## Low risk

**低风险评级条件**：
1. **密钥保护**：密钥库及其密码通过环境变量或外部密钥管理系统管理
2. **算法强度**：使用SHA256或更高版本、RSA-2048或更强的密钥
3. **访问控制**：密钥库文件权限限制（600或更严格），仅应用进程可读
4. **密钥轮换**：定期轮换密钥（至少每年），旧密钥有撤销机制
5. **独立密钥库**：每个应用或环境使用独立的密钥库，避免共享
