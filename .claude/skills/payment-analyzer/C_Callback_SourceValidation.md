# C_Callback_SourceValidation

## Details

**核心漏洞特征**：C应用中回调源验证不当，无IP白名单检查、DNS欺骗、或源身份验证缺失，攻击者可伪造支付服务的回调。

**代码示例定位**：查找回调接收代码，关键词包括 `accept()`, `recvfrom()`, `source`, `ip`, `verify` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `recvfrom()` 或 `getpeername()` - 检查是否获取源地址
- 搜索 `strcmp(ip, ...)` - 检查是否有IP白名单
- 搜索 `gethostbyname()` 或DNS操作 - 检查是否有DNS验证
- 搜索签名验证 - 检查是否验证源身份

**快速定位保护机制**（L2: 跳读）：
- 检查是否有IP白名单检查
- 检查是否验证请求签名
- 检查是否防止DNS欺骗
- 检查是否使用HTTPS TLS验证

## Classify

**漏洞判定标准**：
- 无源IP验证 → **漏洞**
- 无签名验证 → **漏洞**
- 使用DNS作为唯一验证 → **漏洞**
- 允许HTTP明文回调 → **漏洞**

**误报情况**：
- 有IP白名单+签名验证 → 低风险
- HTTPS+TLS验证 → 低风险
- 多层验证 → 低风险

**代码异味**：
- IP白名单不完整或过宽 → 审计
- 签名验证在IP检查之后 → 审计

## Low risk

**低风险评级条件**：
1. **IP白名单**：严格的IP白名单检查
2. **签名验证**：HMAC或证书签名验证
3. **HTTPS强制**：所有回调使用HTTPS
4. **证书验证**：验证证书链和有效期
5. **日志记录**：所有回调源验证都记录
