# C_PaymentState_UncheckedTransition

## Details

**核心漏洞特征**：C/C++应用中支付状态机实现不当，缺少状态转换条件验证，允许非法的状态转换（如从"待支付"直接跳转到"已支付"），导致订单被篡改。

**代码示例定位**：查找状态管理代码（结构体中的状态字段、转换函数），关键词包括 `payment_state`, `order_status`, `setState()`, `switch(status)` 等。

**快速定位核心操作**（L1: 关键词扫描）：
- 搜索 `order->status = PAID` - 直接赋值状态无检查
- 搜索 `switch(current_state)` - 检查所有分支的转换限制
- 搜索 `memcpy()` 或 `strcpy()` - 检查状态复制
- 搜索指针操作 `order->state` - 检查是否可被直接修改

**快速定位保护机制**（L3: 逐行读）：
- 检查是否有状态转换验证函数 `is_valid_transition()`
- 检查是否使用枚举而非字符串表示状态
- 检查是否有多层防护（应用+数据库约束）
- 检查是否记录状态转换日志

## Classify

**漏洞判定标准**：
- 允许任意状态转换无条件检查 → **漏洞**
- 状态通过直接赋值修改无转换函数 → **漏洞**
- 状态作为字符串而非枚举 → **漏洞**
- 无状态转换审计日志 → **漏洞**

**误报情况**：
- 有明确的状态转换验证函数 → 低风险
- 使用状态枚举+转换白名单 → 低风险
- 数据库有约束防止非法转换 → 低风险

**代码异味**：
- 状态转换逻辑散落多个函数 → 审计
- 状态转换日志不完整 → 审计

## Low risk

**低风险评级条件**：
1. **状态定义**：使用枚举或常量定义状态
2. **转换验证**：所有转换通过统一验证函数
3. **原子操作**：状态转换在数据库事务中
4. **审计记录**：所有转换有日志记录
5. **多层防护**：应用层验证+数据库约束
