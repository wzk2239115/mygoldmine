# Python 上传存储权限配置漏洞

## Details

### 漏洞成因
Python 应用常将上传文件保存到本地文件系统、NFS、S3/GCS 等对象存储。如果保存路径与应用同一权限、缺乏随机命名、ACL 配置为公开读写或访问地址固定可预测，攻击者可访问、篡改或覆盖他人文件。常见问题包括 Django `MEDIA_ROOT`、Flask 静态目录、S3 设置 `public-read`、未使用签名 URL、未限制下载权限等。

### 代码示例

**易受攻击的代码：**
```python
def save_file(file):
    filename = file.filename  # 未随机化
    dest = os.path.join("/var/www/app/media", filename)
    file.save(dest)  # 目录可执行且 Web 可访问
    return f"https://cdn.example.com/media/{filename}"
```

```python
import boto3

s3 = boto3.client("s3")
def upload_s3(file):
    key = f"user_uploads/{file.filename}"
    s3.put_object(Bucket=BUCKET, Key=key, Body=file.read(), ACL="public-read")
    return f"https://{BUCKET}.s3.amazonaws.com/{key}"
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- Django `settings.MEDIA_ROOT`, `MEDIA_URL`, `FileSystemStorage`
- Flask/FastAPI `STATIC_FOLDER`, `send_from_directory`
- 对象存储：`boto3`, `google.cloud.storage`, `azure.storage.blob`
- ACL 配置：`ACL`, `public-read`, `make_public`, `SignedUrl`

**定位步骤：**
1. 搜索保存文件的函数，检查是否使用原始文件名、固定路径。
2. 查看对象存储上传代码，确认是否设置公开权限或返回永久 URL。
3. 跳读（L2）确认是否存在覆盖、预测文件名、缺乏鉴权或加密。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **随机命名：** 使用 UUID、哈希、用户 ID 组合命名，防止枚举。
- **访问鉴权：** 通过签名 URL、临时令牌访问文件，限制有效期与操作。
- **权限最小化：** 对象存储使用私有 ACL，应用使用 IAM 角色/策略最小权限。
- **元数据控制：** 配置 `Content-Disposition=attachment`、`Content-Type`，防止 XSS。
- **日志与审计：** 开启 access log，监控异常下载或覆盖行为。

**定位技巧：**
- 检查是否允许覆盖已有文件或缺少版本控制。
- 查看是否对下载进行权限校验或速率限制。
- 确认加密/备份策略是否到位，防止数据泄露或篡改。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 私有存储 + 随机命名 + 签名访问 | **L0（快速跳过）** | 风险低 |
| 公共读但仅包含非敏感资源 | **L2（跳读）** | 检查是否可能上传脚本 |
| 公共目录 + 可预测文件名 | **L3（逐行读）** | 高风险 |
| 存储与多租户共用且无隔离 | **L4（跨模块追踪）** | 需全链路审计 |

## Classify

### 研判标准

#### 确认漏洞
满足以下条件可判定为存储权限漏洞：
1. 上传文件保存位置可被未经授权的用户访问、覆盖或执行。
2. 缺少随机命名、目录隔离或加密，导致文件易被枚举或篡改。
3. 访问方式直接暴露 URL，无鉴权或签名控制。

#### 误报
以下情况属于误报：
1. 上传的仅为公开内容（如静态图片），且无安全影响。
2. 存储层已通过签名 URL、临时凭证控制访问，并记录审计。
3. 文件访问需通过后端授权，且文件名随机不可预测。

#### 代码异味
需记录的风险：
1. 对象存储采用 `public-read` 模式，未来上传敏感文件将受威胁。
2. Web 服务器与上传目录权限一致，易被覆盖篡改。
3. 缺乏删除/过期策略，导致敏感文件长期可访问。
4. 访问日志缺失，难以追踪泄露事件。

## Low risk

### 低风险评级场景

#### 1. 内部系统专用
- **场景：** 文件仅供内部系统访问，并有严格权限控制。
- **风险评估：** 攻击面小，但需防内鬼。

#### 2. 短期签名访问
- **场景：** 所有下载需签名 URL 且有效期短。
- **风险评估：** 风险较低，需确保存储策略安全。

#### 3. 加密存储 + 备份
- **场景：** 文件加密后存储，并定期备份。
- **风险评估：** 降低敏感数据泄露影响。

#### 4. 审计监控
- **场景：** 对象存储与应用层均记录访问日志、异常告警。
- **风险评估：** 有助于快速发现问题，仍需配合防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部访问控制 | 攻击面有限 | 中 |
| 签名 URL + 随机命名 | 技术防护完善 | 低 |
| 加密存储 | 降低泄露价值 | 中 |
| 日志与告警 | 提高发现能力 | 高（持续优化）|
