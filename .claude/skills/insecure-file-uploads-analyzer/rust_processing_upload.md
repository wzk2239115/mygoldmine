# Rust 上传解析与处理漏洞

## Details

### 漏洞成因
Rust 微服务在上传后经常使用 `image`, `imageproc`, `pdfium-render`, `lopdf`, `ffmpeg-cli-wrapper`, `zip` 等 crate 处理图像、PDF、音视频或压缩包。如果缺乏文件头验证、资源限制（像素、页数、时长）、沙箱隔离或超时控制，攻击者可利用恶意文件触发解析库中的漏洞、执行外部命令、制造压缩炸弹，导致拒绝服务甚至远程代码执行。

### 代码示例

**易受攻击的代码：**
```rust
fn generate_thumbnail(path: &Path) -> Result<()> {
    let img = image::open(path)?; // 未限制像素、格式
    let thumbnail = img.thumbnail(512, 512);
    thumbnail.save(path.with_extension("thumb.jpg"))?;
    Ok(())
}
```

```rust
fn extract_pdf_text(path: &Path) -> anyhow::Result<String> {
    let doc = lopdf::Document::load(path)?; // 未限制页数或内嵌对象
    Ok(doc.extract_text()?)
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 图像处理：`image::open`, `DynamicImage`, `resize`, `thumbnail`
- PDF/文档：`lopdf`, `pdfium`, `pdf_extract`, `office`, `docx-rs`
- 压缩：`zip`, `flate2`, `tar`, `xz2`
- 外部命令：`Command::new("ffmpeg")`, `std::process::Command`

**定位步骤：**
1. 搜索上传后调用的解析/转换函数，确认是否有限制。
2. 检查是否在 `async` 任务/worker 中运行，是否设置超时。
3. 跳读（L2）确认是否验证格式、像素、页数、防止压缩炸弹。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **格式白名单：** 在解析前通过 `infer`、`magic` 确认类型。
- **资源限制：** 控制最大像素、页数、音视频时长，使用 `image::ImageDecoderLimits` 等。
- **沙箱执行：** 在子进程或容器中处理，使用 `seccomp`, `cgroups`.
- **超时控制：** `Command::spawn` 配合 `tokio::time::timeout`.
- **错误处理：** 捕获解析异常，记录日志并隔离文件。

**定位技巧：**
- 检查 `zip` 提取是否验证路径、防止目录穿越。
- 确认临时文件位置与权限，处理完成后是否删除。
- 追踪处理结果是否直接暴露给用户或其他服务。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 限制资源 + 沙箱执行 + 日志监控 | **L0（快速跳过）** | 风险低 |
| 部分限制但共享主进程权限 | **L2（跳读）** | 需强化隔离 |
| 任意文件直接进入解析流程 | **L3（逐行读）** | 高风险 |
| 处理结果被下游系统信任 | **L4（跨模块追踪）** | 需审计全链路 |

## Classify

### 研判标准

#### 确认漏洞
需满足：
1. 上传文件在处理前未充分验证类型、大小、资源限制。
2. 解析或转换在主进程/高权限环境执行，缺乏沙箱。
3. 攻击者可利用恶意文件导致 RCE、DoS 或覆盖数据。

#### 误报
以下情形可视为误报：
1. 处理在隔离容器/子进程执行，并设置严格限制。
2. 文件来自可信渠道，且已在上游完成扫描验证。
3. 处理结果不对外暴露，且经过人工审核。

#### 代码异味
需记录的风险：
1. 使用默认 `image` 解码器限制，易受压缩炸弹影响。
2. 缺乏处理失败日志，难以发现攻击。
3. `Command::new` 未处理返回码，忽略失败。
4. 多线程处理共享临时目录，易发生竞争或覆盖。

## Low risk

### 低风险评级场景

#### 1. 内部批处理
- **场景：** 上传仅内部使用，文件来源可信。
- **风险评估：** 攻击面有限，但需防内部滥用。

#### 2. 容器沙箱处理
- **场景：** 每次解析在临时容器执行并限制资源。
- **风险评估：** 风险较低，仍需监控逃逸。

#### 3. 仅读取元数据
- **场景：** 处理过程仅提取安全元信息，不生成可执行输出。
- **风险评估：** 降低利用价值。

#### 4. 监控告警
- **场景：** 结合监控发现异常处理次数、失败率。
- **风险评估：** 有助于快速响应，需配合防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部可信来源 | 攻击面有限 | 中 |
| 容器沙箱 + 限制 | 阻断利用 | 低 |
| 仅读元数据 | 降低危害 | 中 |
| 监控告警 | 提升响应能力 | 高（持续优化）|
