# C/C++ 上传沙箱与隔离漏洞

## Details

### 漏洞成因
为处理用户上传的文件，许多 C/C++ 服务会调用外部命令（如 ImageMagick、FFmpeg、Ghostscript）、内部脚本或插件来转换、扫描或生成预览。如果未在独立沙箱中运行这些操作、缺少 seccomp/AppArmor/SELinux 限制或未隔离文件系统权限，攻击者可以借助恶意文件触发解析器漏洞或命令注入，从而突破沙箱、执行任意代码、横向移动。此外，上传后文件常被放置于共享目录或 NFS/Samba，权限配置不当也会导致信息泄露或恶意覆盖。

### 代码示例

**易受攻击的代码：**
```c
void convert_to_pdf(const char *input_path, const char *output_path) {
    char cmd[1024];
    // 未对路径做任何净化，且直接调用外部命令
    snprintf(cmd, sizeof(cmd), "gs -dSAFER -sDEVICE=pdfwrite -o %s %s", output_path, input_path);
    system(cmd); // 若 gs 存在漏洞，可被恶意文件利用取得 RCE
}
```

**另一个不安全示例（共享目录缺少隔离）：**
```cpp
bool save_and_publish(const std::string &filename, const std::vector<uint8_t> &data) {
    std::string path = "/var/www/html/uploads/" + filename;
    std::ofstream out(path, std::ios::binary);
    out.write(reinterpret_cast<const char*>(data.data()), data.size());
    // /uploads 可被 Web 服务器直接执行或访问，且未配置权限
    return out.good();
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 外部命令调用：`system`, `popen`, `execve`, `fork`, `ProcessBuilder`
- 插件/脚本加载：`dlopen`, `LoadLibrary`, `luaL_dostring`, `py_run`
- 沙箱配置：`seccomp`, `setrlimit`, `chroot`, `namespace`
- 权限设置：`chmod`, `chown`, `umask`, NFS/Samba 配置

**定位步骤：**
1. 搜索处理上传文件后调用的外部命令或库，评估是否有安全配置。
2. 查看是否对上传文件设置了执行权限或放置在可执行目录。
3. 跳读（L2）相关代码，确认是否使用沙箱、限权、临时目录隔离。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **沙箱机制：** 使用 chroot、Linux namespaces、seccomp、AppArmor、SELinux。
- **限权运行：** 上传处理进程以低权限用户运行，并限制资源（CPU、内存、时间）。
- **隔离存储：** 上传目录标记为不可执行、使用随机子目录。
- **审计与告警：** 对外部命令调用、沙箱逃逸尝试进行日志记录。
- **回调验证：** 文件转储到对象存储前需通过安全扫描/签名验证。

**定位技巧：**
- 检查 `system`、`popen` 是否使用可信参数，是否存在命令拼接。
- 确认沙箱配置是否与生产环境一致，而非仅在开发模式启用。
- 追踪上传文件在生命周期内的权限变更与访问逻辑。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 外部处理在强制沙箱 + 最小权限环境运行 | **L0（快速跳过）** | 风险较低 |
| 仅使用部分限权（如 setuid 低权限用户） | **L2（跳读）** | 检查是否存在绕过 |
| 直接 `system` 调用或共享可执行目录 | **L3（逐行读）** | 高风险 |
| 上传文件影响跨服务（共享目录/集群） | **L4（跨模块追踪）** | 需审计全链路 |

## Classify

### 研判标准

#### 确认漏洞
满足以下条件可认定为沙箱隔离不当的上传漏洞：
1. 上传后文件需经过外部命令、脚本或插件处理，而处理过程缺乏沙箱或最小权限控制。
2. 攻击者可构造恶意文件利用已知解析漏洞或命令注入执行任意代码。
3. 上传目录或共享存储未设置适当权限，导致文件可直接访问/执行或横向利用。

#### 误报
以下情况属于误报：
1. 文件处理在隔离容器或受限进程中执行，并启用 seccomp/AppArmor 等策略。
2. 上传目录为不可执行、仅通过授权后端访问，且文件加密存储。
3. 工程已引入多层检测和审批机制，确保恶意文件无法进入处理环节。

#### 代码异味
需记录但不一定是漏洞的情况：
1. 沙箱配置存在绕过可能，例如未阻止特定系统调用。
2. 对外部命令参数依赖业务数据，未来改动可能引入注入风险。
3. 日志与告警不足，无法及时发现异常上传或处理失败。

## Low risk

### 低风险评级场景

#### 1. 受控内部工具
- **场景：** 上传功能仅在内部 CI/CD 或数据管道使用。
- **风险评估：** 攻击面有限，但需防内部滥用。

#### 2. 只读共享目录
- **场景：** 上传后文件存储在只读目录，Web 服务无法执行。
- **风险评估：** 降低 RCE 风险，但仍需关注信息泄露。

#### 3. 多级审批与扫描
- **场景：** 上传文件必须经过自动扫描与人工审核后才对外可见。
- **风险评估：** 风险较低，但仍需严格执行流程。

#### 4. 运行时监控
- **场景：** 实时监控沙箱进程行为并对异常发出告警。
- **风险评估：** 有助于及时发现问题，需结合其它防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部受控场景 | 攻击面小 | 中 |
| 沙箱 + 最小权限 | 有效阻断利用 | 低 |
| 只读隔离存储 | 降低执行风险 | 中 |
| 实时监控/告警 | 快速响应 | 高（持续优化）|
