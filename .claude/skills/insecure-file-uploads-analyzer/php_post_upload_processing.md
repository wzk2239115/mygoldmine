# PHP 上传后处理与执行权限漏洞

## Details

### 漏洞成因
PHP 应用在上传后常使用图像处理库（GD、Imagick）、文档解析库（PhpSpreadsheet、TCPDF）、命令行工具（ImageMagick、FFmpeg）或自定义脚本进行转换、缩略、OCR。如果处理流程缺乏类型验证、资源限制、命令参数净化或访问控制，攻击者可利用恶意文件触发命令注入、ImageTragick、Ghostscript、压缩炸弹等漏洞达成 RCE/DoS。此外，将上传文件设为可执行或组合 `include/require` 动态加载也会产生执行风险。

### 代码示例

**易受攻击的代码：**
```php
function convertImage($path) {
    // 攻击者可上传恶意 svg，利用 ImageMagick RCE
    exec("convert " . escapeshellarg($path) . " " . escapeshellarg($path . '.jpg'));
}
```

```php
function importSpreadsheet($file) {
    $spreadsheet = \PhpOffice\PhpSpreadsheet\IOFactory::load($file);
    // 未限制工作表数量、大小，可能导致内存溢出或公式注入
    return $spreadsheet->getActiveSheet()->toArray();
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 外部命令：`exec`, `shell_exec`, `proc_open`, `symfony/process`
- 图像处理：`Imagick`, `imagecreatefrom*`, `GD`, `intervention/image`
- 文档解析：`PhpSpreadsheet`, `TCPDF`, `FPDI`, `dompdf`
- 模板/包含：`include $path`, `require`, `move_uploaded_file` 后 `include`

**定位步骤：**
1. 搜索上传处理后调用的外部命令或解析库，确认是否受控。
2. 检查是否设置资源限制（如 `memory_limit`, `set_time_limit`）。
3. 跳读（L2）确认是否禁用危险格式（SVG、EPS、PDF 脚本）。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **命令净化与沙箱：** 使用 `escapeshellarg`、`Process` 类、独立容器运行。
- **资源限制：** 通过 `ini_set`, `set_time_limit`, `ulimit`, `cgroups` 限制 CPU/内存。
- **格式白名单：** 禁用高风险格式，解析前检测魔术字。
- **异步隔离：** 在队列/worker 中处理并以低权限运行。
- **审计日志：** 记录处理失败、超时、异常情况。

**定位技巧：**
- 检查是否处理压缩包或多层文件，确认防范压缩炸弹。
- 查看解析后的输出是否直接包含在模板内（可能触发 XSS/LFI）。
- 确认上传目录权限（`chmod 0644`）及 web server 配置是否禁止执行。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 外部处理在沙箱 + 资源限制 | **L0（快速跳过）** | 风险低 |
| 部分限制但仍使用高风险格式 | **L2（跳读）** | 需检查绕过 |
| 任意文件可触发命令/解析 | **L3（逐行读）** | 高风险 |
| 处理结果直接用于 include/模板执行 | **L4（跨模块追踪）** | 需深入分析 |

## Classify

### 研判标准

#### 确认漏洞
需满足以下条件：
1. 上传文件经过高风险处理（命令执行、解析库）而缺乏类型验证和资源限制。
2. 处理环境无隔离，使用与应用同权限。
3. 攻击者可通过上传恶意文件实现 RCE、DoS 或覆盖敏感文件。

#### 误报
以下情况可视为误报：
1. 处理链路在隔离容器中执行，并设置严格限制。
2. 白名单明确只允许安全格式，处理前后均扫描。
3. 上传仅用于内部可信管道，经人工审核。

#### 代码异味
需记录的风险：
1. 对异常缺乏日志与重试控制，易掩盖攻击。
2. 使用老旧库版本存在已知漏洞。
3. Worker 与主服务共用临时目录，可能覆盖文件。
4. 未对处理结果设置权限或净化，易被滥用。

## Low risk

### 低风险评级场景

#### 1. 内部任务
- **场景：** 上传仅由内部流程触发，并经签名验证。
- **风险评估：** 攻击面小，但需防内部滥用。

#### 2. 容器化/Serverless
- **场景：** 每次处理在容器或 serverless 中执行，自动回收资源。
- **风险评估：** 风险较低，仍需监控逃逸。

#### 3. 仅读取元数据
- **场景：** 解析仅获取元信息，不生成输出或执行命令。
- **风险评估：** 降低利用价值。

#### 4. 多层监控
- **场景：** 结合资源监控、告警、WAF/IDS。
- **风险评估：** 有助于快速响应，需配合防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部可信流程 | 攻击面有限 | 中 |
| 容器沙箱 + 限制 | 阻断利用 | 低 |
| 仅读元数据 | 降低危害 | 中 |
| 监控告警 | 提升响应能力 | 高（持续优化）|
