# 文件上传通用漏洞模式（所有项目必审）

任何提供文件上传功能的 Web 应用，无论语言和框架，都需要审计以下问题。这些是设计层面的通用缺陷。

## 1. 文件类型验证缺失或不足

### ⚠️ 仅依赖客户端验证
- **风险**：前端 JavaScript 验证或 Content-Type 头检查可被轻易篡改
- **检查点**：代码中仅在客户端检查文件类型，服务端无验证逻辑

### ⚠️ 仅检查扩展名
- **风险**：仅通过 `.php` 等扩展名判断，未验证文件魔数或实际内容
- **黑名单陷阱**：黑名单永远不完整（`.php3`、`.php7`、`.phtml` 等可绕过）
- **检查点**：查看是否使用了白名单而非黑名单；是否检查了 magic number

### ⚠️ 仅检查 MIME 类型
- **风险**：只信任 Content-Type 头或 `file()` 函数返回值，不验证真实内容
- **检查点**：是否读取文件头部字节（magic number）进行验证，如 `fread($file, 12)`

### ⚠️ 文件内容验证不完整
- **仅检查头部**：仅读取开头几字节，文件后部可嵌入恶意代码
- **图片嵌入**：上传 `shell.php` 数据到 JPG 头部，或在图片中嵌入 PHP 脚本
- **二次渲染不安全**：图片重新保存后恶意代码仍可能残留

## 2. 文件扩展名绕过技巧

### 🔓 大小写绕过
- **问题**：扩展名检查区分大小写（`.PHP` vs `.php`）或仅在 Windows 不区分
- **绕过**：上传 `.PhP`、`.pHp`、`.ASP`
- **检查点**：验证逻辑是否转换为统一大小写（如 `strtolower()`）

### 🔓 特殊字符绕过
- **空格/点号**：`.php ` 或 `.php.` （Windows 系统会忽略）
- **NULL 字节**：`.php%00.jpg` （PHP < 5.3 截断处理）
- **文件流**：`.php::$DATA` （Windows NTFS）
- **检查点**：是否清理了尾部空格、点号；是否处理了 NULL 字节

### 🔓 双扩展名
- **原理**：上传 `shell.php.jpg`，服务器按第一个扩展名解析
- **服务器配置**：`.htaccess` 或 web.config 配置错误，导致 `.php.jpg` 被当作 PHP 执行
- **检查点**：审查 Apache/Nginx 配置是否有多扩展名解析规则

## 3. 文件名处理不当

### ⚠️ 目录穿越
- **风险**：文件名包含 `../`、`..\\` 导致写入任意路径
- **Zip Slip**：解压缩文件时路径未验证，可写入系统目录
- **检查点**：是否验证了最终存储路径不超出上传目录；是否规范化了路径

### ⚠️ 文件名未清理
- **命令注入**：文件名包含 `;`、`|`、`&`、`$` 等，后续处理调用系统命令时注入
- **二次利用**：文件名在其他模块作为参数使用时触发漏洞
- **检查点**：后续业务逻辑是否将文件名用于命令执行或数据库查询

### ⚠️ 文件名可预测
- **连续命名**：文件 ID 为 1、2、3... 或时间戳，可枚举
- **路径泄露**：上传响应返回文件路径或 ID，或通过目录列举获得
- **检查点**：是否使用了随机 UUID；是否在响应中泄露路径信息

## 4. 文件存储位置不安全

### ⚠️ 存储在 Web 根目录
- **风险**：文件在 Web 可直接访问的位置，脚本可被执行
- **Web.config 配置**：上传目录配置允许脚本解析（未禁用 PHP/ASP）
- **检查点**：存储路径是否在 Web 根目录；上传目录的 `.htaccess` 或 web.config 是否禁用了脚本执行

### ⚠️ 文件存储未隔离
- **混合存储**：用户文件与系统配置、其他用户文件混在一起
- **跨租户访问**：SaaS 应用中不同用户的文件未隔离
- **临时文件不清理**：临时文件位置可被发现和访问
- **检查点**：是否按用户/租户分目录；临时文件是否有清理机制

### ⚠️ 云存储配置不当
- **公开桶**：S3/OSS 配置为公开可读
- **无临时签名**：文件访问链接长期有效，未使用 presigned URL
- **回调未验证**：云存储回调或通知未验证签名，可被伪造
- **检查点**：云存储权限设置；是否生成临时访问 URL；回调是否验证签名

## 5. 文件访问控制缺失

### ⚠️ 文件可直接访问
- **无权限检查**：文件可通过 URL 直接访问，无需验证用户权限
- **文件下载**：下载接口未检查用户是否拥有该文件
- **预览缩略图**：生成预览图时未进行权限校验
- **检查点**：访问文件的接口是否验证了当前用户的权限

### ⚠️ 访问令牌不安全
- **无令牌**：文件访问直接通过 URL，无临时访问令牌
- **令牌可预测**：令牌为固定值或可枚举（如 `token=123`）
- **令牌不过期**：令牌无有效期或有效期过长（数年）
- **检查点**：是否使用了临时 token；token 有效期是否合理（分钟级）

## 6. 文件大小和数量限制缺失

### ⚠️ 无大小限制
- **DoS 攻击**：上传超大文件耗尽服务器存储和内存
- **限制过大**：如限制为 1GB，仍可被滥用
- **检查点**：是否有合理的文件大小限制；是否在上传开始前检查大小

### ⚠️ 无频率限制
- **批量上传**：未限制单用户上传频率和总量，可快速消耗存储
- **检查点**：是否有 rate limit；是否有存储配额限制

## 7. 文件处理过程不安全

### ⚠️ 解压缩漏洞
- **Zip Slip**：解压时未验证文件路径，可写入任意目录
- **压缩炸弹**：解压后文件大小极大（压缩包 1MB，解压后 1GB），导致 DoS
- **嵌套深度**：解压过程未限制嵌套层级和文件数量
- **检查点**：是否验证了解压路径；是否限制了解压后大小和文件数

### ⚠️ 图片/文档处理
- **库漏洞**：ImageMagick、GD、PDF 库等存在已知 RCE 漏洞
- **XXE 注入**：解析 XML/Office 文档时未禁用外部实体
- **检查点**：依赖库版本是否有公开漏洞；是否禁用了 XXE 解析

### ⚠️ 文件转换不安全
- **命令注入**：调用 `convert`、`ffmpeg` 等外部命令，文件名参数未转义
- **二次处理**：图片压缩、水印等过程处理恶意输入导致崩溃或 RCE
- **异步任务**：后台任务处理时未重新验证权限和文件类型
- **检查点**：调用系统命令时是否使用了正确的转义；异步处理是否重新验证

## 8. 文件内容安全扫描缺失

### ⚠️ 无病毒扫描
- **直接存储**：上传文件未经过病毒扫描直接存储和分发
- **异步扫描**：病毒扫描在后台进行，用户可在扫描完成前访问文件
- **检查点**：是否集成了杀毒引擎（如 ClamAV）；是否同步扫描

### ⚠️ 无恶意内容检测
- **嵌入脚本**：上传的 Office/PDF 文档可能包含嵌入宏或 JavaScript
- **敏感信息**：上传文件可能包含泄露的密钥、密码、API token
- **检查点**：是否检测了文档内的脚本；是否扫描了敏感信息泄露
