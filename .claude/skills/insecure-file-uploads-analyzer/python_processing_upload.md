# Python 上传后处理链路漏洞

## Details

### 漏洞成因
Python 服务常在上传后对文件进行转换、压缩、OCR、病毒扫描或异步处理，涉及库包括 Pillow、moviepy、PyPDF2、python-docx、ffmpeg-python 等。如果处理链路未限制文件大小、像素、页数、解析时间，或在主进程/高权限用户下运行，攻击者可通过恶意文件触发解析库漏洞、命令注入、资源耗尽，从而导致拒绝服务或远程代码执行。Celery/RQ 等异步任务若未重复校验输入，也会扩散风险。

### 代码示例

**易受攻击的代码：**
```python
from PIL import Image

def make_thumbnail(file_path):
    img = Image.open(file_path)  # 未限制像素、格式，可能触发漏洞
    img.thumbnail((512, 512))
    img.save(file_path + "_thumb.jpg")
```

```python
import fitz  # PyMuPDF

def extract_text(file_path):
    doc = fitz.open(file_path)  # 未限制页数或处理时间
    return "\n".join(page.get_text() for page in doc)
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 图像处理：`PIL.Image`, `cv2`, `wand.image`
- 文档解析：`PyPDF2`, `fitz`, `docx`, `pptx`, `pdfminer`
- 音视频：`ffmpeg`, `subprocess.run(["ffmpeg", ...])`, `moviepy`
- 异步任务：`Celery`, `RQ`, `asyncio`, `BackgroundTasks`

**定位步骤：**
1. 搜索所有处理上传文件的函数，检查是否有限制或沙箱设置。
2. 查看是否通过 `subprocess` 调用外部工具，是否转义参数。
3. 跳读（L2）确认是否在异步任务中重复验证文件类型与大小。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **资源限制：** 控制图像最大像素、PDF 最大页数、视频时长，使用 `Pillow.Image.MAX_IMAGE_PIXELS` 等配置。
- **执行隔离：** 在容器或低权限用户下运行处理任务。
- **超时控制：** `subprocess.run(..., timeout=...)` 或 `asyncio.wait_for`。
- **输入校验：** 在任务入队前后复用白名单/杀毒扫描。
- **异常处理：** 捕获解析异常并记录日志，避免静默失败。

**定位技巧：**
- 检查是否存在压缩炸弹防护，如检测 `zipfile` 中解压后的大小。
- 确认处理完成后是否清理临时文件。
- 追踪处理结果的存储与访问权限。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 限制资源 + 隔离执行 + 日志监控 | **L0（快速跳过）** | 风险低 |
| 有部分限制但缺乏隔离 | **L2（跳读）** | 需补齐防护 |
| 任意文件可直接进入处理流程 | **L3（逐行读）** | 高风险 |
| 处理结果与其他系统交互 | **L4（跨模块追踪）** | 需跟踪上下游 |

## Classify

### 研判标准

#### 确认漏洞
涉及以下情况可界定为漏洞：
1. 上传后处理链路对文件类型、大小、像素、时长缺乏限制。
2. 处理任务在主服务或高权限环境运行，未隔离。
3. 攻击者可利用恶意文件触发解析或外部命令漏洞，造成 RCE/DoS。

#### 误报
以下情形可视为误报：
1. 上传文件处理在独立容器执行，并设置严格的资源限制与超时。
2. 输入在异步任务前后都经过验证与扫描。
3. 输出结果不直接暴露给用户，且含敏感数据前会再次审核。

#### 代码异味
需注意但未必立即构成漏洞：
1. 依赖默认配置，未显式设置 `PIL.Image.MAX_IMAGE_PIXELS` 等限制。
2. 异步任务队列无失败重试策略，易导致文件堆积。
3. 缺少异常日志，难以定位攻击尝试。
4. 未对处理结果进行权限控制或版本管理。

## Low risk

### 低风险评级场景

#### 1. 内部批量任务
- **场景：** 上传处理仅供内部使用并由可信渠道提供。
- **风险评估：** 攻击面有限，但需防内部滥用。

#### 2. 容器化执行
- **场景：** 每个处理任务在短生命周期容器中运行。
- **风险评估：** 风险较低，但需监控逃逸。

#### 3. 输出只读 + 加签
- **场景：** 处理结果为只读文件，并附带签名/校验。
- **风险评估：** 可降低利用价值。

#### 4. 监控与告警
- **场景：** 结合资源监控、日志分析检测异常负载。
- **风险评估：** 有助于及早发现问题，仍需防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部可信流程 | 攻击面小 | 中 |
| 容器沙箱 + 资源限制 | 有效阻断漏洞利用 | 低 |
| 输出只读并加签 | 降低影响 | 中 |
| 监控告警 | 提高响应速度 | 高（持续改进）|
