# JavaScript (Node.js) 上传内容检测与安全审计漏洞

## Details

### 漏洞成因
即使上传流程进行了类型和路径校验，若缺乏内容安全检测（病毒扫描、脚本特征、敏感信息过滤）以及审计日志，攻击者仍可上传恶意文件在后续流程中执行，或传播木马、勒索软件、违规内容。常见的缺陷包括未集成杀毒/沙箱服务、未删除含敏感信息的文件、缺乏上传/下载日志、未对内容进行安全策略扫描等。

### 代码示例

**易受攻击的代码：**
```javascript
app.post("/resume", upload.single("resume"), async (req, res) => {
  // 仅验证扩展名
  if (!req.file.originalname.endsWith(".pdf")) {
    return res.status(400).send("invalid file");
  }
  // 未扫描病毒/恶意内容，直接上传至对象存储
  await s3.upload({ Bucket: bucket, Key: req.file.originalname, Body: req.file.buffer }).promise();
  res.send("ok");
});
```

**另一个不安全示例（缺少审计）：**
```javascript
router.post("/upload", upload.array("files"), async (ctx) => {
  for (const file of ctx.req.files) {
    await storage.save(file); // 未记录上传日志、未扫描敏感信息
  }
  ctx.body = { success: true };
});
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 病毒扫描：`clamd`, `clamav`, `scan`, `virusTotal`
- 内容检测：`DLP`, `regex`, `sensitive`, `classification`
- 日志与监控：`logger.info("upload")`, `audit`, `metrics`
- 回调/队列：`publish("scan")`, `queue.add("scan", ...)`

**定位步骤：**
1. 检查上传流程是否调用扫描服务或触发安全任务。
2. 查看是否记录上传文件的用户、IP、文件名、结果。
3. 跳读（L2）验证是否对敏感信息（身份证、银行卡）进行检测。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **病毒扫描：** 集成 ClamAV、云安全服务或自建沙箱。
- **敏感信息过滤：** 使用 DLP、正则检查个人信息并拒绝或加密。
- **日志审计：** 上传/下载操作写入审计系统，支持追溯。
- **告警与隔离：** 扫描失败或可疑文件进入隔离区并通知安全团队。
- **安全策略更新：** 定期更新病毒库/规则，自动化部署。

**定位技巧：**
- 审查是否处理扫描失败（例如超时、服务不可用）并采取安全默认。
- 检查是否支持人工复核和黑名单。
- 评估对外共享链接是否有限制下载次数、有效期。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 全量病毒扫描 + DLP + 审计告警 | **L0（快速跳过）** | 风险低 |
| 仅部分扫描或缺乏审计 | **L2（跳读）** | 需补齐监控 |
| 无扫描且无日志 | **L3（逐行读）** | 高风险 |
| 上传文件进一步影响其他系统 | **L4（跨模块追踪）** | 需跟踪全链路 |

## Classify

### 研判标准

#### 确认漏洞
需满足以下条件：
1. 上传内容直接进入分发或处理环节，无病毒/恶意检测。
2. 缺乏敏感信息筛查，可能泄露个人数据或合规违规。
3. 无审计日志和告警，无法及时发现恶意上传或滥用。

#### 误报
以下情况可视为误报：
1. 上传内容基于可信管道，并已在上游完成安全检测。
2. 系统集成多层扫描、隔离与人工审核流程。
3. 上传结果仅内部使用，且存在完善的监控与溯源机制。

#### 代码异味
需记录的风险：
1. 扫描服务未处理失败或超时，默认视为安全。
2. 仅对部分类型文件扫描，存在绕过空间。
3. 缺乏日志导致调查阻力。
4. 未定期更新病毒库或规则。

## Low risk

### 低风险评级场景

#### 1. 内部受控流程
- **场景：** 上传来源可信且已有外部审核。
- **风险评估：** 攻击面小，但需防内部滥用。

#### 2. 扫描隔离 + 人工审核
- **场景：** 可疑文件自动隔离，并交由人工复核。
- **风险评估：** 风险低，需确保流程执行。

#### 3. 限制对外分享
- **场景:** 文件仅内部访问，不提供公开链接。
- **风险评估：** 降低传播风险。

#### 4. 监控告警
- **场景：** 上传/下载日志实时分析并告警异常行为。
- **风险评估：** 有助于早期发现问题，需配合防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 可信来源 | 攻击面有限 | 中 |
| 扫描 + 隔离 + 人审 | 技术与流程防护 | 低 |
| 内部访问 | 降低传播 | 中 |
| 监控告警 | 提升发现能力 | 高（持续优化）|
