# Java 媒体/文档处理型上传漏洞

## Details

### 漏洞成因
许多 Java 应用在上传后会对图像、音视频、Office 文档、PDF 等进行转换、预览或 OCR，常用库包括 ImageIO、Apache Tika、POI、PDFBox、FFmpeg、Ghost4J 等。如果处理链路缺少文件头校验、大小/像素限制、超时控制或运行在与主服务同一权限下，攻击者可利用恶意文件触发解析器漏洞、Zip 炸弹、XXE、RCE 等攻击，从而突破隔离或导致拒绝服务。

### 代码示例

**易受攻击的代码：**
```java
public BufferedImage readImage(InputStream inputStream) throws IOException {
    // 未设置 ImageReader 限制，不校验文件头，可能触发内存溢出
    return ImageIO.read(inputStream);
}
```

```java
public String extractText(MultipartFile file) throws IOException {
    // 利用 Apache Tika 对所有上传文件提取文本
    Tika tika = new Tika();
    return tika.parseToString(file.getInputStream()); // 未限制文件类型、大小或解析时间
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 图像处理：`ImageIO`, `BufferedImage`, `Thumbnailator`, `imgscalr`
- 文档解析：`Apache POI`, `PDFBox`, `Tika`, `iText`, `Aspose`
- 音视频：`FFmpeg`, `Xuggler`, `JCodec`, `ProcessBuilder("ffmpeg")`
- 转换逻辑：`convert`, `generatePreview`, `extractText`

**定位步骤：**
1. 查找上传后涉及的解析/转换函数，确认是否受控。
2. 检查是否对输入类型、大小、像素、页数进行限制。
3. 跳读（L2）确认解析是否在隔离环境中执行、是否存在超时机制。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **文件头/类型验证：** 使用 `Tika.detect` 或读取魔术字判定真实类型。
- **资源限制：** 设置最大像素、页数、内存、时间，通过 `ImageReader` `setInput` 配置或使用 `ProcessBuilder` 限制。
- **隔离执行：** 在独立服务或容器中进行转换，主服务仅接收结果。
- **防护补丁：** 使用已修复漏洞的库版本，避免已知 RCE/DoS 漏洞。
- **扫描与日志：** 对解析失败、不符合预期的文件记录告警。

**定位技巧：**
- 检查 PDF/PPT 等解析是否禁用外部实体、字体下载等潜在攻击面。
- 确认 `ProcessBuilder` 调用是否转义参数，避免命令注入。
- 追踪转换后文件在存储和访问层的权限。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 解析链路在隔离服务 + 严格资源控制 | **L0（快速跳过）** | 风险低 |
| 核心限制部分存在但未覆盖所有格式 | **L2（跳读）** | 需检查遗漏 |
| 任意文件直接交由解析库处理 | **L3（逐行读）** | 高风险 |
| 可通过上传触发外部命令/脚本 | **L4（跨模块追踪）** | 需深入分析 |

## Classify

### 研判标准

#### 确认漏洞
要判定为漏洞需满足：
1. 首先上传后会调用解析/转换库处理未经筛选的文件。
2. 处理过程缺乏类型校验、资源限制或隔离，可能触发已知解析漏洞。
3. 解析结果可被攻击者利用执行代码、读取敏感信息或造成 DoS。

#### 误报
以下情况可视为误报：
1. 所有处理均在受控白名单类型、经过多层检测后才执行。
2. 解析在隔离容器中进行，并设置严格的资源/超时限制。
3. 上传仅供内部可信系统或人工审核后执行。

#### 代码异味
需记录的风险点：
1. 缺少失败处理与日志，难以识别恶意尝试。
2. 单线程解析导致 DoS 风险，未设置队列或并发控制。
3. 解析库版本落后，存在 CVE 未修复。
4. 同时支持大量格式，缺乏统一的安全策略。

## Low risk

### 低风险评级场景

#### 1. 受控批处理
- **场景：** 文件由内部系统上传并经签名校验。
- **风险评估：** 攻击面小，但需防内部滥用。

#### 2. 只读解析结果
- **场景：** 解析仅生成文本/缩略图，结果不返回原文件。
- **风险评估：** 危害降低，但需防资源消耗。

#### 3. 容器沙箱处理
- **场景：** 每次解析在独立容器或 serverless 任务中执行，使用最小权限。
- **风险评估：** 风险较低，仍需监控逃逸。

#### 4. 多重监控
- **场景：** 结合异常检测、速率限制与告警系统。
- **风险评估：** 有助于快速响应，但不替代防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 可信来源/签名 | 攻击面有限 | 中 |
| 隔离容器 + 资源限制 | 有效阻断漏洞利用 | 低 |
| 只读/不可执行输出 | 降低进一步利用 | 中 |
| 监控与告警 | 提升发现能力 | 高（持续完善）|
