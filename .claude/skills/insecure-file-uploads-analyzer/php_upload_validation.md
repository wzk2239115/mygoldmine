# PHP 文件上传验证漏洞

## Details

### 漏洞成因
PHP 应用通过 `$_FILES`, `move_uploaded_file`, Laravel `Storage::putFile`, Symfony `UploadedFile` 等接口处理上传。若使用客户端提供的扩展名或 `$_FILES["type"]` 判断类型，未读取文件头、执行白名单、限制大小/数量、随机文件名和目录隔离，攻击者可上传 WebShell、恶意脚本或压缩炸弹实现代码执行、覆盖文件或拒绝服务。特别是在 Apache/Nginx 解析规则不严或禁用 `cgi.fix_pathinfo` 的环境中风险更高。

### 代码示例

**易受攻击的代码：**
```php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $file = $_FILES['upload'];
    $ext = pathinfo($file['name'], PATHINFO_EXTENSION);
    if (!in_array($ext, ['jpg', 'png'])) {
        die('invalid file');
    }
    move_uploaded_file($file['tmp_name'], __DIR__ . '/uploads/' . $file['name']); // 未随机命名
}
```

**另一个不安全示例（依赖 MIME）：**
```php
if ($_FILES['file']['type'] === 'application/pdf') {
    move_uploaded_file($_FILES['file']['tmp_name'], '/var/www/html/docs/' . $_FILES['file']['name']);
    // MIME 可被伪造，且存储在 Web 根目录
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 上传 API：`$_FILES`, `move_uploaded_file`, `Storage::put`, `UploadedFile::move`
- 类型判断：`pathinfo`, `mime_content_type`, `finfo_file`
- 黑名单检查：`strrchr`, `strpos`, `preg_match('/php/')`
- 路径处理：`$uploadDir`, `basename`, `realpath`

**定位步骤：**
1. 搜索上传处理逻辑，确认是否存在扩展名白名单和内容校验。
2. 检查存储目录是否位于 Web 根目录且可执行。
3. 跳读（L2）确认是否限制文件大小、数量、随机命名、权限设置。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **白名单 + 内容检测：** 使用 `finfo_file`, `exif_imagetype`, `getimagesize`.
- **大小限制：** PHP `upload_max_filesize`, `post_max_size`, `MAX_FILE_SIZE`。
- **随机命名与目录隔离：** 使用 UUID、子目录分隔、不可执行目录。
- **权限控制：** 设置 `chmod`, 禁用脚本解析、通过后端签名下载。
- **内容扫描：** 集成杀毒、内容过滤、魔术字检测。

**定位技巧：**
- 检查 `.htaccess` 或 Nginx 配置是否禁止执行上传目录文件。
- 确认上传后是否清理临时文件和无效记录。
- 检查是否防止双扩展、null byte 等绕过。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 白名单 + finfo 校验 + 隔离存储 | **L0（快速跳过）** | 风险低 |
| 部分校验但依赖前端 | **L2（跳读）** | 需验证防护完整性 |
| 直接 `move_uploaded_file` 至可执行目录 | **L3（逐行读）** | 高风险 |
| 上传结果立即被包含/执行 | **L4（跨模块追踪）** | 需深入分析 |

## Classify

### 研判标准

#### 确认漏洞
需满足：
1. 上传入口缺乏可靠的类型、大小、随机命名、防双扩展控制。
2. 文件存储在可执行目录或访问无鉴权，攻击者可执行/覆盖文件。
3. 可利用上传获取代码执行、敏感信息访问或 DoS。

#### 误报
以下情景可判定为误报：
1. 上传仅供可信渠道使用，并通过签名/加密保证不可伪造。
2. 文件存储在不可执行目录，访问需鉴权且返回前处理内容。
3. 已对文件进行多层检测、扫描且确认不可执行。

#### 代码异味
需记录的风险：
1. 仅使用黑名单过滤扩展名，易被绕过。
2. 未设置权限（如 `chmod 0644`），导致可执行。
3. 没有日志，无法追踪恶意上传。
4. 临时文件/失败上传未清理。

## Low risk

### 低风险评级场景

#### 1. 后台上传
- **场景：** 仅后台管理员上传，并有操作审计。
- **风险评估：** 攻击面较小，但需防账号泄露。

#### 2. 上传即转存私有对象存储
- **场景：** 上传后立刻存储到私有对象存储，并使用签名 URL。
- **风险评估：** 可降低执行风险，但仍需校验。

#### 3. 静态只读发布
- **场景：** 上传内容经审核后部署到只读静态 CDN。
- **风险评估：** 风险较低，需防恶意内容传播。

#### 4. 安全监控
- **场景：** WAF/IDS 对上传接口实时监控，记录异常。
- **风险评估：** 有助于快速响应，需配合防护措施。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 管理员专用 | 攻击面有限 | 中 |
| 隔离存储 + 签名访问 | 技术防护完善 | 低 |
| 审核后发布 | 降低利用价值 | 中 |
| 安全监控 | 提升感知能力 | 高（持续优化）|
