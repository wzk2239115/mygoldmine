# Go 异步上传处理链路漏洞

## Details

### 漏洞成因
Go 微服务常通过异步任务（Kafka、RabbitMQ、NATS）、goroutine、worker 池或 serverless 函数对上传文件进行进一步处理（压缩、转码、OCR、病毒扫描）。如果在入队后未重复验证文件类型、大小、权限，或任务执行在与主服务同等权限下且缺乏资源限制和超时控制，攻击者可利用恶意文件触发解析漏洞、命令注入或制造压缩炸弹，导致拒绝服务或远程代码执行。任务失败重试、缺乏幂等控制也会放大影响。

### 代码示例

**易受攻击的代码：**
```go
func handleUpload(c *gin.Context) {
    file, _ := c.FormFile("file")
    path := filepath.Join("/tmp/uploads", file.Filename)
    c.SaveUploadedFile(file, path)
    // 直接将路径发往 Kafka，后续 worker 未进行额外校验
    produce("upload-topic", []byte(path))
}

func worker(msg []byte) {
    path := string(msg)
    // 未限制大小/类型，直接调用外部命令
    exec.Command("convert", path, path+".png").Run()
}
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：**
- 消息队列：`kafka`, `sarama`, `nsq`, `nats`, `rabbitmq`, `Publish`
- 异步执行：`go func()`, `worker`, `pool`, `task queue`
- 外部命令：`exec.Command`, `cmd.Run`, `cmd.CombinedOutput`
- 资源限制：`context.WithTimeout`, `Setrlimit`, `ulimit`

**定位步骤：**
1. 查找上传路径与异步任务之间的连接，确认是否存在再次验证。
2. 检查任务执行环境是否使用低权限账户或容器。
3. 跳读（L2）确认是否限制命令执行时间、内存、频率。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- **输入再验证：** worker 从队列取出后重新校验文件类型、大小、签名。
- **资源限制：** 使用 `context.WithTimeout`, `Cmd.SysProcAttr`, `cgroups` 限制 CPU/内存。
- **幂等控制：** 防止失败重试导致无限执行或覆盖文件。
- **隔离执行：** 在独立容器/沙箱执行转换任务，主服务仅接收结果。
- **监控与告警：** 对执行失败、超时、资源异常进行告警。

**定位技巧：**
- 追踪任务失败后是否进行清理或重试策略。
- 检查是否存在批量任务处理导致资源耗尽。
- 确认消息内容是否需要签名或权限校验。

#### 审计等级标注

| 场景 | 审计等级 | 说明 |
|------|----------|------|
| worker 再次验证 + 隔离执行 + 限制资源 | **L0（快速跳过）** | 风险低 |
| 部分限制但仍与主服务共享权限 | **L2（跳读）** | 需检查绕过 |
| 任意上传路径直接进入 worker | **L3（逐行读）** | 高风险 |
| 多服务串联处理且无统一策略 | **L4（跨模块追踪）** | 需跟踪全链路 |

## Classify

### 研判标准

#### 确认漏洞
需同时满足：
1. 上传文件进入异步处理流程时未重新验证类型、大小、权限。
2. 处理任务在缺乏隔离的环境执行，可能利用解析漏洞或命令注入。
3. 攻击者可借此造成 RCE、DoS 或覆盖敏感数据。

#### 误报
以下情况可视为误报：
1. 异步任务在隔离容器执行，并重复验证文件安全。
2. 上传队列仅接收可信来源，消息带有签名和权限控制。
3. 处理结果非持久化或仅在内部可见，对外无影响。

#### 代码异味
需记录的风险：
1. 冗余重试机制可能无限执行恶意文件。
2. 缺少审计与监控，无法及时发现异常任务。
3. worker 共享同一临时目录，可能覆盖彼此文件。
4. 未删除中间文件，易占满磁盘。

## Low risk

### 低风险评级场景

#### 1. 内部受控管道
- **场景：** 上传由内部系统发起，任务来源可信。
- **风险评估：** 攻击面小，但需防内部滥用或凭证泄露。

#### 2. 容器化沙箱
- **场景：** 每个任务在独立容器中运行，并设置资源限制。
- **风险评估：** 风险较低，仍需监控逃逸。

#### 3. 幂等与限流
- **场景：** 任务具备幂等性，失败有速率限制。
- **风险评估：** 可减少滥用风险。

#### 4. 审计报警
- **场景：** 结合日志、监控系统实时告警异常任务。
- **风险评估：** 有助于快速响应，需配合防护。

### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 内部可信来源 | 攻击面有限 | 中 |
| 容器沙箱 + 资源限制 | 阻断利用 | 低 |
| 幂等 + 限流 | 降低滥用 | 中 |
| 审计监控 | 提升响应速度 | 高（持续优化）|
