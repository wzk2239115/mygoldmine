# 审计节点工作流

## 已有入口

- 保存的流程：`.claude/workflows/goldmine-pipeline.js`。
- 确定性适配：`ui/server/claude-workflows.mjs`。
- 页面04—07重跑默认由原生工作流协调后续节点；08独立重跑只执行08。03独立重跑仍只执行03。
- 页面导入和重新审计启动一轮原生01—08；连续循环由已有控制器启动每一轮的原生01—08流程，最多三轮，连续两轮没有发布改善时停止。08单独完成不启动01。

## 必须遵守

1. 只调用保存的流程，原样使用宿主机提供的节点计划和命令，不自行修改步骤或生成另一份脚本。
2. 每个节点只运行指定命令，返回其最后一行的结构化结果。详细执行日志写入磁盘，不在协调上下文中拼接原始日志。
3. 下一步必须通过已登记顺序、上游产物摘要和总报告摘要检查；界面展示条数不能用作候选筛选依据。
4. 不把无候选、没有可用场景、没有来源完整证据当成成功执行。相应节点明确跳过并保留原因，08继续读取真实反馈。
5. 不凭文字恢复中断任务。重复调用以磁盘回执去重；产物已改变、缺失或节点仍未完成时停止。保留项目锁，不另起同项目审计。
6. 08继续使用现有第三方技能优化模块及评估、发布和回退。候选数量不等于能力提高，缺少可信评估套件不能发布。
7. 大规模重复执行、候选并发、环境修复、重试次数和隔离边界由现有执行器负责，不在提示中绕过这些限制。

## 证据位置

每次调度保存在 `<运行目录>.meta/workflows/<编号>/`，包含 `state.json`、`raw.jsonl` 和节点日志；节点详细产物仍保存于原有独立重跑目录。节点输入附带 `workflow-inputs.json`，记录总报告摘要及全部已有上游产物引用。清单不采用界面的100条展示上限。

## 长任务的责任边界

节点命令现在只登记或查询独立任务，返回 `running` 后当前原生工作流可以结束。宿主机持有项目锁，按真实任务状态等待至终态，再协调剩余节点；不用模型会话的存活代替任务状态，也不在十分钟后重新启动01。每个节点登记进程身份、心跳、截止时间、输出与退出码；相同计划重复调用只返回原任务。任务失败保留具体原因，不能伪装为缺少回执的泛化错误。
