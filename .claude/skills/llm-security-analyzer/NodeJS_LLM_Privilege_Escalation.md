# **NodeJS LLM Privilege Escalation**

当 Node.js 应用允许 LLM 通过提示注入或函数调用来修改用户权限、角色或访问级别，攻击者可以将自己的权限提升到管理员或其他高权限用户的级别。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索权限修改操作：`user.role = `、`permissions.add()`、`updateUserRole()`、`grantPermission()`
- 查找 LLM 工具中的权限操作：`setUserRole`、`updatePermissions`、`elevatePrivileges`
- 搜索权限检查缺失：执行权限改变操作前是否有检查
- 查找条件判断：基于 LLM 输出的权限决策
- 定位数据库操作：`UPDATE users SET role = `

**核心操作保护机制（L2: 跳读）**
- 检查权限修改操作是否需要额外的认证（如 admin 密码）
- 验证是否有权限检查防止权限提升
- 查看是否有审计日志记录权限变化
- 检查是否有限制可被修改的权限值
- 查看是否有人工审核步骤

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪权限修改操作的所有入口点
- 检查是否所有权限修改都进行了身份验证
- 审查参数验证（如允许的角色值）
- 查看条件分支是否有绕过
- 检查错误处理是否隐藏了问题

**数据流追踪（L4: 跨模块追踪）**
- 追踪权限修改从请求到数据库的完整路径
- 检查是否有多个权限修改点
- 验证日志和审计记录

## Classify

**确认为漏洞的特征：**
1. LLM 可以调用权限修改函数，无额外认证
2. 权限值直接来自 LLM 输出，无验证
3. 可以通过提示注入使模型执行权限提升操作
4. 没有人类审核步骤
5. 权限提升操作无日志记录

**误报场景：**
1. 权限修改操作不可被 LLM 访问
2. 权限值有严格的白名单验证
3. 权限修改需要管理员额外确认
4. 有完整的审计日志记录所有权限变化
5. 当前用户只能修改下级权限，不能提升自身

**代码异味（需要深入审查）**
1. 直接从用户输入设置权限
2. 权限检查在权限修改后进行
3. 条件性地允许权限修改
4. 缺少审计日志

## Low risk

**评级为低风险的场景：**
1. 权限修改操作需要 superadmin 密码或密钥
2. 权限值有白名单，不能任意修改
3. 权限提升有人工审核步骤
4. 有完整的审计日志
5. 用户只能修改自己的非关键权限，无法修改他人权限
