# **PHP LLM Input Validation Bypass**

当 PHP 应用对 LLM 的输入验证不足或有逻辑缺陷，攻击者可以通过绕过验证注入恶意内容。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索验证函数：`strlen()`、`filter_var()`、`preg_match()`、缺失的验证
- 查找输入来源：`$_GET`、`$_POST`、`$_REQUEST`
- 搜索绕过技巧：空值、特殊字符、编码
- 查找白名单检查：缺失的 `in_array()`
- 定位验证逻辑：条件判断、异常处理

**核心操作保护机制（L2: 跳读）**
- 检查是否有完整的输入验证
- 验证是否使用了白名单而非黑名单
- 查看验证函数是否正确
- 检查是否有编码问题
- 查看是否有多层验证

**快速定位到具体漏洞（L3: 逐行读）**
- 审查验证逻辑的完整性
- 检查边界条件
- 查看特殊字符处理
- 审查类型检查
- 检查错误处理

**数据流追踪（L4: 跨模块追踪）**
- 追踪验证的完整流程
- 检查所有输入点

## Classify

**确认为漏洞的特征：**
1. 验证逻辑有漏洞或缺失
2. 使用黑名单而非白名单
3. 类型检查不完整
4. 边界条件未处理
5. 可以通过编码绕过

**误报场景：**
1. 完整的白名单验证
2. 类型检查正确
3. 边界条件处理完整
4. 多层验证
5. 安全的验证函数

**代码异味（需要深入审查）**
1. 条件性验证
2. 多个验证点
3. 复杂的验证逻辑
4. 黑名单验证

## Low risk

**评级为低风险的场景：**
1. 使用白名单验证
2. 类型检查正确
3. 边界条件处理完整
4. 多层验证无漏洞
5. 使用成熟的验证库（如 Respect/Validation）
