# **PHP LLM Function Call No Identity Check**

当 PHP 应用的 LLM 函数调用缺少身份验证检查，攻击者可以通过提示注入使模型执行操作而无需确认用户身份。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索工具定义：`$tools = []`、`$functions = `
- 查找函数执行：`call_user_func()`、`$function($args)`、`method_exists()`
- 搜索身份检查：缺失的 `isLoggedIn()`、`getCurrentUser()`
- 查找用户信息：`$_SESSION`、`auth()` 使用
- 定位工具执行点：函数调用前的检查

**核心操作保护机制（L2: 跳读）**
- 检查是否在执行函数前验证用户身份
- 验证是否检查了用户权限
- 查看是否有白名单限制
- 检查是否验证了函数参数
- 查看是否有日志审计

**快速定位到具体漏洞（L3: 逐行读）**
- 在函数执行前检查身份验证逻辑
- 追踪用户信息的获取
- 审查权限检查
- 查看参数验证
- 检查异常处理

**数据流追踪（L4: 跨模块追踪）**
- 追踪身份验证的完整流程
- 检查所有执行点

## Classify

**确认为漏洞的特征：**
1. 无身份验证检查
2. 直接执行 LLM 选择的函数
3. 无白名单
4. 参数未验证
5. 无审计日志

**误报场景：**
1. 执行前身份验证
2. 权限检查
3. 白名单机制
4. 参数验证
5. 审计日志

**代码异味（需要深入审查）**
1. 缺少身份检查
2. 多个执行点
3. 条件性检查
4. 复杂逻辑

## Low risk

**评级为低风险的场景：**
1. 所有函数执行前都验证身份
2. 有权限检查
3. 白名单机制
4. 参数验证
5. 完整审计日志
