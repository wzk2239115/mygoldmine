# **Rust LLM Function Call Ownership Issue**

当 Rust 应用的 LLM function calling 实现中，函数或数据的所有权转移处理不当，可能导致悬垂指针、use-after-free 或数据泄露。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索所有权转移：`move`、`clone()`、`to_owned()`
- 查找借用规则：`&`、`&mut`、缺失的借用标注
- 搜索函数指针或闭包：`fn()`、`||`、capture lists
- 查找不安全代码：`unsafe`、`*const`、`*mut`
- 定位工具函数：function table、tool registry

**核心操作保护机制（L2: 跳读）**
- 检查是否正确处理了所有权
- 验证是否有悬垂指针风险
- 查看是否过度使用 clone
- 检查是否有生命周期循环
- 查看是否使用了不安全代码

**快速定位到具体漏洞（L3: 逐行读）**
- 审查所有权转移的方式
- 检查借用的合法性
- 查看闭包的捕获
- 审查不安全代码块
- 检查编译器错误和警告

**数据流追踪（L4: 跨模块追踪）**
- 追踪数据所有权的转移
- 检查生命周期的正确性

## Classify

**确认为漏洞的特征：**
1. 不安全的所有权转移（transmute、cast）
2. 悬垂指针风险
3. use-after-free 可能
4. 过度的 clone 导致数据泄露
5. 不安全代码块处理不当

**误报场景：**
1. 所有权处理正确
2. 无 unsafe 代码或最小化
3. 正确的生命周期标注
4. 编译通过无警告
5. 类型系统保证安全

**代码异味（需要深入审查）**
1. unsafe 块
2. transmute/cast 使用
3. 过度克隆
4. 复杂的所有权链

## Low risk

**评级为低风险的场景：**
1. 无 unsafe 代码或最小化且安全
2. 所有权处理符合 Rust 规则
3. 生命周期标注清晰正确
4. 编译无错误和警告
5. 代码审查通过
