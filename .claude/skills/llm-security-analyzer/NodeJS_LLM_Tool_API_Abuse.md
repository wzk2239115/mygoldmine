# **NodeJS LLM Tool API Abuse**

当 LLM 的函数调用工具可以访问应用的 API 或外部服务，而未对调用进行适当限制时，攻击者可以通过提示注入使模型滥用这些 API，执行未授权的操作、获取敏感数据或进行扫描。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索 API 调用工具：`fetch()`、`axios.get()`、`http.request()`、`api_call tool`
- 查找未验证的参数：`endpoint`、`url`、`method`、`headers`、`body` 来自 LLM
- 搜索速率限制：缺失的速率限制、请求频率控制
- 查找资源消耗：`large payloads`、`loops`、`recursive calls`
- 定位 API 密钥：`api_key`、`authorization`、`credentials`

**核心操作保护机制（L2: 跳读）**
- 检查 API 工具是否有请求白名单
- 验证是否限制了可使用的 HTTP 方法
- 查看是否有请求大小和频率限制
- 检查是否验证了请求参数
- 查看是否记录了 API 调用审计

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪 API 请求参数的来源
- 检查是否有 endpoint 白名单
- 审查参数验证逻辑
- 查看是否有超时和大小限制
- 检查错误响应是否泄露敏感信息

**数据流追踪（L4: 跨模块追踪）**
- 追踪从 LLM 输出到 API 调用的完整路径
- 检查是否有中间步骤验证请求
- 验证日志记录和监控

## Classify

**确认为漏洞的特征：**
1. API 工具接受任意 endpoint，无白名单
2. 允许所有 HTTP 方法（包括 DELETE、PATCH）
3. 请求大小和频率无限制
4. 可以使用应用的 API 密钥进行 API 调用
5. 无法区分内部 API 和外部 API

**误报场景：**
1. API 工具仅允许特定的、预定义的端点
2. 只允许安全的 HTTP 方法（GET、HEAD）
3. 有严格的请求大小和频率限制
4. API 密钥不可被 LLM 访问
5. 完整的审计日志记录

**代码异味（需要深入审查）**
1. 动态构造 API 端点
2. 条件性地允许某些端点
3. 请求参数直接来自 LLM
4. 缺少请求验证

## Low risk

**评级为低风险的场景：**
1. API 工具只允许特定的、已知的安全端点
2. 仅支持读操作（GET），无修改操作
3. 有严格的请求大小限制（如 10KB）
4. 有频率限制（如每分钟 1 次请求）
5. 不使用实际的 API 密钥，仅用于演示或内部测试
