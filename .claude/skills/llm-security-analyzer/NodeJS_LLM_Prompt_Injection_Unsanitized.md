# **NodeJS LLM Prompt Injection Unsanitized**

当 Node.js 应用将用户输入未经清理直接拼接到发送给 LLM 的提示词中，或使用模板引擎动态生成提示词但未进行转义，攻击者可以注入恶意提示词，改变模型行为或提取敏感信息。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索字符串拼接：`\`...\${userInput}\`、`"..." + userInput`、`template.format()`
- 查找 LLM 库调用：`openai.chat.completions.create()`、`anthropic.messages.create()`
- 搜索模板引擎：`template.compile()`、`Handlebars.compile()`、`ejs.render()`
- 定位 prompt 构造：`systemPrompt`、`userMessage`、`messages array`
- 查找是否有提示词模板文件

**核心操作保护机制（L2: 跳读）**
- 检查是否使用了参数化的提示词构造
- 验证是否对输入进行了验证和清理
- 查看是否使用了专门的 LLM 提示词库（如 LangChain）
- 检查是否有输入长度和内容限制
- 查看模板是否启用了自动转义

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪从用户输入到 LLM 调用的数据流
- 检查是否有多个拼接点
- 审查提示词模板结构，查看用户输入的位置
- 查看是否有分隔符或边界标记
- 检查是否对特殊字符进行了处理

**数据流追踪（L4: 跨模块追踪）**
- 追踪用户输入从 HTTP 请求、数据库到 LLM 调用
- 检查是否有中间处理步骤
- 验证错误消息中是否也包含未清理的输入

## Classify

**确认为漏洞的特征：**
1. 用户可控的输入通过字符串模板直接进入提示词
2. 未对输入进行长度、格式、内容验证
3. 提示词模板中明确了用户输入的位置但无保护
4. 可以观察到提示注入的效果（模型行为改变）
5. 应用的系统提示可以被用户注入的内容覆盖

**误报场景：**
1. 用户输入仅用于参数化的特定字段（如查询值）
2. 使用了 LangChain PromptTemplate 等安全构造
3. 输入经过了严格的验证（长度、格式、正则表达式）
4. 提示词系统设计清晰指定了用户输入区域和格式
5. 使用了 sandboxed 的提示词注入防护库

**代码异味（需要深入审查）**
1. 多层嵌套的字符串模板
2. 动态生成的提示词内容
3. 条件性地包含用户输入
4. 相同模式的提示词拼接在多个地方

## Low risk

**评级为低风险的场景：**
1. 使用 LangChain、LlamaIndex 等框架的参数化提示词
2. 输入长度严格限制且经过验证
3. 提示词系统设计明确，用户输入与指令完全分离
4. 模型配置了 JSON schema，限制输出格式
5. 有明确的提示词版本控制和审核机制
