# **Python LLM Context Leaking**

当 Python 应用维护 LLM 会话或上下文时，多个用户的上下文数据混淆或被错误地共享，导致敏感信息泄露给未授权的用户。这在使用全局变量、线程本地存储不当或缓存时常见。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索全局变量：`global conversation`、`global context`、`global history`
- 查找线程本地存储：`threading.local()`、`contextvars.ContextVar`
- 搜索缓存机制：`functools.cache`、`Redis`、`Memcached`
- 查找会话管理：`session[]`、`request.session`、`SessionMiddleware`
- 定位多用户处理：`for user_id in users`、`async def handle_user()`

**核心操作保护机制（L2: 跳读）**
- 检查是否为每个用户维护独立的上下文
- 验证缓存键是否包含用户标识（user_id）
- 查看是否使用了线程安全的数据结构
- 检查异步代码中是否正确使用了 `contextvars`
- 查看会话隔离是否正确实现

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪上下文变量的生命周期
- 检查是否有全局变量被多个请求共享
- 审查缓存清理逻辑
- 查看并发请求处理中是否有竞态条件
- 检查错误处理是否会暴露其他用户的数据

**数据流追踪（L4: 跨模块追踪）**
- 追踪会话创建到销毁的完整生命周期
- 检查多个模块是否都正确隔离了用户数据
- 验证日志和错误消息中是否泄露了敏感信息

## Classify

**确认为漏洞的特征：**
1. 使用全局变量存储用户会话或上下文，无用户隔离
2. 缓存键未包含用户标识，多用户共享缓存结果
3. 线程本地存储在异步环境中使用不当
4. 上下文变量未正确清理，导致跨请求泄露
5. 多租户应用中，用户能够访问其他用户的上下文

**误报场景：**
1. 上下文完全隔离，每个用户有独立的会话
2. 缓存键明确包含用户标识和权限信息
3. 使用 `contextvars` 正确管理异步上下文
4. 每个请求完成后都清理了上下文
5. 会话管理由框架（Flask、Django）完全处理

**代码异味（需要深入审查）**
1. 全局变量被多个函数修改
2. 缓存清理逻辑不明确
3. 异步代码中混合了线程本地存储和 contextvars
4. 会话超时设置不合理

## Low risk

**评级为低风险的场景：**
1. 每个用户的上下文完全独立，使用 request-scoped 存储
2. 缓存键包含完整的用户标识和权限信息
3. 正确使用 `contextvars.ContextVar` 处理异步
4. 会话框架（如 Flask-Session、Django sessions）正确配置
5. 敏感数据不在上下文中存储，仅在需要时从数据库查询
