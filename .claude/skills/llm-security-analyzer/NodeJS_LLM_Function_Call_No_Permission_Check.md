# **NodeJS LLM Function Call No Permission Check**

当 Node.js 应用实现 LLM function calling 或 tool use 时，未在执行前检查调用者权限，攻击者可以通过提示注入使模型调用敏感函数，执行未授权的操作。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索函数定义：`tools: []`、`functions: []`、`availableFunctions`、`toolRegistry`
- 查找函数执行：`executeFunction()`、`getFunction()`、`functionMap[name]()`、`dynamic require`
- 搜索权限检查缺失的地方：执行函数前是否调用了 `checkPermission()`、`authorize()`
- 查找 Express 路由权限检查：`req.user`、`req.isAuthenticated()`
- 定位系统操作：`child_process.exec()`、`fs.readFile()`、`database.query()`

**核心操作保护机制（L2: 跳读）**
- 检查每个工具函数是否都有权限检查
- 验证权限检查是否在函数执行前进行
- 查看是否使用了白名单限制可用的工具
- 检查是否验证了函数参数
- 查看是否有日志记录函数调用

**快速定位到具体漏洞（L3: 逐行读）**
- 在函数执行点追踪权限检查
- 检查 `if (userPermissions.includes(toolName))` 之类的逻辑
- 审查函数参数的验证
- 查看是否有条件分支导致权限检查被绕过
- 检查异常处理是否隐藏了错误

**数据流追踪（L4: 跨模块追踪）**
- 追踪从 LLM 输出到函数执行的完整路径
- 检查多步函数调用是否在每步都进行检查
- 验证错误处理中是否也进行权限检查

## Classify

**确认为漏洞的特征：**
1. 工具列表包含敏感操作，无权限检查
2. 函数执行前未验证调用者权限
3. 使用反射动态执行函数，无白名单
4. 参数未验证直接用于敏感操作
5. LLM 选择的函数直接在高权限上下文中执行

**误报场景：**
1. 所有可用工具都是只读、无害的操作
2. 有明确的白名单，只有授权的函数可被 LLM 访问
3. 每个函数执行前都进行权限检查
4. 参数经过严格验证
5. 敏感操作有额外的确认步骤

**代码异味（需要深入审查）**
1. 动态生成的工具列表
2. 多个权限检查点
3. 条件性地包含/排除工具
4. 复杂的权限逻辑

## Low risk

**评级为低风险的场景：**
1. 工具完全是只读操作，无法修改数据
2. 白名单机制，只有预定义的安全工具
3. 参数严格验证（长度、格式、范围）
4. 每个工具调用前都验证权限，无条件分支
5. 敏感操作需要人工确认或二次认证
