# **Go LLM Function Call Permission Missing**

当 Go 应用的 LLM function calling 缺少权限检查，攻击者可以通过提示注入使模型调用不应被执行的函数。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索工具定义：`tools := []`、`type Tool struct`、`availableFunctions`
- 查找函数执行：`reflect.ValueOf()`、`functionMap[name]()`、`executeFunc()`
- 搜索权限检查：缺失的 `canExecute()`、`checkPermission()`
- 查找敏感操作：`os.`、`ioutil.`、`database/sql`、`http.`
- 定位工具列表：工具定义部分

**核心操作保护机制（L2: 跳读）**
- 检查是否有白名单限制可用函数
- 验证是否在执行前检查权限
- 查看函数参数是否经过验证
- 检查是否有日志记录
- 查看是否有资源限制

**快速定位到具体漏洞（L3: 逐行读）**
- 在函数执行前检查权限逻辑
- 追踪函数名称来源
- 审查参数验证
- 查看异常处理
- 检查条件分支

**数据流追踪（L4: 跨模块追踪）**
- 追踪从 LLM 到函数执行的路径
- 检查多个执行点

## Classify

**确认为漏洞的特征：**
1. 工具列表包含敏感操作
2. 直接执行 LLM 选择的函数
3. 无白名单机制
4. 参数未验证
5. 无权限检查

**误报场景：**
1. 明确的白名单
2. 权限检查在执行前
3. 参数严格验证
4. 完整的审计日志
5. 安全的函数

**代码异味（需要深入审查）**
1. 动态函数列表
2. 多个权限检查点
3. 条件性包含函数
4. 复杂的权限逻辑

## Low risk

**评级为低风险的场景：**
1. 函数是只读安全操作
2. 白名单机制
3. 执行前权限检查
4. 参数验证
5. 敏感操作需要确认
