# **PHP LLM Session Isolation Failure**

当 PHP 应用的 LLM 会话数据在多用户环境中未能正确隔离，不同用户的数据可能混淆或相互访问。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索全局变量：`global $conversation`、`$GLOBALS`
- 查找会话使用：`$_SESSION`、`session_start()`
- 搜索缓存：`apcu_store()`、`cache`、`redis`
- 查找用户隔离：缺失的 `$_SESSION['user_id']` 检查
- 定位会话存储：文件、数据库、内存

**核心操作保护机制（L2: 跳读）**
- 检查是否为每个用户隔离了会话
- 验证会话键是否包含用户标识
- 查看缓存键是否隔离
- 检查会话超时设置
- 查看是否有会话销毁逻辑

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪会话的存储和访问方式
- 检查用户隔离逻辑
- 审查缓存键的构造
- 查看会话清理
- 检查全局变量使用

**数据流追踪（L4: 跨模块追踪）**
- 追踪会话的完整生命周期
- 检查隔离机制

## Classify

**确认为漏洞的特征：**
1. 会话数据未按用户隔离
2. 全局变量存储会话
3. 缓存键未包含用户标识
4. 会话超时不合理
5. 无会话销毁逻辑

**误报场景：**
1. 会话由 PHP 容器管理，隔离正确
2. 缓存键包含用户标识
3. 会话超时合理
4. 正确的销毁逻辑
5. 敏感数据不缓存

**代码异味（需要深入审查）**
1. 全局变量使用
2. 缓存键构造不清晰
3. 会话超时设置不明确
4. 清理逻辑缺失

## Low risk

**评级为低风险的场景：**
1. 会话由 PHP 正确管理
2. 缓存键包含用户标识
3. 会话超时设置合理（如 30 分钟）
4. 正确的销毁逻辑
5. 敏感数据不在会话中缓存
