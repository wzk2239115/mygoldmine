# **Java LLM Function Call No Access Control**

当 Java 应用的 LLM function calling 功能缺少访问控制检查，攻击者可以通过提示注入使模型调用应该被限制的函数，执行未授权操作。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索工具定义：`@Tool`、`@Function`、`tools = `、`functions = `
- 查找函数执行：`invokeFunction()`、`Method.invoke()`、`executor.execute()`
- 搜索权限检查缺失的地方：直接执行函数前无 `checkPermission()`
- 查找敏感操作：文件操作、数据库操作、系统命令
- 定位函数列表定义：`availableFunctions`、`toolRegistry`

**核心操作保护机制（L2: 跳读）**
- 检查是否有白名单限制可用的函数
- 验证每个函数执行前是否进行了权限检查
- 查看是否使用了 Java 的权限系统（SecurityManager）
- 检查函数参数是否经过验证
- 查看是否有日志记录函数调用

**快速定位到具体漏洞（L3: 逐行读）**
- 在函数执行点检查权限检查逻辑
- 追踪函数选择的方式（直接名称或反射）
- 审查函数参数的验证
- 查看异常处理中是否隐藏了权限检查
- 检查是否有条件分支导致检查被绕过

**数据流追踪（L4: 跨模块追踪）**
- 追踪从 LLM 输出到函数执行的完整路径
- 检查多步函数调用是否都进行了检查
- 验证权限模型的正确实现

## Classify

**确认为漏洞的特征：**
1. 工具列表包含敏感操作，无访问控制
2. 直接根据 LLM 输出执行函数，无权限检查
3. 使用反射动态执行函数，无白名单
4. 函数参数未验证直接使用
5. 没有人工审核或确认步骤

**误报场景：**
1. 有明确的白名单，只有预定义的安全函数可用
2. 每个函数执行前都进行权限检查
3. 敏感函数需要额外的身份验证
4. 参数经过严格验证
5. 有完整的审计日志

**代码异味（需要深入审查）**
1. 动态生成函数列表
2. 多个权限检查点
3. 条件性地包含函数
4. 权限检查逻辑复杂

## Low risk

**评级为低风险的场景：**
1. 函数是只读、无害的操作
2. 白名单机制，只有预定义的函数
3. 函数执行前都进行权限检查，无条件分支
4. 参数严格验证
5. 敏感操作需要额外确认或管理员批准
