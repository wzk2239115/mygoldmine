# **C LLM Output Buffer Overflow**

当 C 应用将 LLM 输出写入固定大小的缓冲区而未进行边界检查，可能导致缓冲区溢出，导致崩溃或任意代码执行。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索不安全函数：`strcpy()`、`sprintf()`、`gets()`、`scanf()`
- 查找缓冲区声明：`char buffer[256]`
- 搜索 LLM 输出复制：`strcpy(buffer, llm_output)`
- 查找边界检查：缺失的 `strlen()` 检查、`sizeof()` 比较
- 定位不安全的读写：未限制的 memcpy、read 等

**核心操作保护机制（L2: 跳读）**
- 检查是否使用了安全函数（strncpy、snprintf）
- 验证是否进行了长度检查
- 查看缓冲区大小定义
- 检查是否使用了堆栈栅栏或 ASLR
- 查看是否有运行时保护

**快速定位到具体漏洞（L3: 逐行读）**
- 审查所有字符串操作
- 检查边界检查逻辑
- 查看缓冲区分配
- 审查输入大小验证
- 检查错误处理

**数据流追踪（L4: 跨模块追踪）**
- 追踪缓冲区的使用
- 检查所有写入操作

## Classify

**确认为漏洞的特征：**
1. 使用 strcpy、sprintf 等不安全函数
2. 缺少边界检查
3. 固定大小缓冲区接收动态数据
4. 未验证 LLM 输出大小
5. 可能导致溢出

**误报场景：**
1. 使用 strncpy、snprintf 等安全函数
2. 进行了完整的边界检查
3. 使用了堆栈保护
4. 输入大小限制
5. 静态分析无缺陷

**代码异味（需要深入审查）**
1. 不安全函数使用
2. 缺少长度检查
3. 多个缓冲区操作
4. 复杂的内存管理

## Low risk

**评级为低风险的场景：**
1. 仅使用安全函数（strncpy、snprintf）
2. 完整的边界检查
3. 堆栈保护启用
4. 输入大小限制
5. 定期代码审查和测试
