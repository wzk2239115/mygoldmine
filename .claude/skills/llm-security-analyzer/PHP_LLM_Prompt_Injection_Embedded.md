# **PHP LLM Prompt Injection Embedded**

当 PHP 应用将用户输入嵌入到 LLM 提示词中而未进行清理，攻击者可以通过注入恶意提示词改变模型行为。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索字符串插值：`"...$variable..."`、`'{$var}'`、`implode()`
- 查找提示词构造：`$prompt = `、`$message = `
- 搜索 LLM 调用：`OpenAI`、`Anthropic`、`curl`、`client->chat()`
- 查找未清理的输入：`$_GET`、`$_POST`、`$_REQUEST`
- 定位消息数组：`$messages = []`

**核心操作保护机制（L2: 跳读）**
- 检查是否对输入进行了验证
- 验证是否使用了参数化消息构造
- 查看是否有长度限制
- 检查是否分离了系统和用户消息
- 查看是否有提示词注入检测

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪从用户输入到提示词的构造
- 检查字符串插值的方式
- 审查验证逻辑
- 查看消息结构
- 检查是否有清理

**数据流追踪（L4: 跨模块追踪）**
- 追踪用户输入的完整处理
- 检查所有提示词构造点

## Classify

**确认为漏洞的特征：**
1. 直接使用用户输入构造提示词
2. 未进行任何验证
3. 可以覆盖系统提示
4. 提示词结构不清晰
5. 注入效果可观察

**误报场景：**
1. 输入严格验证和清理
2. 消息明确分离
3. 长度严格限制
4. 参数化构造
5. 提示词由应用控制

**代码异味（需要深入审查）**
1. 多个拼接点
2. 动态提示词
3. 缺少验证
4. 模板处理提示

## Low risk

**评级为低风险的场景：**
1. 输入严格验证
2. 消息明确分离
3. 长度限制
4. 参数化消息
5. 清晰的提示词设计
