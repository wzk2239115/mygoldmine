# **NodeJS LLM Context Isolation Failure**

当 Node.js 应用在多用户环境中，LLM 会话上下文（聊天历史、用户信息）未能正确隔离，不同用户的数据可能被混淆或泄露。这在使用全局变量、不当的对象共享或异步处理不当时常见。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索全局变量：`global.conversation`、`global.context`、`module.exports.history`
- 查找对象共享：`const context = {}` 在函数外声明，多次调用共享
- 搜索会话管理：`req.session`、`app.locals`、`sessionStorage`
- 查找异步操作：`async (req, res) =>`、`await`、`Promise`
- 定位变量生命周期：缓存、内存存储、连接对象

**核心操作保护机制（L2: 跳读）**
- 检查是否为每个用户创建了独立的上下文对象
- 验证会话管理是否正确隔离
- 查看是否有全局变量存储用户数据
- 检查缓存键是否包含用户标识
- 查看异步操作中是否有竞态条件

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪上下文对象的创建和销毁
- 检查是否使用了 `req.user` 或 `req.session` 来隔离数据
- 审查并发请求处理
- 查看是否有全局变量被多个请求修改
- 检查错误处理中的数据泄露

**数据流追踪（L4: 跨模块追踪）**
- 追踪会话创建到销毁的完整生命周期
- 检查多个中间件是否都正确隔离了用户数据
- 验证缓存清理逻辑

## Classify

**确认为漏洞的特征：**
1. 使用全局变量存储用户会话，无用户隔离
2. 对象在函数外创建并在多个请求间共享
3. 缓存键未包含用户标识，多用户共享结果
4. 异步操作中的竞态条件
5. 多用户能够访问彼此的会话数据

**误报场景：**
1. 为每个请求创建独立的上下文对象
2. 正确使用 `req.session` 或 `req.user` 隔离数据
3. 缓存键包含用户标识
4. 没有全局共享状态
5. 会话框架正确配置和使用

**代码异味（需要深入审查）**
1. 全局变量被多个路由修改
2. 缓存清理逻辑不清晰
3. 对象被多个请求处理器使用
4. 会话超时设置不合理

## Low risk

**评级为低风险的场景：**
1. 每个请求都创建独立的上下文对象
2. 正确使用 Express session 中间件
3. 缓存键明确包含用户标识和权限
4. 没有全局共享状态
5. 敏感数据不在内存中存储，仅在需要时从数据库查询
