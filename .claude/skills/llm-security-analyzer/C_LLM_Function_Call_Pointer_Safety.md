# **C LLM Function Call Pointer Safety**

当 C 应用使用指针或函数指针实现 LLM function calling，但未进行适当的验证，攻击者可能通过覆盖指针或调用不应被执行的函数指针实现任意代码执行。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索函数指针：`typedef ... (*func_ptr)()`、`(*func)()`
- 查找指针赋值：`func_ptr = &function`、`func_ptr = NULL + offset`
- 搜索动态执行：`(*function_ptr)(args)`、`dlsym()`
- 查找指针验证：缺失的指针有效性检查
- 定位工具函数表：`struct tool_t`、`function_array[]`

**核心操作保护机制（L2: 跳读）**
- 检查是否验证了函数指针的有效性
- 验证是否使用了白名单
- 查看指针来源是否受控
- 检查是否有地址空间布局随机化（ASLR）
- 查看是否有运行时保护

**快速定位到具体漏洞（L3: 逐行读）**
- 审查指针赋值和使用
- 检查指针验证逻辑
- 查看白名单实现
- 审查指针计算
- 检查边界检查

**数据流追踪（L4: 跨模块追踪）**
- 追踪指针的来源和使用
- 检查所有指针操作

## Classify

**确认为漏洞的特征：**
1. 函数指针来自未验证的输入
2. 缺少指针有效性检查
3. 指针可被覆盖
4. 无白名单机制
5. 无运行时保护

**误报场景：**
1. 有白名单机制
2. 指针验证完整
3. 指针来源受控
4. 有运行时保护
5. 栈金丝雀或 CFI 启用

**代码异味（需要深入审查）**
1. 函数指针数组
2. 指针计算
3. 动态加载函数
4. 缺少验证

## Low risk

**评级为低风险的场景：**
1. 有完整的白名单
2. 函数指针验证正确
3. ASLR 和栈保护启用
4. CFI 或类似技术启用
5. 定期代码审查
