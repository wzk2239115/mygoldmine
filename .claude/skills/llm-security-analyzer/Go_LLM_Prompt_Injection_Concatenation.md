# **Go LLM Prompt Injection Concatenation**

当 Go 应用将用户输入直接连接到发送给 LLM 的提示词中，攻击者可以通过注入恶意提示词改变模型行为或提取敏感信息。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索字符串拼接：`fmt.Sprintf()`、`strings.Builder`、`+ userInput`、`` `...${userInput}` ``
- 查找 LLM 调用：`openai.CreateChatCompletion()`、`client.CreateCompletion()`
- 搜索消息构造：`messages = []`、`Content: userInput`
- 查找模板使用：`template.Execute()`、`text/template`
- 定位提示词变量：`systemPrompt`、`userMessage`

**核心操作保护机制（L2: 跳读）**
- 检查是否使用了参数化的消息构造
- 验证是否对输入进行了验证
- 查看是否使用了安全的字符串处理库
- 检查是否有输入长度限制
- 查看是否分离了系统和用户消息

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪从用户输入到提示词的构造
- 检查是否有多个拼接点
- 审查字符串拼接的方式
- 查看消息列表的构造
- 检查是否有清理或转义

**数据流追踪（L4: 跨模块追踪）**
- 追踪用户输入的完整处理
- 检查所有提示词构造点

## Classify

**确认为漏洞的特征：**
1. 直接拼接用户输入到提示词字符串
2. 未对输入进行验证或清理
3. 可以覆盖系统提示
4. 提示词结构不清晰
5. 可以观察到注入的效果

**误报场景：**
1. 输入经过严格验证
2. 消息明确分离（SystemMessage vs UserMessage）
3. 使用参数化的消息构造
4. 长度严格限制
5. 提示词系统设计清晰

**代码异味（需要深入审查）**
1. 多个拼接点
2. 动态提示词构造
3. 缺少输入验证
4. 模板处理 LLM 提示

## Low risk

**评级为低风险的场景：**
1. 使用 LangChain-Go 等框架的安全 API
2. 消息明确分离且无用户输入在系统提示中
3. 输入严格限制长度和格式
4. 明确的提示词设计
5. 版本控制和审核机制
