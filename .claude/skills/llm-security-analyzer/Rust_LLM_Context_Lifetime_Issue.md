# **Rust LLM Context Lifetime Issue**

当 Rust 应用在异步并发环境中处理 LLM 上下文时，生命周期问题可能导致数据竞态或使用释放后的数据（use-after-free），影响多用户的数据隔离。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索异步代码：`async fn`、`await`、`tokio::spawn()`
- 查找生命周期：缺失的生命周期标注、`'static`、`'a`
- 搜索全局状态：`static`、`lazy_static!`、`Mutex<>`
- 查找数据共享：`Arc<Mutex<>>`、`Rc<>`、`&self`
- 定位会话存储：上下文对象的存储和传递

**核心操作保护机制（L2: 跳读）**
- 检查是否正确使用了生命周期
- 验证是否使用了适当的智能指针
- 查看是否有数据竞态
- 检查是否使用了 Send/Sync traits
- 查看是否有正确的同步机制

**快速定位到具体漏洞（L3: 逐行读）**
- 审查异步函数的生命周期
- 检查智能指针的使用
- 查看数据的所有权转移
- 审查同步原语
- 检查编译器警告

**数据流追踪（L4: 跨模块追踪）**
- 追踪数据在异步任务间的流动
- 检查生命周期的正确性

## Classify

**确认为漏洞的特征：**
1. 不安全的生命周期使用（`transmute`、`unsafe`）
2. 使用 `Rc<>` 在异步代码中
3. 共享可变状态无同步
4. 数据竞态风险
5. 编译时不安全代码

**误报场景：**
1. 正确的生命周期标注
2. 使用 `Arc<Mutex<>>` 等安全智能指针
3. 正确的 Send/Sync 实现
4. 适当的同步机制
5. 类型系统保证安全

**代码异味（需要深入审查）**
1. unsafe 块
2. transmute 使用
3. 复杂的生命周期
4. 多个 Mutex 嵌套

## Low risk

**评级为低风险的场景：**
1. 无 unsafe 代码或 unsafe 代码最小化
2. 正确使用 Arc<Mutex<>> 和 tokio::sync
3. 生命周期标注清晰正确
4. Send/Sync traits 正确实现
5. 编译无警告
