# **C LLM Prompt Injection Native**

当 C 应用使用本地 LLM 推理库或直接调用 LLM API 时，将用户输入未清理地传递给模型，导致提示注入漏洞。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索字符串拼接：`strcat()`、`sprintf()`、`snprintf()`
- 查找 LLM 调用：本地模型库如 `llama.cpp`、或 API 调用
- 搜索提示词构造：`prompt = `、`message = `
- 查找输入来源：命令行参数、文件读取、网络输入
- 定位消息数组：提示词数组或结构体

**核心操作保护机制（L2: 跳读）**
- 检查是否对输入进行了验证
- 验证是否有长度限制
- 查看是否分离了系统和用户提示
- 检查是否使用了参数化构造
- 查看是否有提示词模板

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪字符串拼接的方式
- 检查边界和长度检查
- 审查输入验证
- 查看提示词结构
- 检查是否有清理逻辑

**数据流追踪（L4: 跨模块追踪）**
- 追踪输入的完整处理
- 检查提示词构造点

## Classify

**确认为漏洞的特征：**
1. 用户输入直接拼接到提示词
2. 未进行验证或清理
3. 可以覆盖系统提示
4. 提示词结构不清晰
5. 注入效果可观察

**误报场景：**
1. 输入严格验证
2. 长度严格限制
3. 消息明确分离
4. 参数化构造
5. 清晰的提示词设计

**代码异味（需要深入审查）**
1. 字符串拼接
2. 多个构造点
3. 缺少验证
4. 动态提示词

## Low risk

**评级为低风险的场景：**
1. 输入严格验证和限制
2. 消息明确分离
3. 参数化提示词
4. 清晰设计
5. 定期审查
