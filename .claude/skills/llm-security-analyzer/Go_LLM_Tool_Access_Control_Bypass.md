# **Go LLM Tool Access Control Bypass**

当 Go 应用的 LLM 工具访问控制存在漏洞，攻击者可以通过提示注入或其他方式绕过权限检查，访问不应被访问的工具或数据。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索权限检查：`canAccess()`、`checkPermission()`、缺失的检查
- 查找工具列表：`tools := []`、`ToolRegistry`
- 搜索访问决策：`if user.Role ==`、权限逻辑
- 查找绕过方式：条件分支、特殊值处理
- 定位敏感工具：文件操作、数据库、系统命令

**核心操作保护机制（L2: 跳读）**
- 检查权限检查是否完整
- 验证是否有条件分支导致绕过
- 查看是否使用了白名单
- 检查权限模型是否正确
- 查看是否有日志审计

**快速定位到具体漏洞（L3: 逐行读）**
- 审查权限检查逻辑
- 检查条件分支
- 追踪权限的传递
- 查看特殊值处理
- 检查错误处理

**数据流追踪（L4: 跨模块追踪）**
- 追踪权限检查的完整流程
- 检查所有访问点

## Classify

**确认为漏洞的特征：**
1. 权限检查不完整或缺失
2. 存在条件分支导致绕过
3. 特殊值（如 admin）处理不当
4. 权限模型有漏洞
5. 无法审计访问

**误报场景：**
1. 权限检查完整且无条件分支
2. 使用白名单机制
3. 权限模型正确
4. 有完整的审计日志
5. 定期安全审查

**代码异味（需要深入审查）**
1. 多个权限检查点
2. 条件性检查
3. 特殊值处理
4. 权限逻辑复杂

## Low risk

**评级为低风险的场景：**
1. 权限检查完整无漏洞
2. 白名单机制
3. 权限模型清晰正确
4. 完整的审计日志
5. 定期安全审查和测试
