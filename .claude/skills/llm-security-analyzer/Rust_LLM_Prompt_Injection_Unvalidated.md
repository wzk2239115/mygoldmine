# **Rust LLM Prompt Injection Unvalidated**

当 Rust Web 应用（如 Actix-web、Rocket）将用户输入未验证地拼接到 LLM 提示词中，攻击者可以通过提示注入改变模型行为或提取敏感信息。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索字符串操作：`format!()`、`format_args!`、`to_string()`、`+` 拼接
- 查找 LLM 调用：`client.create_chat_completion()`、`openai-rust`
- 搜索消息构造：`vec![Message]`、`messages.push()`
- 查找输入来源：`web::Path`、`web::Query`、`web::Json`
- 定位提示词：`system_prompt`、`user_message`

**核心操作保护机制（L2: 跳读）**
- 检查是否对输入进行了验证
- 验证是否使用了类型安全的消息构造
- 查看是否有长度限制
- 检查是否使用了结构化数据而非字符串
- 查看是否分离了系统和用户消息

**快速定位到具体漏洞（L3: 逐行读）**
- 追踪字符串拼接的方式
- 检查验证逻辑
- 审查消息结构
- 查看长度检查
- 检查是否有清理

**数据流追踪（L4: 跨模块追踪）**
- 追踪输入的完整处理
- 检查提示词构造点

## Classify

**确认为漏洞的特征：**
1. 直接拼接用户输入到提示词字符串
2. 未进行验证
3. 可以覆盖系统提示
4. 提示词结构不清晰
5. 注入可观察

**误报场景：**
1. 输入验证完整
2. 长度严格限制
3. 消息明确分离
4. 参数化构造
5. 清晰的设计

**代码异味（需要深入审查）**
1. 字符串拼接
2. 多个构造点
3. 缺少验证
4. 动态提示词

## Low risk

**评级为低风险的场景：**
1. 输入验证完整
2. 长度限制合理
3. 消息分离清晰
4. 参数化提示词
5. 定期审查
