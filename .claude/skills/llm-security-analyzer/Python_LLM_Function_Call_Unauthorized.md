# **Python LLM Function Call Unauthorized**

当 LLM 集成的 function calling 或 tool use 功能缺少身份认证、权限检查或访问控制机制时，攻击者可以通过恶意提示注入，使模型调用不应被执行的函数或访问受限资源。

## Details

**代码示例位置识别技巧（L1: 关键词扫描）**
- 搜索 function calling 定义：`tools=[]`、`functions=[]`、`function_definitions`、`@tool`
- 查找 OpenAI function calling：`response.choices[0].message.tool_calls`
- 搜索 Anthropic tools：`tools=[Tool(...)]`、`@anthropic_sdk.tool`
- 定位函数执行点：`getattr()`、`globals()[func_name]()`、`function_map[name]()`
- 查找敏感操作：文件读写、数据库操作、网络请求、系统命令

**核心操作保护机制（L2: 跳读）**
- 检查是否对每个可用函数验证了调用权限
- 查看是否在函数执行前检查了调用者身份
- 验证是否使用了白名单明确指定哪些函数可被 LLM 调用
- 检查函数参数是否经过验证和清理
- 查看是否有日志记录函数调用审计

**快速定位到具体漏洞（L3: 逐行读）**
- 在函数执行点检查权限检查逻辑
- 追踪 LLM 选择的函数名称是否直接使用
- 审查函数参数的验证和清理
- 查看是否有异常处理隐藏了权限拒绝
- 检查是否有条件分支导致权限检查被绕过

**数据流追踪（L4: 跨模块追踪）**
- 追踪用户输入到 LLM 调用再到函数执行的完整链
- 检查多步骤的函数调用是否在每步都进行权限检查
- 验证错误处理路径中是否也进行权限检查

## Classify

**确认为漏洞的特征：**
1. 定义的可用函数（tools/functions）包含敏感操作，且无权限检查
2. 函数执行前未验证调用者身份或权限
3. 使用反射（`getattr()` 等）动态调用函数，且无黑/白名单
4. 函数参数未经验证直接用于敏感操作（如文件路径、SQL 查询）
5. LLM 生成的函数调用直接在高权限上下文中执行

**误报场景：**
1. 所有可用函数都是无害的、只读的操作
2. 有明确的白名单机制，且只有授权的函数被 LLM 访问
3. 函数执行前进行了完整的权限检查和参数验证
4. 应用有明确的用户权限模型，且正确映射到函数级别
5. 测试环境的函数与生产环境完全隔离

**代码异味（需要深入审查）：**
1. 函数列表动态生成
2. 有多个权限检查点
3. 条件性地包含/排除函数
4. 权限检查逻辑复杂或分散

## Low risk

**评级为低风险的场景：**
1. 定义的工具函数完全是只读操作，无法修改任何数据
2. 明确的白名单机制，列出所有允许的函数，其他函数不可调用
3. 函数参数被严格验证（如数值范围、字符串长度、正则表达式）
4. 每个函数调用前都进行权限检查，且无绕过方式
5. 敏感操作（如文件删除）需要额外确认步骤
