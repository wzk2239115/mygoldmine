# C/C++ 状态机跳转未校验前置条件

**漏洞类型**：状态转换绕过（State Transition Bypass）  
**审计等级**：L3-L4（逐行读+跨模块追踪）

---

## Details

### 核心特征
状态机在执行状态转换时，未验证当前状态是否允许目标状态的跳转，导致非法状态流转。

### 代码示例

```c
// 典型漏洞：直接设置状态，无前置校验
void updateOrderState(Order* order, int newState) {
    order->state = newState;  // 危险：未校验 order->state 是否可跳转到 newState
    processOrder(order);
}

// 常见场景：订单/会话/设备状态机
enum State { INIT=0, PENDING=1, CONFIRMED=2, SHIPPED=3, COMPLETED=4 };
void shipOrder(Order* o) {
    o->state = SHIPPED;  // 缺陷：可能从 INIT 直接跳到 SHIPPED
}
```

### 快速定位技巧

**核心操作定位（L1-L2）**：
- 关键词：`state`、`status`、`phase`、`stage`、`mode`、枚举类型赋值
- 模式：`obj->state = xxx`、`setState()`、`transition()`、`switch (state)`
- 重点函数：订单处理、会话管理、工作流引擎、设备控制

**保护机制定位（L3-L4）**：
- 查找状态转换表：`allowedTransitions[][]`、`canTransition(from, to)`
- 查找前置条件检查：`if (current_state != EXPECTED)`、状态白名单
- 跟踪状态赋值前的所有 `if/switch` 分支，确认是否覆盖非法路径

**高危信号**：
- 状态赋值前无任何条件判断
- 使用原始整型而非受限枚举（易被任意值污染）
- 外部输入直接影响状态值（API 参数、消息字段）
- 多线程环境下无锁保护状态读写（引发竞态）

---

## Classify

### 漏洞（需报告）
1. **外部可控触发**：API/消息/回调可直接操纵状态跳转，且无业务逻辑限制  
   → 例：未完成支付的订单可被标记为已发货
2. **绕过关键步骤**：跳过支付、审批、授权等关键中间态  
   → 例：从 `INIT` 直接跳到 `COMPLETED` 绕过支付验证
3. **竞态窗口**：多线程下状态检查与状态更新非原子，可插入非法转换  
   → 例：TOCTOU 漏洞，检查时是 A 状态，使用时已变 B 状态

### 误报（需排除）
1. **私有内部状态**：状态机完全在可信内部模块，无外部输入影响
2. **已有完整校验**：在调用链上游已强制验证前置状态（需跨模块确认）
3. **幂等操作**：重复状态转换无业务影响（如日志状态）

### 代码异味（建议改进）
1. 状态转换逻辑分散在多个文件，难以审计完整性
2. 使用 `int` 而非枚举定义状态，类型安全不足
3. 缺少状态转换日志，难以追溯异常流转

---

## Low Risk

以下情况可降级为低风险：

1. **内部管理界面**：仅管理员在后台操作状态，且有审计日志
2. **测试/调试接口**：仅在开发环境启用的状态切换接口（需确认生产禁用）
3. **无敏感资源**：状态机不涉及支付、权限、数据完整性（如 UI 展示状态）
4. **业务容错设计**：下游系统会二次验证状态合法性，本层绕过无实际影响
5. **状态可逆**：非法跳转可通过正常业务流程回退，不造成永久数据损坏

**审计建议**：即使低风险，也应建议添加状态转换矩阵验证，提升代码健壮性。
