# 通用业务逻辑缺陷模式（所有项目必审）

拿到任何包含业务逻辑处理的项目，无论使用何种编程语言，以下业务逻辑缺陷模式都必须进行审计。这些问题源于业务流程设计或实现上的缺陷，与具体语言实现无关。

## 状态转换未校验前置条件

### 状态机跳转缺乏前置条件验证

业务状态转换未校验当前状态或操作权限，允许非法状态跳转或绕过关键步骤：

- 订单状态可直接从"待支付"跳转到"已发货"，绕过支付步骤。**审计要点**：检查状态转换接口是否验证当前状态，是否只允许合法的状态跳转路径，是否存在状态转换白名单或状态机定义
- 审批流程状态转换未验证审批人权限或审批顺序。**审计要点**：验证状态转换时是否检查操作者权限，是否按审批顺序执行，是否存在审批链验证机制
- 状态机允许从任意状态回退到初始状态，可重复触发业务逻辑。**审计要点**：检查是否存在状态回退漏洞，是否允许重复触发关键业务逻辑，回退操作是否验证业务规则

### 多步骤流程可跳过中间环节

多步骤业务流程未强制顺序执行，可直接访问后续步骤绕过验证：

- 注册流程可跳过邮箱验证直接完成注册。**审计要点**：验证多步骤流程是否强制顺序执行，后续步骤是否验证前置步骤完成状态，是否使用会话或数据库记录步骤完成情况
- 支付流程可绕过金额确认直接调用支付完成接口。**审计要点**：检查支付完成接口是否验证前置确认步骤，金额是否与确认阶段一致，是否存在步骤令牌或状态验证
- 表单提交可跳过前置验证步骤，参数未与会话状态绑定。**审计要点**：验证表单提交是否与会话状态绑定，是否验证前置步骤完成，参数是否与步骤上下文关联

## 资源操作缺乏授权或归属验证

### 资源归属未验证

操作资源时未验证资源是否属于当前用户或当前用户是否有权限操作：

- 修改订单时未验证订单归属，可修改他人订单。**审计要点**：检查所有资源操作接口是否验证资源归属，是否在数据库查询中强制添加用户ID过滤条件，是否存在水平权限绕过
- 删除或更新资源时未校验操作者与资源所有者关系。**审计要点**：验证删除/更新操作是否检查资源所有者，是否验证操作者权限（所有者或管理员），是否存在权限提升漏洞
- 查询接口未过滤用户权限范围，可查看他人数据。**审计要点**：检查查询接口是否自动过滤用户权限范围，是否在SQL查询中添加用户ID条件，是否存在通过参数注入绕过过滤的情况

### 资源配额或限制未校验

资源分配或消耗操作未检查配额限制或权限边界：

- 积分扣减、余额消费未检查当前余额是否充足。**审计要点**：检查扣减操作前是否查询并验证当前余额，是否使用事务保证原子性，是否存在并发导致余额为负的情况
- 资源创建或分配未检查用户配额上限，可无限创建。**审计要点**：验证资源创建前是否检查用户配额，是否在数据库层面设置限制，是否存在绕过配额检查的接口
- API 调用频率或容量未限制，可超出预期使用量。**审计要点**：检查是否存在频率限制机制（如令牌桶、滑动窗口），是否在API网关或应用层实现限流，是否存在绕过限流的接口

## 并发竞态导致状态不一致

### 关键业务操作存在并发竞态

高并发场景下，状态更新或资源扣减存在竞态条件，导致数据不一致：

- 库存扣减、配额消耗存在并发竞态，可超卖或超限使用。**审计要点**：检查是否使用数据库锁（悲观锁/乐观锁）或分布式锁，是否在事务中执行扣减操作，是否存在"先查后改"的竞态条件
- 优惠券、积分兑换未实施去重或锁机制，可并发重复使用。**审计要点**：验证是否使用唯一约束或幂等性控制，是否在兑换时加锁，是否存在并发请求导致重复兑换的情况
- 账户余额更新、转账操作未加锁，可导致余额不一致。**审计要点**：检查余额更新是否在事务中执行，是否使用行锁或表锁，是否存在并发转账导致余额计算错误的情况

### 幂等性控制缺失

重复提交或重复调用导致资源重复分配或操作重复执行：

- 奖励发放、商品购买未实施幂等性控制，重复提交导致重复发放。**审计要点**：检查是否使用幂等性令牌（idempotency key），是否在数据库层面使用唯一约束，是否存在重复请求导致重复处理的情况
- 支付回调或异步通知未去重，可触发多次业务处理。**审计要点**：验证回调处理是否记录已处理的通知ID，是否使用数据库唯一约束防止重复处理，是否存在重放攻击风险
- 订单创建或状态更新接口未防重，可创建重复订单。**审计要点**：检查订单创建是否使用业务唯一标识（如订单号），是否在数据库层面设置唯一约束，是否存在重复提交导致重复订单的情况

## 回调或异步操作缺乏来源验证

### 第三方回调未验证合法性

支付回调、webhook、异步通知等未验证来源，可被伪造触发：

- 支付回调未验证签名或来源IP，可伪造支付成功通知。**审计要点**：检查回调接口是否验证签名（HMAC、RSA等），是否验证来源IP白名单，是否验证回调参数完整性，是否存在伪造支付成功的风险
- 第三方 webhook 通知未校验签名或 token，可伪造事件。**审计要点**：验证webhook接口是否校验签名或token，是否验证请求来源，是否验证事件类型和参数，是否存在伪造事件的风险
- 短信回调、邮件送达通知未验证，可伪造验证成功状态。**审计要点**：检查通知接口是否验证来源，是否验证通知内容完整性，是否存在伪造验证成功状态的风险，是否在服务端重新验证状态

### 异步任务触发上下文未校验

异步任务、定时任务、消息队列处理未验证触发来源或权限：

- 异步任务执行时未验证任务创建者权限或上下文。**审计要点**：检查异步任务是否携带创建者上下文信息，执行时是否验证权限，是否存在权限提升或越权执行的风险
- 消息队列消费者未验证消息来源或签名，可伪造消息。**审计要点**：验证消息队列消费者是否校验消息签名，是否验证消息来源，是否存在消息伪造导致业务逻辑被恶意触发的风险
- 定时任务触发时未校验执行条件，可被提前或重复触发。**审计要点**：检查定时任务是否验证执行条件（如时间窗口、前置条件），是否使用分布式锁防止重复执行，是否存在被提前或重复触发的风险

## 依赖客户端逻辑进行安全决策

### 信任客户端提交的业务参数

服务端直接使用客户端提交的业务关键参数（如价格、数量、权限标识）进行决策：

- 商品价格由客户端提交，服务端未校验，可篡改价格。**审计要点**：检查价格相关接口是否从数据库重新查询价格，是否验证价格与商品信息一致性，是否存在价格篡改导致的经济损失风险
- 权限判断、角色标识由客户端传递，服务端未验证。**审计要点**：验证权限和角色是否从服务端会话或数据库获取，是否完全信任客户端传递的权限标识，是否存在权限提升风险
- 优惠折扣、积分抵扣金额由客户端计算，服务端直接接受。**审计要点**：检查折扣和抵扣金额是否由服务端重新计算，是否验证计算规则和优惠条件，是否存在金额计算错误导致的经济损失风险

### 依赖前端状态或存储进行业务控制

业务流程控制依赖前端状态、本地存储或会话存储，可被篡改：

- 前端状态管理（如 Redux、Vuex）控制业务流程，可篡改绕过。**审计要点**：检查业务流程关键决策是否依赖前端状态，服务端是否重新验证业务状态，是否存在通过修改前端状态绕过业务逻辑的风险
- LocalStorage 或 SessionStorage 存储业务状态，可修改绕过校验。**审计要点**：验证业务关键状态是否存储在客户端，服务端是否验证状态合法性，是否存在通过修改本地存储绕过校验的风险
- SPA 路由守卫或权限控制仅在前端实现，后端未验证。**审计要点**：检查后端API是否独立验证权限，是否仅依赖前端路由守卫，是否存在通过直接调用API绕过前端权限控制的风险

## 条件判断逻辑不完整

### 边界条件或异常路径未覆盖

业务逻辑判断未考虑边界情况、异常值或特殊路径，存在绕过可能：

- 条件判断未覆盖负数、零值、空值等边界情况。**审计要点**：检查业务逻辑是否处理边界值（负数、零、空值、最大值、最小值），是否进行输入验证，是否存在边界值绕过业务规则的风险
- 异常捕获后业务流程继续执行，未终止或回滚。**审计要点**：验证异常处理是否正确终止业务流程，是否进行事务回滚，是否存在异常后继续执行导致数据不一致的风险
- 多个条件分支存在遗漏，特定组合可绕过校验。**审计要点**：检查条件判断是否覆盖所有可能的分支，是否存在条件组合漏洞，是否使用完整的if-else或switch-case结构，是否存在特定组合绕过校验的风险

### 不安全的相等性测试（CWE-1053）

使用不安全的比较操作符导致类型转换绕过或逻辑错误：

- PHP中 `==` 导致的类型转换：`0 == "admin"` 为真，绕过权限检查
- JavaScript中 `==` 类型转换：`null == undefined` 为真，`0 == false` 为真，导致条件判断异常
- Python中 `==` 而非 `is` 比较：`"0" == 0` 为真，`[] == False` 为真，可绕过特定条件判断
- 订单状态比较：`if (status == 0)` 可被意外匹配到其他值，应使用 `if (status === 0)` 或 `if (status == OrderStatus.PENDING)`
- 权限/角色检查中的类型混淆：字符串与整数混用导致权限检查逻辑失效
