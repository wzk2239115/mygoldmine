# PHP 上传文件名路径遍历

## Details

**代码示例**

```php
// 典型漏洞代码
$filename = $_FILES['upload']['name'];
$ext = pathinfo($filename, PATHINFO_EXTENSION);
if (in_array($ext, ['jpg', 'png', 'pdf'])) {
    move_uploaded_file($_FILES['upload']['tmp_name'], "/var/www/uploads/" . $filename);
}

// 攻击场景：文件名为 "../../config/database.php"
// 结果路径：/var/www/config/database.php (覆盖配置文件)
```

**快速定位核心操作技巧（L1-L2）**

- **L1 关键词扫描**：`move_uploaded_file`、`copy`、`file_put_contents`、`$_FILES`、`rename`
- **L2 跳读**：追踪 `$_FILES[*]['name']` 从获取到使用的流程，检查是否直接拼接到目标路径
- 关注点：文件名变量是否直接用于路径拼接，basename() 是否在扩展名检查后被绕过

**快速定位保护机制技巧（L1-L3）**

- **L1 关键词扫描**：`basename()`、`realpath()`、`preg_replace('/[^a-zA-Z0-9_.-]/')`、路径遍历过滤
- **L2 跳读**：检查是否对文件名进行 `../`、`..\\`、空字节过滤或白名单字符限制
- **L3 逐行读**：确认 basename() 调用时机（必须在路径拼接前）、realpath() 是否验证最终路径在预期目录内
- 注意：仅检查扩展名不足以防御，需同时处理文件名中的路径分隔符

## Classify

**漏洞判定**
- 文件名直接或仅经过扩展名检查后用于路径拼接
- 未使用 basename() 去除路径部分，或在错误位置调用（如扩展名检查前用但拼接时用原始值）
- 过滤不完整（仅过滤 `../` 但未过滤编码变体 `..%2f`、`..\`）

**误报判定**
- 文件名已通过 basename() 完全去除路径部分且无二次拼接原始文件名
- 使用随机生成的文件名（UUID、时间戳+随机数），完全忽略用户提供的文件名
- realpath() 验证最终路径在白名单目录内且正确处理符号链接

**代码异味**
- 使用黑名单过滤 `../`（易被绕过，如大小写、编码、重复字符）
- 扩展名检查后未对文件名做进一步处理直接使用（虽可能有其他防护但架构不佳）
- 依赖前端验证或客户端文件名过滤

## Low risk

**目标目录权限受限**
- 上传目录被严格限制为特定低权限目录，且 Web 服务器用户无法写入关键路径（如配置文件、代码目录）

**文件覆盖影响有限**
- 仅能覆盖同名上传文件（无关键功能文件存在于可遍历路径）
- 应用架构将上传文件与代码/配置完全隔离在不同分区或容器

**保护机制不完善但有缓解**
- 虽未使用 basename()，但路径拼接前有部分字符过滤（如过滤 `/`），仅能遍历同级子目录
- 文件名长度严格限制（如8字符），实际难以构造有效遍历路径

**上下文约束**
- 功能仅限管理员使用且有严格访问控制及审计日志
- 上传的文件类型限制为纯数据文件（如CSV），即使覆盖也无法执行代码
