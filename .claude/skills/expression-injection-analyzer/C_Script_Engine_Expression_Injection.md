# C/C++ 脚本引擎表达式注入

**漏洞成因**：使用 Lua、Perl、Tcl 等嵌入式脚本引擎执行用户提供的脚本代码或表达式，脚本环境未被正确沙箱化，导致用户可在脚本中访问危险对象或调用系统函数。常见于扩展配置、用户脚本、动态规则定义场景。

---

## Details

**代码示例**：
```c
// 危险：直接执行用户脚本
lua_State* L = luaL_newstate();
luaL_openlibs(L);  // 暴露所有标准库（包括 os、io）
const char* user_script = request_param("script");
luaL_dostring(L, user_script);  // 直接执行用户脚本

// 危险：Perl 表达式直接求值
perl_eval(interp, user_input);

// 较安全：限制脚本环境和沙箱化
lua_State* L = luaL_newstate();
// 仅加载需要的库，不加载 os 和 io
lua_newtable(L);  // 创建受限环境
luaL_register(L, "math", luaL_Reg_math);  // 仅暴露 math 库
lua_setglobal(L, "_G");
```

**快速定位核心操作**：
- 关键词：`luaL_dostring`、`luaL_loadstring`、`lua_call`、`perl_eval`、`Tcl_Eval`、脚本引擎初始化
- 检查脚本环境初始化时暴露了哪些库和对象
- 追踪用户输入到脚本执行函数的数据流
- 检查是否存在脚本执行环境的重用（多个用户共享一个 Lua 状态）
- 关注脚本超时和资源限制机制

**快速定位保护机制**：
- 是否创建了隔离的沙箱环境（限制库加载、禁用危险函数）
- 是否移除了脚本中的 require/import、os、io、system 等危险库
- 是否对脚本的长度、执行时间有限制
- 是否使用了脚本权限框架（如 Lua 的 capabilites）
- 是否对脚本进行了白名单验证或 AST 分析

**审计等级**：**L3-L4**
- **L3**：逐行分析脚本环境初始化和用户脚本的执行上下文
- **L4**：跨模块追踪脚本执行环境的生命周期，检查是否存在环境污染

---

## Classify

**确认为漏洞**：
- 脚本环境通过 `luaL_openlibs()` 或类似机制暴露所有标准库
- 用户输入直接传入脚本执行函数，未经验证
- 脚本环境未被沙箱化，可访问文件系统、进程管理、网络等危险 API
- 脚本环境被多个用户共享且未被隔离清理

**误报**：
- 脚本由应用内部定义，不接收用户输入
- 脚本环境被严格沙箱化，仅暴露安全的库和函数
- 脚本经过静态白名单验证，不支持动态代码执行
- 脚本执行在完全隔离的子进程中

**代码异味**：
- 脚本初始化代码不规范，包含过多暴露库的调用
- 脚本环境缺少超时和内存限制机制
- 脚本权限检查存在但不全面

---

## Low Risk

以下情况可评为低风险：
- **受限脚本能力**：脚本仅支持基础数据操作，不支持函数定义、循环、条件分支等高级特性
- **完全沙箱化**：脚本环境仅暴露算术、字符串处理等安全库，禁用所有 I/O 和系统库
- **内网脚本管理**：脚本由内部管理员编写和部署，普通用户无上传权限
- **执行隔离**：脚本在容器化环境或虚拟机中执行，权限最小化
- **严格超时控制**：脚本执行有严格的时间限制（< 100ms）和内存限制

**注意**：低风险≠可忽略，脚本注入风险的严重性取决于脚本环境的开放程度。
