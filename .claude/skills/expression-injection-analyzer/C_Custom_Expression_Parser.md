# C/C++ 自定义表达式解析器注入

**漏洞成因**：实现自定义的表达式解析或求值器，在处理用户输入的表达式时，未对表达式的语法、语义进行充分验证，导致用户通过特殊构造的表达式访问危险函数或越权操作。常见于数据查询、条件过滤、计算引擎等场景。

---

## Details

**代码示例**：
```c
// 危险：自定义表达式解析器允许函数调用
typedef struct {
    char* func_name;
    int (*func)(int, int);
} FunctionMap;

FunctionMap* find_function(const char* name) {
    // 直接返回所有注册的函数，包括系统调用
    return function_registry[hash(name)];
}

int parse_and_eval(const char* expr) {
    // expr = "exec('rm -rf /')"
    // 不检查 func_name 是否危险
    char func_name[256];
    sscanf(expr, "%s(", func_name);
    FunctionMap* f = find_function(func_name);
    if (f) return f->func(...);  // 执行用户指定的函数
}

// 较安全：严格的白名单和类型检查
typedef struct {
    const char* name;
    int (*safe_func)(int, int);
    int arg_count;
    int (*type_check)(const char*);
} SafeFunction;

SafeFunction safe_functions[] = {
    {"add", safe_add, 2, validate_int},
    {"sub", safe_sub, 2, validate_int},
    {NULL, NULL, 0, NULL}
};
```

**快速定位核心操作**：
- 关键词：`parse_expression`、`eval_expression`、自定义 AST 处理、语法分析函数
- 查看表达式解析器如何处理函数调用、属性访问、特殊符号
- 追踪是否存在函数黑名单或白名单机制
- 检查用户输入的表达式是否经过预处理或转义
- 关注嵌套表达式和递归解析是否有深度限制

**快速定位保护机制**：
- 是否维护了安全函数的白名单
- 是否对表达式进行了语法校验和 AST 分析
- 是否限制了表达式的复杂度和深度
- 是否对表达式求值结果进行了类型检查
- 是否使用了符号表隔离来限制变量访问范围

**审计等级**：**L3-L4**
- **L3**：逐行分析表达式解析器的关键步骤，重点关注函数查询和调用机制
- **L4**：跨模块追踪表达式输入到函数执行的完整路径，验证所有安全检查点

---

## Classify

**确认为漏洞**：
- 用户可指定调用的函数名称，函数解析器无白名单限制
- 表达式解析器允许访问对象属性或调用成员方法，无沙箱限制
- 存在绕过机制（编码、大小写、空白字符）绕过黑名单
- 表达式中的变量引用可访问系统范围内的任意对象

**误报**：
- 表达式仅支持基础运算符（+、-、*、/、==、<、>），不支持函数调用
- 所有可调用函数都被严格白名单限制且为安全函数
- 表达式中的变量被限制在指定的符号表内，无权访问系统对象

**代码异味**：
- 表达式解析器支持多种调用语法（方法调用、属性访问、索引访问）
- 函数黑名单存在但不完整，遗漏了危险函数
- 缺少对表达式复杂度和长度的限制

---

## Low Risk

以下情况可评为低风险：
- **严格的函数白名单**：仅允许调用预定义的安全函数（如基础数学运算）
- **受限的符号表**：变量访问被限制在明确定义的数据集合内
- **表达式能力有限**：不支持函数定义、递归调用、或高级控制流
- **内网编辑器**：表达式仅由内部用户编辑，有访问控制和审计
- **静态验证**：表达式在编译时进行白名单验证，运行时不接收用户输入

**注意**：即使函数被白名单限制，也需检查白名单是否完整以及是否存在编码绕过。
