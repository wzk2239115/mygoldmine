# C｜共享缓冲区数据竞争

## Details

### 漏洞成因
在使用 `pthread`、`std::thread` 或异步 IO 的 C/C++ 程序中，共享缓冲区（如环形队列、日志缓存、网络发送缓冲）经常被多个线程同时写入。如果缺乏互斥锁、原子操作或正确的内存屏障，就会出现数据覆盖、写指针错乱、长度计数溢出等竞态问题。常见误区包括：仅使用 `volatile` 试图解决可见性问题、在部分写入路径漏加锁、在锁内执行阻塞 IO 导致开发者随意移除锁等。

### 代码示例

**易受攻击示例：**
```c
// 生产者线程
void *producer(void *arg) {
    for (;;) {
        size_t len = generate_payload(buf);
        // 未加锁的写指针和长度更新
        memcpy(shared_buffer + write_pos, buf, len);
        write_pos = (write_pos + len) % BUFFER_SIZE;
        total_bytes += len;
    }
}
```

**正确示例（互斥保护 + 条件变量）：**
```c
pthread_mutex_lock(&buf_mutex);
size_t len = generate_payload(tmp);
while (free_space < len) {
    pthread_cond_wait(&not_full, &buf_mutex);
}
memcpy(shared_buffer + write_pos, tmp, len);
write_pos = (write_pos + len) % BUFFER_SIZE;
total_bytes += len;
pthread_mutex_unlock(&buf_mutex);
```

### 快速定位技巧

#### 核心操作定位（审计等级：L1-L2）
**关键词扫描：** `pthread_create`, `std::thread`, `memcpy`, `write_pos`, `buffer`, `global`, `static`, `volatile`, `producer`, `consumer`。

**定位步骤：**
1. 全局搜索涉及缓冲区写入的函数（`memcpy`, `strncpy`, `write` 等）。
2. 查找共享变量（`static` 指针、全局数组、结构体成员）是否在多个线程函数中出现。
3. 跳读（L2）判断写入操作附近是否获取锁或使用原子操作。

#### 保护机制定位（审计等级：L2-L3）
**检查是否存在：**
- 互斥锁/读写锁：`pthread_mutex_lock`, `std::mutex`, `std::unique_lock`。
- 原子变量：`std::atomic<size_t>`、`__sync_fetch_and_add`。
- 条件变量或信号量：`pthread_cond_wait`, `sem_wait`。
- 环形缓冲封装：统一的 `enqueue/dequeue` 接口并在内部加锁。

**定位技巧：**
1. 若发现未加锁的写入，逐行读（L3）追踪写指针、长度计数、标志位的修改。
2. 关注 `memcpy` 后是否更新共享状态；是否使用 `volatile` 代替锁。
3. 跨模块追踪（L4）时，检查队列封装是否在所有调用点都持有相同的锁对象。

#### 审计等级标注
| 场景 | 审计等级 | 说明 |
|------|----------|------|
| 缓冲区完全封装在线程安全 API 中（锁或原子） | **L0（快速跳过）** | 可直接忽略 |
| 大部分路径加锁但需确认覆盖率 | **L2（跳读）** | 快速验证是否有遗漏 |
| 发现未加锁写指针或计数更新 | **L3（逐行读）** | 需深入分析数据流 |
| 缓冲区跨多个模块共享 | **L4（跨模块追踪）** | 追踪全部入口确保一致性 |

## Classify

### 研判标准

#### 确认漏洞
满足以下条件可判定为竞态问题：
1. 多线程/中断同时写同一缓冲区。
2. 写入相关变量（指针、长度、标志）缺乏互斥或原子保证。
3. 能复现数据覆盖、重复发送、崩溃或异常行为。

#### 误报
1. 缓冲区只读或仅单线程写入。
2. 使用专用环形缓冲封装，内部已通过锁/原子保证线程安全。
3. 写入顺序由硬件 DMA、零拷贝机制保证，不在程序内同时访问。

#### 代码异味
1. 部分路径加锁但存在未加锁的快捷出口。
2. 使用 `volatile` 或自定义标志代替互斥。
3. 缺少注释解释同步策略，维护者可能误用。

## Low risk

### 低风险评级场景

#### 1. 非关键调试缓冲
- 场景：仅用于调试日志，错误只影响打印顺序。
- 风险评估：可以记录为低风险，但建议长期修复。

#### 2. 单线程执行路径
- 场景：当前部署仅单线程运行，但代码看似支持多线程。
- 风险评估：短期可降级，但必须标注并验证部署假设。

#### 3. 幂等聚合
- 场景：数据最终会被 CRC/校验或幂等逻辑纠正。
- 风险评估：影响有限，可标记低风险但仍需改进。

#### 风险降级条件总结
| 条件 | 降级理由 | 建议优先级 |
|------|----------|------------|
| 缓冲仅用于日志 | 功能影响小 | 中 |
| 实际运行单线程 | 攻击面有限 | 中 |
| 下游有幂等校验 | 可修正错误 | 低 |
